# 19. 向量检索与重排序：从语义搜索到精准检索

### 一句话总结

向量检索解决"语义相似度搜索"问题，ANN 算法将 O(N) 的暴力搜索加速到 O(log N)，Re-Ranker 用交叉编码器对初筛结果做精细化排序，混合检索结合关键词和向量搜索取长补短。

### 核心概念（详细解释）

#### 近似最近邻搜索（ANN）

精确最近邻搜索（Brute Force）复杂度 O(N)，百万级向量需秒级响应。ANN 通过索引结构加速到 O(log N)。

类比：百万本书中找最相关的5本。暴力搜索是逐本翻阅，ANN是先看目录索引快速定位。

#### HNSW（分层导航小世界图）

类比：城市导航。先走高速公路（高层）快速到达附近城市，再走主干道（中层），最后走小路（底层）找到精确位置。

```Python
// 代码块
import hnswlib

dim = 1024
index = hnswlib.Index(space='cosine', dim=dim)
index.init_index(max_elements=1000000, ef_construction=200, M=16)
index.add_items(embeddings)
labels, distances = index.knn_query(query_embedding, k=10)
```

关键参数：

- M：节点最大连接数，越大精度越高
- ef_construction：建图搜索深度
- ef_search：查询搜索深度

#### FAISS 算法对比

| 算法 | 原理 | 精度 | 速度 | 适用场景 |
| --- | --- | --- | --- | --- |
| Flat | 暴力搜索 | 100% | O(N) | <10K |
| IVF | 倒排索引 | 高 | O(sqrt(N)) | 百万级 |
| HNSW | 分层图 | 高 | O(log N) | 百万级 |
| PQ | 乘积量化 | 中 | O(1) | 亿级 |
| IVF+PQ | 聚类+量化 | 中 | O(sqrt(N)) | 十亿级 |

#### Re-Ranker 模型

向量检索是"粗筛"（embedding相似度），Re-Ranker是"精筛"（交叉注意力）。

类比：向量检索像搜索引擎的"相关度排序"（快但粗），Re-Ranker像"人工审核"（慢但精）。

```Python
// 代码块
from sentence_transformers import CrossEncoder

reranker = CrossEncoder('BAAI/bge-reranker-large')
scores = reranker.predict([
    ["用户问题", "文档1"],
    ["用户问题", "文档2"],
    ["用户问题", "文档3"],
])
# 按分数重新排序
```

常用模型：

- **Cross-Encoder**：query+document拼接输入BERT，输出相关性分数
- **ColBERT**：token-level交互计算相关性
- **RankLLM**：用大模型做排序，效果最好但成本高

#### 混合检索（Hybrid Search）

向量检索擅长**语义匹配**，关键词检索（BM25）擅长**精确匹配**。混合检索=两者结合。

```
// 代码块
用户问题 ->
  |- 向量检索 -> Top-K（语义匹配）
  |- BM25检索 -> Top-K（关键词匹配）
  |- 归一化分数
  |- RRF融合排序 -> 最终Top-K
```

**RRF（Reciprocal Rank Fusion）**：

    RRF(d) = sum over retrievers r: 1 / (k + rank_r(d))

k是平滑参数（通常60）。RRF的优点是不需要分数归一化，只依赖排名。

### 实际案例

#### 企业知识库检索优化

某公司RAG系统检索优化历程：

1. 纯向量检索：准确率70%
2. 向量+Re-Ranker：准确率82%
3. 混合检索+Re-Ranker：准确率89%

#### LangChain/LlamaIndex 的检索流程

两个主流RAG框架都支持：

1. 向量检索（默认）
2. 混合检索（BM25+向量）
3. Re-Ranker（可选）

### 常见误区

- **向量检索一定能找到最相关的文档**：ANN是近似算法，可能遗漏
- **Re-Ranker越多越好**：Re-Ranker计算成本高，通常只对Top-10到Top-50重排序
- **混合检索一定比单一检索好**：如果向量检索和关键词检索结果高度重合，混合检索收益有限
- **FAISS是最好的向量数据库**：FAISS是库不是数据库，生产环境通常用Milvus、Qdrant等
