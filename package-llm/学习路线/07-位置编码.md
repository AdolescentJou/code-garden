# 第7天：位置编码—— 正弦/学习式位置编码、RoPE旋转位置编码、ALiBi

**一句话总结**：Transformer没有RNN的循环结构，不知道词的位置顺序，位置编码就是告诉模型"这个词排第几位"的方法。

**前置知识**：第2天Transformer架构、第3天Self-Attention、三角函数基础。

### 核心概念

#### 1.1 为什么需要位置编码？

**问题**：Transformer的Self-Attention对所有词一视同仁——如果你打乱词序，Self-Attention的输出（在加上位置编码之前）完全不变。

**举个例子**：

- "狗咬人" → 三个词的Self-Attention计算
- "人咬狗" → 三个词的Self-Attention计算

如果没有位置信息，模型看到的只是"狗"、"咬"、"人"三个词的关系，但不知道谁在前谁在后。这显然不行——"狗咬人"和"人咬狗"意思完全相反！

**解决方案**：给每个位置一个独特的"标签"（位置编码向量），加到词嵌入上：

$$\text{Input} = \text{Embedding}(w_i) + \text{PE}(i)$$

这样模型不仅能知道"这是什么词"，还能知道"它排在第几位"。

#### 1.2 正弦/余弦位置编码（原始Transformer）

原始Transformer（2017年）使用的位置编码公式：

$$PE_{(pos, 2i)} = \sin(pos / 10000^{2i/d})$$
$$PE_{(pos, 2i+1)} = \cos(pos / 10000^{2i/d})$$

其中pos是位置序号（0, 1, 2, ...），i是维度索引，d是模型维度。

**直观理解**：

- 不同维度使用不同频率的正弦/余弦波
- 低维度（小i）→ 高频率 → 捕捉局部位置信息
- 高维度（大i）→ 低频率 → 捕捉全局位置信息

**类比**：想象一个时钟——秒针转得快（高频，捕捉细粒度位置），时针转得慢（低频，捕捉粗粒度位置）。不同维度就像不同精度的时钟，组合起来就能精确编码位置。

**关键性质**：任意两个位置之间的相对距离，可以通过线性组合表示：

$$PE_{pos+\Delta} = PE_{pos} \cdot M(\Delta)$$

这意味着模型理论上可以学习到相对位置关系。

**缺点**：

- 固定编码，无法外推到训练时未见过的序列长度
- 高维空间中的周期性会导致远距离位置难以区分

#### 1.3 可学习的位置编码

最简单的方法：把位置编码当做一个可训练的嵌入矩阵：

```Python
// 代码块
# 可学习位置编码
pos_emb = nn.Embedding(max_seq_len, d_model)
# max_seq_len=2048, d_model=768
# 每个位置一个可训练的向量
```

**优点**：简单、灵活，模型自己学习最佳的位置表示
**缺点**：无法外推到超过max_seq_len的长度。训练时max_seq_len=2048，推理时不能用4096

#### 1.4 RoPE（Rotary Position Embedding）—— 当前主流

RoPE是目前大模型最常用的位置编码方法（LLaMA、ChatGPT、Qwen、GPT-4都使用）。

**核心思想**：不是给词向量加一个位置向量，而是**在注意力计算中直接编码相对位置**。

**怎么做到的？** 通过在复数空间中对Q和K向量做旋转：

$$q_m = R_m \cdot q, \quad k_n = R_n \cdot k$$

其中 $R_m$ 是一个旋转矩阵，旋转角度 $\theta_i = m / 10000^{2i/d}$。

**关键性质**：当计算 $q_m$ 和 $k_n$ 的点积时：

$$\text{Attention}(q_m, k_n) = q^T R_{n-m} k$$

点积结果**只依赖相对位置 **$n-m$，不依赖绝对位置！这就是RoPE的核心优势。

**类比**：RoPE就像给每个词配了一个"旋转角度"，两个词之间的角度差只取决于它们之间的距离，而不是具体位置。就像时钟——3点和5点之间的角度差，与8点和10点之间的角度差是一样的（都是2小时）。

**优点**：

- 天然编码**相对位置**信息
- 可以**外推到任意长度**（理论上）
- 与注意力机制深度整合
- 计算高效

**为什么RoPE能外推？** 因为旋转操作不依赖于绝对位置值，只依赖于位置差。即使推理时的序列长度超过训练时的长度，RoPE仍然能计算合理的旋转角度。

#### 1.5 ALiBi（Attention with Linear Biases）

ALiBi是BigScience提出的另一种位置编码方法。

**核心思想**：在注意力分数上直接加一个**与距离成反比的偏置**：

$$\text{Attention score} = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}} - |i-j| \cdot m\right)$$

其中 $|i-j|$ 是两个位置的绝对距离，$m$ 是一个固定的斜率参数。

**类比**：ALiBi就像一个"近视眼"——离得越近的词越清晰（高分），离得越远越模糊（低分）。

**优点**：

- **极强的外推能力**——可以外推到训练时5-10倍长的序列
- 不需要位置嵌入，零额外参数
- 简单高效

**缺点**：

- 相对位置信息是线性的，不如RoPE丰富
- 对需要精确长距离依赖的任务效果略差

#### 1.6 三种位置编码对比

| 方法 | 类型 | 外推能力 | 相对位置 | 额外参数 | 主流模型 |
| --- | --- | --- | --- | --- | --- |
| 正弦/余弦 | 绝对 | 弱 | 间接 | 无 | 原始Transformer |
| 可学习 | 绝对 | 无 | 无 | 有 | BERT, GPT-2 |
| RoPE | 相对 | 中等 | 直接编码 | 无 | LLaMA, GPT-4 |
| ALiBi | 相对 | 强 | 线性偏置 | 无 | BLOOM |

### 技术细节

#### 2.1 RoPE代码实现

```Python
// 代码块
import torch
import torch.nn as nn
import math

def precompute_rope_angles(seq_len, d_model, base=10000):
    """预计算RoPE旋转角度"""
    # 计算频率: 1/base^(2i/d)
    inv_freq = 1.0 / (base ** (torch.arange(0, d_model, 2).float() / d_model))
    # 计算位置 × 频率
    positions = torch.arange(seq_len).float()
    freqs = torch.outer(positions, inv_freq)  # [seq_len, d_model//2]
    return freqs

def apply_rope(q, k, freqs):
    """将RoPE应用到Q和K上
    
    参数:
        q, k: [batch, n_heads, seq_len, d_k]
        freqs: [seq_len, d_k//2]
    """
    # 取cos和sin
    cos = freqs.cos().unsqueeze(0).unsqueeze(0)  # [1, 1, seq_len, d_k//2]
    sin = freqs.sin().unsqueeze(0).unsqueeze(0)
    
    # 将Q/K的最后一维分成两半
    # 前半部分作为实部，后半部分作为虚部
    d_k = q.size(-1)
    q1 = q[..., :d_k//2]  # [batch, n_heads, seq_len, d_k//2]
    q2 = q[..., d_k//2:]
    k1 = k[..., :d_k//2]
    k2 = k[..., d_k//2:]
    
    # 复数乘法: (a + bi)(cos + i*sin) = (a*cos - b*sin) + i(a*sin + b*cos)
    q_rotated = torch.cat([
        q1 * cos - q2 * sin,  # 实部
        q1 * sin + q2 * cos   # 虚部
    ], dim=-1)
    k_rotated = torch.cat([
        k1 * cos - k2 * sin,
        k1 * sin + k2 * cos
    ], dim=-1)
    
    return q_rotated, k_rotated

# 使用示例
seq_len, d_model, n_heads = 10, 64, 4
d_k = d_model // n_heads

# 预计算角度
freqs = precompute_rope_angles(seq_len, d_k)

# 模拟Q, K
q = torch.randn(1, n_heads, seq_len, d_k)
k = torch.randn(1, n_heads, seq_len, d_k)

# 应用RoPE
q_rope, k_rope = apply_rope(q, k, freqs)

# 验证相对位置性质
# 位置1和位置3的注意力 = 位置5和位置7的注意力（相对距离都是2）
attn_1_3 = (q_rope[0, 0, 1] * k_rope[0, 0, 3]).sum().item()
attn_5_7 = (q_rope[0, 0, 5] * k_rope[0, 0, 7]).sum().item()
print(f"位置(1,3)的注意力: {attn_1_3:.6f}")
print(f"位置(5,7)的注意力: {attn_5_7:.6f}")
print(f"差异: {abs(attn_1_3 - attn_5_7):.10f}")  # 应该非常小
```

#### 2.2 正弦位置编码实现

```Python
// 代码块
def sinusoidal_position_encoding(seq_len, d_model):
    """原始Transformer的正弦/余弦位置编码"""
    pe = torch.zeros(seq_len, d_model)
    position = torch.arange(0, seq_len).unsqueeze(1).float()
    
    # 计算频率: 1/10000^(2i/d)
    div_term = torch.exp(
        torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model)
    )
    
    pe[:, 0::2] = torch.sin(position * div_term)  # 偶数维度用sin
    pe[:, 1::2] = torch.cos(position * div_term)  # 奇数维度用cos
    
    return pe

# 可视化位置编码（文字版）
pe = sinusoidal_position_encoding(10, 8)
print("位置编码矩阵（10个位置，8个维度）:")
print("       dim0    dim1    dim2    dim3    dim4    dim5    dim6    dim7")
for pos in range(10):
    values = "  ".join(f"{pe[pos, d]:6.3f}" for d in range(8))
    print(f"pos{pos}  {values}")
```

### 实际案例

#### LLaMA-3的RoPE配置

LLaMA-3使用RoPE，并引入了一个重要改进——**RoPE缩放（RoPE Scaling）**：

- 原始RoPE的base频率：10000
- LLaMA-3的base频率：500000（增大50倍）

**为什么要增大base？** 更大的base意味着更低的旋转频率，使得模型在长上下文（128K）时仍能区分远距离位置。

#### 长上下文扩展

GPT-4 Turbo支持128K上下文，Claude 3支持200K上下文。这些超长上下文能力严重依赖位置编码的外推能力：

| 模型 | 上下文长度 | 位置编码 | 外推方法 |
| --- | --- | --- | --- |
| GPT-4 Turbo | 128K | RoPE | 动态NTK缩放 |
| Claude 3 | 200K | RoPE | 渐进式扩展 |
| LLaMA-3 | 128K | RoPE | 三阶段训练+高频base |

### 常见误区

**误区1：RoPE是绝对位置编码**

**事实**：RoPE是相对位置编码——虽然旋转角度和绝对位置有关，但注意力计算的结果只依赖相对位置。

**误区2：位置编码对模型性能影响不大**

**事实**：位置编码直接决定模型能否理解词序、处理长文本。选错位置编码，模型性能会大幅下降。

**误区3：ALiBi可以完全替代RoPE**

**事实**：ALiBi的外推能力强，但对需要精确长距离依赖的任务效果不如RoPE。
