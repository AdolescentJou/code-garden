# 20. 高级 RAG 策略：从简单检索到知识图谱增强

### 一句话总结

基础 RAG 的"分块->向量化->检索->生成"套路在复杂场景下效果有限，高级 RAG 通过**多跳检索、HyDE 假设文档、知识图谱增强、长上下文 RAG** 等技术，显著提升复杂推理和专业知识问答的效果。

### 前置知识

- **第18天 RAG 架构**：基础检索增强生成流程
- **第19天 向量检索与重排序**：ANN、Re-Ranker、混合检索
- **第17天 长上下文处理**：百万级 token 的处理能力

### 核心概念（详细解释）

#### 基础 RAG 的局限

1. **单跳检索**：只检索一次，可能遗漏关键信息
2. **切片粒度问题**：固定切片无法适应不同问题
3. **语义理解局限**：embedding 无法理解复杂逻辑关系
4. **长文档丢失上下文**：关键信息可能在文档不同位置

#### 多跳检索（Multi-hop Retrieval）

对于需要多步推理的问题："A 公司的 CEO 的配偶毕业于哪所大学？"

基础RAG一次性检索很难找到答案。多跳检索：

```
// 代码块
第1轮："A公司的CEO是谁？" -> 检索到CEO名字
第2轮："CEO的配偶是谁？" -> 检索到配偶名字
第3轮："配偶毕业于哪所大学？" -> 得到答案
```

两种实现方式：

- **迭代式**：每轮用上一轮结果重构查询，多次检索
- **并行式**：同时生成多个子查询，并行检索后合并

类比：基础RAG像翻一次字典，多跳检索像查字典时看到一个词条，发现需要再查另一个词条，连续查多次。

#### HyDE（Hypothetical Document Embeddings）

核心思想：**让大模型先"假设"一个答案，然后检索与假设答案最相似的文档。**

类比：考试时先猜答案，再去书上找依据。

流程：

1. 用户问题 -> LLM生成假设答案
2. 假设答案 -> embedding
3. 用假设答案的embedding检索文档
4. 用检索到的文档生成最终答案

**为什么有效？** 大模型生成的假设答案通常比用户问题"更接近"知识库中的真实文档。因为文档是用"答案式"语言写的，而用户问题是用"提问式"语言写的。

#### 知识图谱增强 RAG（GraphRAG）

将文档知识抽取为**知识图谱**（实体-关系-实体三元组），检索时基于图结构进行推理。

```
// 代码块
文档 -> NER + 关系抽取 -> 知识图谱
用户问题 -> 图查询 -> 相关子图 -> LLM生成
```

优势：

- **多跳推理**：通过图路径发现间接关系
- **结构化信息**：比文本块更精确
- **全局理解**：理解文档集整体知识结构

#### 长上下文 RAG

当文档非常长（书籍、法律文件）时，传统切片检索效果差。长上下文RAG直接让模型读取完整长文档：

- 依赖长上下文模型（Claude 200K、Gemini 1M）
- 依赖FlashAttention和NTK缩放
- 检索时直接返回完整文档而非切片

#### 其他高级策略

| 策略 | 原理 | 适用场景 |
| --- | --- | --- |
| Self-RAG | LLM自我反思检索结果质量 | 减少幻觉 |
| CRAG | 检索结果校正（正确/错误/未知） | 提高可靠性 |
| RAPTOR | 层次化摘要树构建 | 长文档理解 |
| HippoRAG | 基于海马记忆索引的图谱检索 | 知识整合 |

### 实际案例

#### 微软 GraphRAG

微软2024年开源的GraphRAG项目：

1. 从文档中抽取实体和关系，构建知识图谱
2. 用社区检测算法对图谱分群
3. 为每个社区生成摘要
4. 查询时：全局查询用社区摘要，局部查询用图遍历

效果：在长文档理解任务上显著优于基础RAG。

#### Multi-hop QA 系统

某法律问答系统：

- 问题："原告公司在2020年的专利申请数量是否超过了被告公司？"
- 需要多跳：先找原告公司专利数据，再找被告公司数据，最后比较
- 用多跳检索+Re-Ranker，准确率从55%提升到78%

### 常见误区

- **高级RAG一定比基础RAG好**：简单问题用基础RAG足够，高级策略增加延迟和成本
- **HyDE总是有效**：如果模型对领域不熟悉，假设答案可能误导检索方向
- **知识图谱很难维护**：实际上有很多自动化工具（LLM+NER）可以半自动构建
- **长上下文RAG不需要切片**：即使有1M上下文，切片检索仍然有助于聚焦相关信息
