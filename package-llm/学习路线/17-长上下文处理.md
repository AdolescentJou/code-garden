# 17. 长上下文处理：突破 Transformer 的序列长度限制

### 一句话总结

Transformer 的注意力复杂度 O(N^2) 和位置编码的长度限制，让长上下文（100K+ tokens）成为瓶颈。NTK 缩放、ALiBi、Ring Attention 分别从**位置编码外推、注意力偏置、分布式计算**三个维度突破限制。

### 前置知识

- **第2天 位置编码**：RoPE（旋转位置编码）
- **第13天 KV Cache**：长上下文推理的显存挑战
- **第14天 FlashAttention**：长序列注意力计算优化

### 核心概念（详细解释）

#### 长上下文三大挑战

1. **计算复杂度**：注意力 O(N^2)，N=100K时计算量巨大
2. **显存占用**：KV Cache 随序列长度线性增长
3. **位置编码外推**：模型在N长度训练，需要在kN长度推理

类比：读了400页的书（训练4K），要考1000页的书（推理100K）。前400页记住了，后面600页怎么办？

#### RoPE 缩放（NTK-aware Scaling）

RoPE公式：RoPE(x, m) = x * exp(i*m*theta)

NTK缩放通过**增大theta**扩展序列长度：theta' = theta * k^(1/(d/2))

k是目标长度/训练长度的比值。增大theta相当于"拉长"位置编码的波长，让模型能感知更远的位置。

类比：把尺子刻度间距拉大，原来量到4cm，现在量到100cm。

#### NTK-by-parts

分段调整theta：对高频和低频使用不同缩放因子，避免极长序列精度下降。

#### 动态 NTK

推理时动态插值：超过训练长度时按比例压缩位置索引。简单有效。

#### ALiBi（Attention with Linear Biases）

不依赖位置编码，在注意力分数加**线性偏置**：

    AttentionScore_ij = Q_i*K_j**^T/sqrt(d) - m_h * |i - j|

m_h 是每个head的斜率。越远的token注意力分数扣分越多。

理论可无限外推，但与FlashAttention兼容性差（需物化bias mask）。

#### Ring Attention

**分布式长上下文**方案：把超长序列切分到多个GPU，每个GPU计算局部注意力，环形通信交换KV Cache。

类比：把1000页的书分给10人同时阅读，每读完一段传给下一人。

#### 技术对比

| 方法 | 原理 | 外推能力 | 兼容FA |
| --- | --- | --- | --- |
| 原始RoPE | 旋转编码 | 2x | 是 |
| NTK缩放 | 增大theta | 10-100x | 是 |
| NTK-by-parts | 分段theta | 更好 | 是 |
| Dynamic NTK | 位置插值 | 简单有效 | 是 |
| ALiBi | 线性偏置 | 理论无限 | 否 |
| Ring Attention | 分布式 | 百万级 | 是 |

### 实际案例

#### Claude 200K

Anthropic Claude 2 支持200K上下文，使用RoPE缩放+FlashAttention。

#### Gemini 1M

Gemini 1.5 Pro 支持1M token，使用Ring Attention+FlashAttention-2。

#### Llama-3 128K

NTK-by-parts将上下文从8K扩展到128K（16x扩展）。

### 常见误区

- **长上下文可以替代RAG**：长上下文处理更多信息，但RAG在大规模知识检索、实时更新方面仍有优势
- **ALiBi比RoPE好**：理论外推强，但实践中RoPE+NTK效果更好
- **Ring Attention没有额外开销**：环形通信有开销，但比单卡OOM好

### 为什么重要

1. 大模型下一个战场：Claude 200K、Gemini 1M
2. RAG的基础：长上下文是高级RAG前提
3. 硬件利用率：Ring Attention让百万级token成为可能
