### 核心概念

#### 模型压缩的四大武器

##### 1. 量化（Quantization）—— 降低数值精度

> 类比：把高清照片（RAW格式，每像素14bit）压缩成JPEG（每像素8bit）。肉眼看不出差别，但文件大小缩小了40%。

**为什么量化有效？**

神经网络中大多数权重在[-3, 3]之间，而FP32可以表示[-3.4e38, 3.4e38]。**99.9%的精度范围是浪费的。**

```
// 代码块
量化原理：

  FP32（32位浮点数）：
  ├─ 范围：[-3.4e38, 3.4e38]
  ├─ 精度：约7位有效数字
  └─ 每个权重4字节

  FP16（16位浮点数）：
  ├─ 范围：[-65504, 65504]
  ├─ 精度：约3位有效数字
  └─ 每个权重2字节 → 压缩2倍

  INT8（8位整数）：
  ├─ 范围：[-128, 127]
  ├─ 精度：整数
  └─ 每个权重1字节 → 压缩4倍

  INT4（4位整数）：
  ├─ 范围：[-8, 7]
  ├─ 精度：整数
  └─ 每个权重0.5字节 → 压缩8倍
```

**量化公式推导**：

```
// 代码块
INT8量化：

  步骤1：找到权重的最大绝对值
  max_val = max(|W|)  # 例如 2.5
  
  步骤2：计算缩放因子
  scale = max_val / 127  # 2.5 / 127 ≈ 0.0197
  
  步骤3：量化
  W_int8 = round(W_fp32 / scale)  # 1.5 → round(1.5/0.0197) = 76
  
  步骤4：反量化（推理时）
  W_fp32 ≈ W_int8 * scale  # 76 * 0.0197 ≈ 1.497
  
  误差：|1.5 - 1.497| = 0.003 → 误差极小！

INT4量化：
  步骤1：max_val = max(|W|)  # 2.5
  步骤2：scale = max_val / 7  # 2.5 / 7 ≈ 0.357
  步骤3：W_int4 = round(W_fp32 / scale)  # 1.5 → round(4.2) = 4
  步骤4：W_fp32 ≈ 4 * 0.357 = 1.428
  
  误差：|1.5 - 1.428| = 0.072 → 误差稍大，但可接受
```

##### 2. 剪枝（Pruning）—— 删掉不重要的权重

> 类比：修剪树枝。把枯枝、弱枝剪掉，树还是能正常生长，但体积更小。

```
// 代码块
剪枝原理：

  神经网络中很多权重接近0（"枯枝"）
  ├─ 研究表明：大模型中70%+的权重可以删除而不影响精度
  └─ 这些权重对输出贡献极小

  剪枝流程：
  1. 训练完整模型
  2. 计算每个权重的重要性（绝对值越小越不重要）
  3. 删除不重要的权重（设为0）
  4. 微调恢复精度

  类型：
  ├─ 非结构化剪枝：逐个权重删除 → 稀疏矩阵
  │  优点：压缩比高
  │  缺点：硬件支持差（稀疏计算效率低）
  │
  └─ 结构化剪枝：整个通道/层删除 → 更小的密集矩阵
     优点：硬件友好
     缺点：压缩比相对低
```

#### ONNX与TensorRT的关系

```
// 代码块
模型部署流水线：

  PyTorch模型
    ↓ torch.onnx.export()
  ONNX模型（中间格式）
    ↓ TensorRT解析优化
  TensorRT引擎（针对特定GPU优化）
    ↓ 部署
  生产环境

TensorRT的核心优化：
  1. 内核融合（Kernel Fusion）：
     把多个小操作合并成一个大内核
     例如：MatMul + Bias + ReLU → 一个融合内核
     效果：减少GPU调用开销，速度提升2-3倍

  2. 层融合（Layer Fusion）：
     把相邻的线性层+激活层合并
     例如：Linear → ReLU → Linear → ReLU
     合并为：FusedLinearReLU → FusedLinearReLU

  3. 精度校准（Calibration）：
     自动选择最佳量化精度
     分析每层对精度的敏感度，敏感层保持FP16，不敏感层用INT8
```

#### 模型并行

当单个GPU装不下整个模型时，需要模型并行：

```
// 代码块
1. 张量并行（Tensor Parallelism）：

  把一个矩阵乘法拆分到多个GPU
  
  例如：Y = X × W
  W = [W1, W2]  (按列切分)
  
  GPU1: Y1 = X × W1
  GPU2: Y2 = X × W2
  Y = [Y1, Y2]  (合并)
  
  优点：每个GPU只存一半的权重
  缺点：需要GPU间通信（NVLink）
  适合：大模型推理

2. 流水线并行（Pipeline Parallelism）：

  把模型按层切分到多个GPU
  
  GPU1: Layer 1-20
  GPU2: Layer 21-40
  GPU3: Layer 41-60
  GPU4: Layer 61-80
  
  数据像流水线一样从GPU1流到GPU4
  
  优点：不需要GPU间高带宽通信
  缺点：有流水线气泡（GPU空闲等待）
  适合：大模型训练

3. 混合并行（张量+流水线）：

  生产部署最常见的方式
  
  例如：LLaMA-3-70B用8张A100
  ├─ 4路张量并行（每张GPU存1/4权重）
  ├─ 2路流水线并行（分2段）
  └─ 总共 4 × 2 = 8张GPU
```

### 技术细节

#### PyTorch → ONNX → ONNX Runtime

```Python
// 代码块
import torch
import torch.onnx
import onnxruntime as ort
import numpy as np

# 1. 准备模型
class SimpleModel(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.linear1 = torch.nn.Linear(768, 512)
        self.relu = torch.nn.ReLU()
        self.linear2 = torch.nn.Linear(512, 256)
    
    def forward(self, x):
        x = self.linear1(x)
        x = self.relu(x)
        x = self.linear2(x)
        return x

model = SimpleModel()
model.eval()

# 2. 导出ONNX
dummy_input = torch.randn(1, 768)
torch.onnx.export(
    model,
    dummy_input,
    "model.onnx",
    opset_version=13,
    input_names=["input"],
    output_names=["output"],
    dynamic_axes={
        "input": {0: "batch_size"},   # 支持动态batch
        "output": {0: "batch_size"},
    },
)
print("ONNX模型已导出")

# 3. ONNX Runtime推理
session = ort.InferenceSession(
    "model.onnx",
    providers=["CUDAExecutionProvider", "CPUExecutionProvider"],
)

# 准备输入
input_data = np.random.randn(4, 768).astype(np.float32)  # batch=4

# 推理
outputs = session.run(None, {"input": input_data})
print(f"输出形状: {outputs[0].shape}")  # (4, 256)
```

#### 量化对比实验

```Python
// 代码块
import torch
from transformers import AutoModelForCausalLM

# 加载FP16模型
model_fp16 = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3-8B",
    torch_dtype=torch.float16,
    device_map="auto",
)

# 加载INT4量化模型（使用bitsandbytes）
model_int4 = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3-8B",
    load_in_4bit=True,          # INT4量化
    device_map="auto",
)

# 比较模型大小和速度
import time

def benchmark(model, input_ids, num_runs=10):
    times = []
    with torch.no_grad():
        for _ in range(num_runs):
            start = time.time()
            _ = model.generate(input_ids, max_new_tokens=100)
            times.append(time.time() - start)
    return np.mean(times), np.std(times)

input_ids = torch.randint(0, 32000, (1, 128)).cuda()

# FP16
t_fp16, std_fp16 = benchmark(model_fp16, input_ids)
print(f"FP16: {t_fp16:.2f}s ± {std_fp16:.2f}s")

# INT4
t_int4, std_int4 = benchmark(model_int4, input_ids)
print(f"INT4: {t_int4:.2f}s ± {std_int4:.2f}s")
print(f"加速比: {t_fp16/t_int4:.2f}x")

# 显存对比
mem_fp16 = torch.cuda.max_memory_allocated() / 1e9
print(f"FP16显存: {mem_fp16:.1f}GB")

torch.cuda.reset_peak_memory_stats()
_ = model_int4.generate(input_ids, max_new_tokens=1)
mem_int4 = torch.cuda.max_memory_allocated() / 1e9
print(f"INT4显存: {mem_int4:.1f}GB")
print(f"显存节省: {(1 - mem_int4/mem_fp16)*100:.1f}%")
```

#### 性能对比表

| 优化方式 | 体积减少 | 速度提升 | 精度损失 | 适用场景 |
| --- | --- | --- | --- | --- |
| FP16量化 | 2× | 1.5-2× | 可忽略 | 通用部署 |
| INT8量化 | 4× | 2-3× | 轻微（<1%） | 线上服务 |
| INT4量化 | 8× | 3-5× | 中等（1-3%） | 边缘部署 |
| FP8量化 | 4× | 2-3× | 轻微（<1%） | NVIDIA H100 |

| 剪枝(70%) | 3× | 2-4× | 轻微（<2%） | 特定架构 |

### 常见误区

**❌ 误区1：量化后效果一定变差**
INT8量化的精度损失通常<1%，在大多数任务上几乎看不出差别。关键是使用校准数据集来选择最佳量化参数。

**❌ 误区2：ONNX一定比PyTorch快**
ONNX本身只是一个格式，不保证更快。需要配合ONNX Runtime或TensorRT等优化引擎才能获得加速。

**❌ 误区3：模型并行一定比单GPU快**
模型并行引入了通信开销。如果GPU间通信带宽不够（如没有NVLink），多GPU反而可能比单GPU慢。只有在模型太大单GPU装不下时才用模型并行。

**❌ 误区4：压缩越多越好**
过度压缩会导致精度严重下降。一般INT4是下限，低于INT4精度损失不可接受。最佳实践是"蒸馏+INT8"或"蒸馏+INT4"的组合。

### 为什么重要

模型压缩与部署是**大模型从实验室走向产品的必经之路**：

- **成本**：没压缩的100B模型推理成本约$0.01/1000次，压缩后降至$0.001
- **可及性**：压缩后的7B模型可以在消费级GPU（如RTX 3090）上运行
- **生态**：ONNX让模型跨平台运行成为可能
- **趋势**：端侧部署（手机、IoT设备）是未来方向，压缩是必选项

**关键认知**：量化+蒸馏+推理框架优化是三位一体的压缩方案。单独的量化可能不够，需要组合使用才能达到最佳效果。

### 小练习

**练习1**：解释为什么INT4量化的误差比INT8大，但仍然被广泛使用。

**答案提示**：INT4的误差确实更大（1-3% vs <1%），但它把模型压缩8倍（vs INT8的4倍）。在边缘设备、手机等资源受限场景下，INT4是唯一能在有限内存中运行大模型的方法。精度损失可以通过微调恢复部分精度。

**练习2**：设计一个方案，把Llama-3-70B部署到1张A100（80GB）上。

**答案提示**：

1. INT4量化：70B × 0.5字节 = 35GB（模型权重）
2. KV Cache可用空间：80 - 35 = 45GB
3. 使用vLLM + PagedAttention管理KV Cache
4. 最大序列长度设为4096
5. 理论并发用户数：约8-10个
