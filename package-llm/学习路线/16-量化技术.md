# 16. 量化技术：从 FP16 到 INT4 的精度换空间术

### 一句话总结

量化通过**降低权重精度（FP16->INT8->INT4）** 压缩模型体积 4-8 倍，GPTQ 用 Hessian 矩阵指导逐层量化，AWQ 跳过对激活影响大的权重，GGUF 采用混合精度适配 CPU 端侧部署。

### 前置知识

- **浮点数表示**：IEEE-754 标准，FP32/FP16/BF16
- **第13天 KV Cache**：量化同样适用于 KV Cache

### 核心概念（详细解释）

#### 为什么需要量化？

- 70B 模型 FP16 需要 140GB，H100(80GB) 都放不下
- 4-bit 量化后仅需 35-40GB，消费级显卡能跑
- 低精度数据传输更快，推理速度提升

类比：量化像把高清图片压缩成JPEG。文件小了4倍，看起来差不多。

#### 量化基础

线性量化：Q(x) = round((x - x_min) / s)，s = (x_max - x_min) / (2^bits - 1)
反量化：x = Q(x) * s + x_min

#### PTQ vs QAT

| 方法 | 需要重训 | 精度损失 | 适用场景 |
| --- | --- | --- | --- |
| PTQ | 不需要 | 1-5% | 部署现有模型 |
| QAT | 需要 | <1% | 高质量部署 |

#### GPTQ：Hessian 矩阵指导逐层量化

类比：精准外科手术——先评估每条"神经"被切掉后的影响，从最不重要的开始切。

步骤：

1. 计算 Hessian 矩阵 H = d^2L/dW^2
2. 按 H_ii 从小到大排序（H_ii 越小，量化影响越小）
3. 优先量化影响最小的权重
4. 量化后更新补偿项

#### AWQ：激活感知的权重量化

核心洞察：**并非所有权重同等重要。** 通过分析激活值识别"关键权重"，对关键权重保留高精度。

效果：4-bit AWQ 精度通常优于 GPTQ。

#### GGUF：CPU 端侧部署标准

- llama.cpp 社区提出，混合精度策略
- 支持 CPU 推理，Mac 端侧部署标准
- Q4_K、Q5_K 等混合量化级别

#### 效果对比

| 精度 | 70B显存 | 精度损失 | 适用场景 |
| --- | --- | --- | --- |
| FP16 | ~140GB | 基准 | 训练/高质量推理 |
| INT8 | ~70GB | 1-3% | 生产推理 |
| INT4(GPTQ) | ~35GB | 3-8% | 资源受限 |
| INT4(AWQ) | ~35GB | 1-5% | 生产推理（更优） |

#### 代码示例

```Python
// 代码块
import torch

def linear_quantize(weight, bits=4):
    w_min, w_max = weight.min().item(), weight.max().item()
    q_max = (1 << bits) - 1
    scale = (w_max - w_min) / q_max
    zero_point = -w_min / scale
    q_weight = torch.clamp(torch.round(weight / scale + zero_point), 0, q_max).to(torch.uint8)
    return q_weight, scale, zero_point

def linear_dequantize(q_weight, scale, zero_point):
    return (q_weight.float() - zero_point) * scale

torch.manual_seed(42)
weight = torch.randn(128, 256) * 0.1
q_w, s, zp = linear_quantize(weight, bits=4)
deq_w = linear_dequantize(q_w, s, zp)
mse = torch.mean((weight - deq_w) ** 2).item()
print(f"INT4 MSE: {mse:.6f}, 压缩比: 4.0x")
```

### 实际案例

#### Llama-3 70B 部署

- FP16: 140GB, 需2张H100
- INT4 AWQ: 35GB, 单张H100
- 速度: INT4比FP16快1.5-2x

#### Mac 端侧

- llama.cpp + GGUF
- M2 Max(64GB) 跑70B Q4
- 速度: 5-10 tokens/s

### 常见误区

- **量化后效果很差**：INT4 AWQ 损失只有1-5%
- **量化只压缩权重**：KV Cache 也可量化
- **QAT一定比PTQ好**：QAT成本高10倍，PTQ对大多数场景足够

### 为什么重要

1. 大模型民主化：让消费级硬件运行大模型
2. 推理成本降低：显存减半=成本减半
3. 端侧部署：GGUF让Mac跑70B成为现实
