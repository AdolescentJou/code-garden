# 第4天：预训练（Pre-training）方法论—— Next Token Prediction、训练数据工程

**一句话总结**：预训练是大模型的"基础教育"阶段，通过"续写文本"这个简单任务，让模型从海量语料中自学语言规律和世界知识。

**前置知识**：第1天（什么是大模型）、第2天（Transformer架构）、第3天（Self-Attention）。

---

### 核心概念

#### 1.1 什么是预训练？

预训练是大模型训练的**第一个阶段**，在巨大的无标注文本语料库上通过**自监督学习**训练通用语言模型。

**类比**：预训练相当于给一个人灌了整本书的知识，但不教他怎么用这些知识。SFT（第8天）才是教他"怎么当客服、怎么写作文"。

#### 1.2 核心训练目标：Next Token Prediction

$$\text{最大化} \sum_{i=1}^{n} \log P(w_i | w_1, w_2, ..., w_{i-1})$$

**类比**：一个学生被丢进图书馆，只能通过"看到前面的字，猜后面的字"来学习。读完整个互联网后，不仅学会了语法，还学会了事实、逻辑、推理……

**为什么这么简单的任务能学到这么多？**

因为要准确预测下一个词，模型必须理解：

- **语法**：英语的"SVO"结构、中文的"SOV"结构
- **事实知识**："巴黎是___的首都" → 法国
- **推理逻辑**："如果A>B且B>C，那么A___C" → >
- **代码语法**："def fibonacci(n):" → "if"
- **常识**："太阳从___升起" → 东

**预测下一个词是一个极其信息密集的任务**——它迫使模型学习语言的方方面面。

#### 1.3 训练数据工程

数据是预训练的命脉。GPT-3用了3000亿tokens，LLaMA-3用了15万亿tokens。但数据不只是"多"就行，**质量比数量更重要**。

**典型数据配比**：

| 数据源 | 典型占比 | 理由 | 举例 |
| --- | --- | --- | --- |
| Common Crawl | 50-70% | 量大，覆盖最广 | 网页爬取 |
| 书籍 | 10-15% | 高质量长文本，提升连贯性 | Books3, Gutenberg |
| 代码(GitHub) | 10-15% | 代码语料，提升推理能力 | The Stack |
| Wikipedia | ~5% | 高质量百科知识 | 多语言维基 |
| 学术文献 | 2-5% | 学术论文，提升专业知识 | arXiv |

**关键洞察**：**数据质量 > 数据量**。高质量数据（书籍、百科、论文）虽然量少，但对模型能力的贡献远大于大量低质量网页。

**数据配比的影响**：LLaMA-3通过增加代码和学术数据的占比，大幅提升了推理和编程能力。

#### 1.4 数据预处理Pipeline

```
// 代码块
原始数据
    │
    ▼
1. 去重（MinHash/LSH）
    │  去除完全相同或高度相似的文档
    │  原因：重复数据会让模型"背"而不是"学"
    ▼
2. 质量过滤
    │  - 语言模型打分：用小模型给文本打分，保留高质量文本
    │  - 规则过滤：去除太短/太长/乱码/广告内容
    │  - 安全过滤：去除有害、色情、暴力内容
    ▼
3. 分词（Tokenization）
    │  BPE（Byte Pair Encoding）分词
    │  把文本转成token ID序列
    ▼
4. 格式统一
    │  统一编码、统一换行符、去除HTML标签
    ▼
5. 配比混合
    │  按预定比例混合不同来源的数据
    ▼
训练数据
```

#### 1.5 BPE分词

大模型不直接处理字符，而是处理**token**——token是介于字符和词之间的单位。

**BPE（Byte Pair Encoding）算法**：

1. 初始化：每个字符是一个token
2. 统计所有相邻token对的出现频率
3. 合并频率最高的token对，形成新token
4. 重复步骤2-3直到达到目标词汇表大小

**例子**：

```
// 代码块
初始: "l o w </w>"  →  l, o, w, </w>
统计: "l o" 出现5次, "o w" 出现3次, "w </w>" 出现2次
合并: "l o" → "lo"
结果: "lo w </w>"  →  lo, w, </w>
继续: ...
```

**为什么用BPE？**

- 处理未登录词：即使没见过的词也能分解成已知token
- 平衡词汇表大小和序列长度
- 跨语言通用：中文、英文、代码都能处理

### 技术细节

#### 2.1 预训练代码实现

```Python
// 代码块
import torch
import torch.nn as nn

class PreTrainingTrainer:
    """预训练训练器"""
    def __init__(self, model, tokenizer, optimizer, device='cuda'):
        self.model = model
        self.tokenizer = tokenizer
        self.optimizer = optimizer
        self.criterion = nn.CrossEntropyLoss()
        self.device = device
    
    def prepare_data(self, text, max_length=4096):
        """准备训练数据"""
        # 1. 分词
        tokens = self.tokenizer.encode(text)
        
        # 2. 截断到最大长度
        if len(tokens) > max_length + 1:
            tokens = tokens[:max_length + 1]
        
        # 3. 构造input和label
        # input: [w1, w2, ..., w_{n-1}]
        # label: [w2, w3, ..., w_n]
        # 模型看到w1预测w2，看到w1,w2预测w3...
        input_ids = tokens[:-1]
        labels = tokens[1:]
        
        return torch.tensor(input_ids), torch.tensor(labels)
    
    def train_step(self, input_ids, labels):
        """一个训练步骤"""
        self.optimizer.zero_grad()
        
        # 前向传播
        logits = self.model(input_ids)  # [batch, seq_len, vocab_size]
        
        # 计算损失
        loss = self.criterion(
            logits.view(-1, logits.size(-1)),  # [batch*seq_len, vocab_size]
            labels.view(-1)                     # [batch*seq_len]
        )
        
        # 反向传播
        loss.backward()
        
        # 梯度裁剪
        torch.nn.utils.clip_grad_norm_(self.model.parameters(), max_norm=1.0)
        
        # 参数更新
        self.optimizer.step()
        
        return loss.item()
    
    def calculate_perplexity(self, text):
        """计算困惑度（Perplexity）"""
        input_ids, labels = self.prepare_data(text)
        
        with torch.no_grad():
            logits = self.model(input_ids.unsqueeze(0))
            loss = self.criterion(
                logits.view(-1, logits.size(-1)),
                labels.unsqueeze(0).view(-1)
            )
        
        # Perplexity = exp(loss)
        # 越低越好，表示模型对文本的"困惑程度"
        return torch.exp(loss).item()

# 训练循环示例
def train_epoch(trainer, data_loader, epoch):
    """训练一个epoch"""
    total_loss = 0
    num_batches = 0
    
    for batch in data_loader:
        input_ids, labels = batch
        loss = trainer.train_step(input_ids, labels)
        
        total_loss += loss
        num_batches += 1
        
        if num_batches % 100 == 0:
            avg_loss = total_loss / num_batches
            perplexity = torch.exp(torch.tensor(avg_loss)).item()
            print(f"Epoch {epoch}, Step {num_batches}, "
                  f"Loss: {avg_loss:.4f}, Perplexity: {perplexity:.2f}")
    
    return total_loss / num_batches
```

#### 2.2 典型预训练配置

以LLaMA-2 70B为例：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 序列长度 | 4096 tokens | 每个训练样本的长度 |
| 批次大小 | 4M tokens/step | 每步处理的token数 |
| 训练步数 | 1,400,000 steps | 总训练步数 |
| 训练数据量 | 2万亿 tokens | 总数据量 |
| 优化器 | AdamW (β1=0.9, β2=0.95, weight_decay=0.1) |   |
| 学习率 | 峰值 1.5e-4 | warmup 2000步 |
| 硬件 | 2048张A100 80G GPU |   |
| 训练时间 | 约12天 |   |
| 总FLOPs | 约840 ZetaFLOPs |   |

**批次大小为什么这么大（4M tokens）？**

大batch size有几个好处：

1. 梯度估计更准确（更多样本的平均）
2. GPU利用率更高
3. 训练更稳定

但太大会导致泛化能力下降。4M tokens是经过大量实验得出的最优值。

#### 2.3 Perplexity（困惑度）

Perplexity是衡量语言模型质量的常用指标：

$$\text{Perplexity} = \exp\left(-\frac{1}{N}\sum_{i=1}^{N}\log P(w_i|w_1,...,w_{i-1})\right)$$

**直观理解**：Perplexity表示模型在每个位置"犹豫"的程度。如果Perplexity=10，意味着模型在每个位置像是在10个词中选一个。

| 模型 | Perplexity (越低越好) |
| --- | --- |
| GPT-2 | ~20 |
| GPT-3 | ~15 |
| LLaMA-2 70B | ~5-7 |
| LLaMA-3 405B | ~3-5 |

### 实际案例

#### LLaMA-3的三阶段预训练

LLaMA-3采用了一种创新的**三阶段预训练策略**：

1. **第一阶段（基础能力）**：4096上下文，15T tokens
  - 目标：学习基本语言能力和知识

1. **第二阶段（中等上下文）**：8192上下文，5T tokens
  - 目标：逐步适应更长的上下文

1. **第三阶段（长上下文）**：128K上下文，5T tokens
  - 目标：掌握超长文本理解能力

**为什么分阶段？**

如果一开始就用128K上下文训练，计算成本会非常高（O(n²)复杂度）。先在短上下文上训练基础能力，再逐步扩展到长上下文，既节省成本又能达到好的效果。

#### Chinchilla的最优训练策略

DeepMind的Chinchilla论文给出了一个重要结论：

**在给定算力预算下，模型参数和训练数据量应该等比例增加。**

经验法则：**Token数 ≈ 参数量 × 20**

| 模型 | 参数量 | 最优tokens | 实际tokens | 是否最优 |
| --- | --- | --- | --- | --- |
| GPT-3 | 1750亿 | 35万亿 | 3000亿 | ❌ 严重不足 |
| Chinchilla | 700亿 | 1.4万亿 | 1.4万亿 | ✅ 最优 |
| LLaMA-2 70B | 700亿 | 1.4万亿 | 2万亿 | ✅ 超额 |
| LLaMA-3 405B | 4050亿 | 8万亿 | 15万亿 | ✅ 大幅超额 |

GPT-3的教训：参数太多但数据不够，相当于一个聪明人读的书太少。

### 常见误区

**误区1：预训练数据越多越好**

**事实**：数据**质量**比数量更重要。低质量数据会"污染"模型，导致幻觉和不准确。LLaMA-3花费大量精力在数据清洗上。

**误区2：Next Token Prediction太简单，学不到复杂能力**

**事实**：要准确预测下一个词，模型必须理解语法、事实、推理、代码等。这个"简单"任务的信息密度极高。

**误区3：预训练后模型就能用了**

**事实**：预训练后的模型只会"续写文本"，不知道怎么遵循指令、进行对话。需要经过SFT和RLHF才能成为有用的助手。

### 与其他知识点的关系

- 第5天（优化器）：预训练需要AdamW + warmup + cosine decay
- 第6天（分布式训练）：预训练必须依赖大规模分布式训练
- 第8-10天（SFT/RLHF）：预训练完成后进入微调和对齐阶段

### 为什么重要

预训练是大模型能力的**根基**。没有预训练就没有知识；没有高质量预训练数据，模型能力就不够。
