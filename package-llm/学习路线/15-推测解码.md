# 15. 推测解码（Speculative Decoding）：小模型起草，大模型验证

### 一句话总结

推测解码用**一个小模型快速生成多步草稿，大模型一次性并行验证**，在数学上保证输出分布完全相同的前提下，将推理速度提升 2-6.5 倍。

### 前置知识

- **自回归生成**：逐个 token 生成，每步依赖前一步输出
- **第13天 KV Cache**：推理中缓存历史 Key-Value
- **贪心采样 / 核采样**：大模型的 token 生成策略

### 核心概念（详细解释）

#### 问题：大模型的推理瓶颈到底在哪？

大模型生成文本是自回归的：每个 token 生成需要一次完整的 forward pass。70B 模型一次 forward 约 30ms，生成 100 tokens 就要 3 秒。

**瓶颈不在计算，而在内存带宽——每次 forward 都要加载模型权重到 GPU。**

类比：每次只走一步，但每走一步都要重新读一次地图。地图很大（70B参数），读地图比走路慢得多。

#### 推测解码的核心思想：小模型当"替工"

**草稿模型（Draft Model）**：小模型（如1B参数）快速生成多个 token
**验证模型（Target Model）**：大模型（如70B参数）一次性验证草稿

类比：让实习生快速写方案草稿，老板一次性审查修改。老板不用逐行写，只需判断哪些对哪些错。

**为什么能加速？** 小模型3ms/step，大模型30ms/step：

- 小模型生成10个token：30ms
- 大模型验证10个token：30ms（批量并行！）
- 总共60ms生成约7-10个token，比纯大模型快3-5倍

#### 接受-拒绝采样的数学原理

    P(accept draft_i) = min(1, P_target(draft_i) / P_draft(draft_i))

- 大模型概率 >= 小模型概率 -> 一定接受
- 大模型概率 < 小模型概率 -> 按概率比随机接受
- 被拒绝 -> 用大模型重新采样

**这保证了输出分布和大模型完全相同。** 是无损加速！

#### 代码示例

```Python
// 代码块
import torch
import torch.nn.functional as F
import random

def speculative_decoding(target_model, draft_model, prompt_tokens, max_new_tokens=100, N=5):
    tokens = prompt_tokens.copy()
    logits = target_model.forward(tokens)
    next_token = sample(logits[-1])
    tokens.append(next_token)
    
    while len(tokens) < len(prompt_tokens) + max_new_tokens:
        # 1. 草稿模型生成 N 个 token
        draft_tokens, draft_logits = draft_model.generate(tokens, num_tokens=N)
        # 2. 大模型一次性验证
        all_tokens = tokens + draft_tokens
        target_logits = target_model.forward(all_tokens)
        # 3. 逐个验证
        accepted = 0
        for i in range(N):
            draft_token = draft_tokens[i]
            target_prob = F.softmax(target_logits[len(tokens) + i], dim=-1)[draft_token].item()
            draft_prob = F.softmax(draft_logits[i], dim=-1)[draft_token].item()
            ratio = target_prob / draft_prob
            if ratio >= 1.0:
                accepted += 1
            elif random.random() < ratio:
                accepted += 1
            else:
                new_token = sample(target_logits[len(tokens) + i])
                tokens.append(new_token)
                break
        if accepted > 0:
            tokens.extend(draft_tokens[:accepted])
        if accepted == N:
            new_token = sample(target_logits[len(tokens)])
            tokens.append(new_token)
    return tokens
```

### 实际案例

#### vLLM 推测解码

- 草稿模型1B + 验证模型70B
- 加速比2-3x（ChatBot场景）
- 延迟从30ms/token降到10-15ms/token

### 常见误区

- **会降低输出质量**：不会，数学保证输出分布相同
- **任何场景都适合**：代码生成等场景命中率低
- **草稿模型越大越好**：需平衡速度和命中率

### 为什么重要

1. 无损加速：数学保证输出分布相同
2. 即插即用：不需要修改大模型
3. 工业界标配：vLLM、TensorRT-LLM都支持
