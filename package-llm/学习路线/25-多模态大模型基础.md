### 核心概念

#### 多模态的"统一Token"思路

大语言模型本质上只理解数字（Token ID）。它的大脑里只有文字，没有视觉、听觉。要让模型理解图片，核心问题是：**怎么把图片变成Token？**

```
// 代码块
传统方法（早期尝试）：
  图片 → CNN特征提取 → 全连接层 → 一个向量 → 喂给LLM
  
  问题：
  ├─ 一个向量信息量太少（像用一张模糊的缩略图描述整个世界）
  ├─ 丢失了空间信息（物体在图片中的位置）
  └─ 分辨率低（细节全没了）

Vision Tokenizer方法（当前主流）：
  图片 → ViT分块 → 线性投影 → Vision Token序列 → 和Text Token统一
  
  优势：
  ├─ 多个Token保留空间信息（196个Token = 14×14的空间网格）
  ├─ 每个Token对应图片的一个区域（保留细节）
  └─ 和文字Token格式统一（LLM不需要改架构）
```

> 类比：你要给一个只懂英语的人描述一幅中国画。方法一是用一句话总结（"这是一个山水画"），方法二是把画面切成小块，每块用英语描述（"左上角是远山，中间是河流，右下角是松树"）。方法二保留了更多细节信息。

#### Vision Tokenizer 详细流程

这是理解多模态大模型的**核心**。让我们一步步来看图片是如何变成Token的：

```
// 代码块
步骤1：图片预处理
  原始图片：224×224×3（高×宽×RGB通道）
  
  为什么要224×224？
  ├─ 这是ViT的标准输入尺寸
  ├─ 太小（如64×64）→ 信息丢失太多
  ├─ 太大（如512×512）→ Token数量爆炸（计算量太大）
  └─ 224×224是精度和计算量的平衡点

步骤2：分块（Patchify）
  把224×224的图片切成14×14的网格
  每个patch是16×16像素
  → 14×14 = 196个patch
  
  类比：
  ├─ 就像把一幅拼图切成196块
  ├─ 每块16×16像素 = 768个数字（16×16×3=768）
  └─ 每块包含了一个小区域的颜色信息

步骤3：线性投影（Linear Projection）
  每个patch的768个像素值 → 768维向量（一个Token）
  
  这实际上是一个线性变换：
  patch_vector = W @ pixel_values + b
  其中 W 是 [768, 768] 的权重矩阵
  
  类比：
  ├─ 把每个拼图块"翻译"成LLM能理解的语言
  └─ 768维正好和很多LLM的隐藏层维度一致

步骤4：添加位置编码
  196个Token + 196个位置编码
  
  为什么需要位置编码？
  ├─ Transformer本身没有位置感知能力
  ├─ 如果不加位置信息，模型不知道"左上角的patch"和"右下角的patch"的区别
  └─ 位置编码告诉模型每个patch在图片中的位置

步骤5：ViT Transformer处理
  196个Token经过多层Transformer处理
  → 每层都做自注意力计算
  → 不同patch之间相互"交流"
  → 最终输出196个视觉Token（每个是一个768维向量）

步骤6：输入到LLM
  [CLS] + [视觉Token 1] + ... + [视觉Token 196] + [文本Token 1] + ... + [文本Token N]
  
  LLM看到的就是一串Token，不管是视觉的还是文字的，格式一样
```

#### CLIP（Contrastive Language-Image Pre-training）—— 多模态对齐的里程碑

> 类比：把文字和图片都"翻译"成同一门"语言"——向量空间。就像中英词典，让中文和英文在同一个语义空间中对齐。

**CLIP的架构**：

```
// 代码块
CLIP双编码器架构：

  ┌─────────────────────────────────────────────────┐
  │                  CLIP Model                     │
  │                                                 │
  │  ┌──────────────┐      ┌──────────────┐        │
  │  │ Text Encoder  │      │ Vision Encoder│        │
  │  │ (Transformer) │      │    (ViT)      │        │
  │  │               │      │               │        │
  │  │ "一只猫"      │      │ [猫的图片]    │        │
  │  └──────┬───────┘      └──────┬───────┘        │
  │         │                      │                 │
  │         ↓                      ↓                 │
  │  [0.3, -0.5, ...]      [0.4, -0.3, ...]         │
  │  text embedding        image embedding           │
  │         │                      │                 │
  │         └──────────┬───────────┘                 │
  │                    ↓                             │
  │            对比损失计算                           │
  │    拉近匹配对，推远不匹配对                       │
  └─────────────────────────────────────────────────┘
```

**对比学习的核心思想**：

```
// 代码块
训练目标（InfoNCE损失）：

给定 N 对 (text_i, image_i)：
  text_1 ↔ image_1: ✅ 匹配 → 拉近（向量距离变小）
  text_1 ↔ image_2: ❌ 不匹配 → 推远（向量距离变大）
  text_1 ↔ image_3: ❌ 不匹配 → 推远
  ...
  text_1 ↔ image_N: ❌ 不匹配 → 推远

数学形式：
L = -(1/N) * Σ log(exp(sim(t_i, i_i) / τ) / Σ_j exp(sim(t_i, i_j) / τ))

其中：
  sim() = 余弦相似度
  τ = 温度系数（控制分布的平滑程度）
  
直觉：
  分子 = 匹配对的相似度（要大）
  分母 = 所有对的相似度之和（包括不匹配的）
  → 要让分子占比越大越好（匹配对的相似度远高于不匹配的）
```

**CLIP的革命性意义**：

1. 用4亿张图片-文字对训练，不需要人工标注分类标签
2. 训练完成后可以直接做零样本分类（zero-shot classification）
3. 奠定了所有多模态模型的基础

```
// 代码块
零样本分类示例：

  传统分类器：
  ├─ 需要训练数据：1000张猫的图片 + 1000张狗的图片
  ├─ 训练一个分类器
  └─ 只能区分猫和狗
  
  CLIP零样本分类：
  ├─ 不需要训练数据
  ├─ 把类别描述为文字："a photo of a cat" / "a photo of a dog"
  ├─ 计算图片和每个文字描述的相似度
  └─ 选最相似的作为分类结果
  
  效果：在ImageNet上达到76%的零样本准确率
        （传统有监督方法约85%）
```

#### 多模态对齐（Multimodal Alignment）

**为什么需要对齐？**

文字和图像属于不同"模态"，它们的特征空间完全不同：

- 文字Token的嵌入空间是语言模型学到的
- 图像Token的嵌入空间是视觉模型学到的
- 如果不做对齐，两者在模型内部"各说各话"

```
// 代码块
对齐前的向量空间：

  文字"猫"的向量：[0.3, -0.5, 0.8, ...]
  图片（猫）的向量：[0.9, 0.2, -0.1, ...]
  
  两个向量在完全不同的空间里，无法直接比较！

对齐后的向量空间：

  文字"猫"的向量：[0.5, 0.3, 0.7, ...]
  图片（猫）的向量：[0.48, 0.32, 0.69, ...]  ← 很接近！
  
  现在可以直接计算相似度，用文字搜图片，或用图片搜文字
```

**对齐方法**：

1. **投影层（Projection Layer）**：用一个轻量MLP把视觉Token的维度映射到和文本Token相同的维度
2. **交叉注意力（Cross-Attention）**：让视觉Token和文本Token通过注意力机制交互
3. **对比预训练（Contrastive Pre-training）**：如CLIP，在大规模图文对上预训练对齐

#### 主流多模态大模型

| 模型 | 视觉编码器 | 对齐方式 | 特点 | 典型应用 |
| --- | --- | --- | --- | --- |
| **CLIP** | ViT-L/14 | 对比学习 | 零样本分类标杆 | 图文检索、分类 |
| **LLaVA** | CLIP-ViT-L | 投影层 | 开源最强多模态 | 图片问答、描述 |

| **InternVL** | InternViT | 投影层 | 开源高分辨率 | 高分辨率图像理解 |

### 技术细节

#### CLIP 训练代码（PyTorch完整实现）

```Python
// 代码块
import torch
import torch.nn as nn
import torch.nn.functional as F

class CLIPModel(nn.Module):
    """
    CLIP模型：双编码器 + 对比学习
    """
    def __init__(self, text_encoder, vision_encoder, embed_dim=512, temperature=0.07):
        super().__init__()
        self.text_encoder = text_encoder     # 文本编码器（Transformer）
        self.vision_encoder = vision_encoder  # 视觉编码器（ViT）
        
        # 投影层：把编码器输出映射到统一的嵌入空间
        self.text_proj = nn.Linear(text_encoder.hidden_size, embed_dim)
        self.vision_proj = nn.Linear(vision_encoder.hidden_size, embed_dim)
        
        # 温度参数（可学习）
        self.logit_scale = nn.Parameter(torch.ones([]) * np.log(1 / temperature))
    
    def forward(self, texts, images):
        """
        前向传播
        
        参数：
        - texts: [N, seq_len] 文本Token IDs
        - images: [N, 3, 224, 224] 图片张量
        """
        # 1. 编码
        text_features = self.text_encoder(texts)    # [N, hidden_text]
        image_features = self.vision_encoder(images) # [N, hidden_vision]
        
        # 2. 投影到统一空间
        text_embeds = self.text_proj(text_features)   # [N, embed_dim]
        image_embeds = self.vision_proj(image_features) # [N, embed_dim]
        
        # 3. L2归一化（使向量长度为1，余弦相似度=内积）
        text_embeds = F.normalize(text_embeds, dim=-1)
        image_embeds = F.normalize(image_embeds, dim=-1)
        
        # 4. 计算相似度矩阵
        #    [N, N]矩阵，每个元素是text_i和image_j的余弦相似度
        logit_scale = self.logit_scale.exp()
        logits = logit_scale * text_embeds @ image_embeds.T  # [N, N]
        
        # 5. 对比损失（对称的InfoNCE）
        #    对角线是匹配对（应该相似），非对角线是不匹配对（应该不相似）
        labels = torch.arange(len(texts), device=texts.device)
        
        # image-to-text loss: 给定图片，找正确的文字
        loss_i2t = F.cross_entropy(logits, labels)
        
        # text-to-image loss: 给定文字，找正确的图片
        loss_t2i = F.cross_entropy(logits.T, labels)
        
        # 总损失 = 两个方向的平均
        loss = (loss_i2t + loss_t2i) / 2
        
        return loss
    
    def encode_text(self, texts):
        """编码文本 → 嵌入向量"""
        with torch.no_grad():
            features = self.text_encoder(texts)
            embeds = self.text_proj(features)
            return F.normalize(embeds, dim=-1)
    
    def encode_image(self, images):
        """编码图片 → 嵌入向量"""
        with torch.no_grad():
            features = self.vision_encoder(images)
            embeds = self.vision_proj(features)
            return F.normalize(embeds, dim=-1)

# 零样本分类示例
def zero_shot_classify(image, class_names, clip_model, tokenizer):
    """
    使用CLIP做零样本分类
    
    参数：
    - image: [1, 3, 224, 224] 待分类图片
    - class_names: ["cat", "dog", "bird", "fish"]
    """
    # 1. 编码图片
    image_embed = clip_model.encode_image(image)  # [1, embed_dim]
    
    # 2. 编码所有类别名称
    #    加上prompt: "a photo of a {class}"
    prompts = [f"a photo of a {name}" for name in class_names]
    text_tokens = tokenizer(prompts)
    text_embeds = clip_model.encode_text(text_tokens)  # [num_classes, embed_dim]
    
    # 3. 计算图片和每个类别的相似度
    similarities = (image_embed @ text_embeds.T).squeeze(0)  # [num_classes]
    
    # 4. 选最相似的类别
    predicted_idx = similarities.argmax().item()
    predicted_class = class_names[predicted_idx]
    confidence = F.softmax(similarities * clip_model.logit_scale.exp(), dim=0)
    
    return predicted_class, confidence

# 示例输出：
# predicted_class = "cat"
# confidence = tensor([0.85, 0.08, 0.05, 0.02])
# → 85%确信是猫
```

#### LLaVA 架构详解

```
// 代码块
LLaVA = Vision Encoder + Projection Layer + LLM

  图片 (224×224)
    ↓
  ViT (CLIP预训练的ViT-L/14)
    ↓
  576个视觉Token (每个2048维)
    ↓
  投影层 (MLP: 2048 → 4096)
    ↓
  576个视觉Token (每个4096维)
    ↓ 与LLaMA-2的隐藏维度(4096)对齐
  拼接文本Token
  [视觉Token 1] ... [视觉Token 576] [文本Token 1] ... [文本Token N]
    ↓
  LLaMA-2 (标准LLM，不需要修改)
    ↓
  文本输出

LLaVA的训练分两步：

  第1步：预训练（Pretrain）
  ├─ 数据：CC-3M数据集（300万图文对）
  ├─ 只训练投影层（MLP）
  ├─ 冻结ViT和LLM
  └─ 目的：让投影层学会把视觉特征映射到LLM的输入空间

  第2步：指令微调（Instruction Tuning）
  ├─ 数据：158K图文对话数据
  │  ├─ 58K对话数据（多轮对话）
  │  ├─ 77K详细描述数据
  │  └─ 23K复杂推理数据
  ├─ 训练投影层 + LLM
  ├─ 冻结ViT
  └─ 目的：让LLM学会基于视觉信息回答问题
```

### 常见误区

**❌ 误区1：多模态就是"两个模型拼一起"**
多模态不是简单地把视觉模型和语言模型拼接。核心难点在**对齐**——怎么让模型真正理解"图片中的猫"和文字"cat"是同一个概念。如果对齐不好，模型只是"看到"图片但"不理解"。

**❌ 误区2：视觉Token和文字Token完全等价**
虽然格式上统一了，但视觉Token和文字Token的信息密度不同。一个文字Token（如"猫"）包含明确的语义，而一个视觉Token（16×16像素块）可能只包含颜色和纹理信息，需要多个Token组合才能表达"猫"的概念。

**❌ 误区3：CLIP能做一切**
CLIP是检索和分类工具，不是生成模型。它不能生成图片（那是DALL-E/Stable Diffusion的工作），也不能做复杂的多模态推理（那是LLaVA/GPT-4V的工作）。

**❌ 误区4：分辨率越高越好**
高分辨率意味着更多Token（512×512 → 1024个Token vs 224×224 → 196个Token），计算量爆炸。实际上，224×224对大多数任务够用了。需要高分辨率的场景（如OCR、细粒度识别）可以使用动态分辨率或视觉Token剪枝。

### 小练习

**练习1**：解释为什么CLIP使用对比学习而不是分类任务来训练。

**答案提示**：分类任务需要预定义类别（如ImageNet的1000类），而对比学习不需要预定义类别——只要图文匹配就行。这使得CLIP可以在任何图文对上训练，不受类别限制，从而实现零样本分类。

**练习2**：如果要把LLaVA的ViT从ViT-L/14（224×224输入）换成ViT-L/14@336（336×336输入），需要修改什么？视觉Token数量会变成多少？

**答案提示**：336/16=21，所以21×21=441个视觉Token（vs 原来14×14=196个）。需要修改投影层输入维度（如果patch size不变，每个Token维度不变），以及位置编码的数量。Token数量从196增到441，计算量增加约2.25倍。
