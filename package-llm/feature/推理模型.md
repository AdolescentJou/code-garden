## 三、逐阶段详细对比（DeepSeek 官方技术路线）

### 1. 预训练阶段（两者基本相同）

- **目标**：学习通用语言、世界知识、语法、语义。
- **数据**：海量通用文本（网页、书籍、代码、百科等）。
- **任务**：标准下一个词预测（Next Token Prediction）。
- **结果**：模型“会说话、懂知识”，但不会主动推理。
- **结论**：预训练阶段两者几乎一样，R1 直接复用 V3 的预训练权重。

### 2. 监督微调（SFT）阶段：天壤之别

#### （1）普通 LLM（V3）的 SFT

- **数据**：通用指令—回答对（如“写一篇文章”“翻译这句话”）。
- **目标**：让模型学会遵循指令、格式规范、回答自然。
- **训练方式**：模仿学习，直接拟合人类答案。
- **不强调**：中间思考过程。

#### （2）推理大模型（R1）的 SFT（多轮、推理导向）

R1 的 SFT 不是一轮，而是多阶段、带推理链的复杂流程：

- **① 冷启动 SFT（R1-Zero 生成数据）**
  - 先用无 SFT、纯 RL 训练出一个 R1-Zero 模型。
  - 让 R1-Zero 生成大量带思维链（CoT）的问答对（约 60 万条推理数据 + 20 万条知识数据）。
  - **数据格式**：问题 → 思考步骤 → 答案。
  - **目标**：给主模型提供推理格式的“脚手架”。
- **② 第一轮 SFT（基础对齐）**
  - 用上面生成的 80 万条数据微调 V3。
  - **目标**：让模型学会输出“思考 → 答案”的结构，而不是直接给答案。
- **③ 拒绝采样 SFT（RS-SFT）**
  - 模型生成多个候选回答。
  - 用奖励模型（RM）自动打分，只保留步骤正确、答案对的样本。
  - 再用这些高质量样本做一轮 SFT。
  - **目标**：只学“正确的推理”，不学错误路径。

### 3. 强化学习（RL）阶段：最核心差异

#### （1）普通 LLM（V3）：RLHF（结果导向）

- **算法**：PPO（Proximal Policy Optimization）。
- **奖励信号**：
  - 人类偏好打分（喜欢 / 不喜欢）。
  - 只看最终答案是否通顺、有用、安全。
  - **不奖励**：中间步骤是否正确。
- **目标**：让模型“更像人说话”。

#### （2）推理大模型（R1）：GRPO（过程导向，DeepSeek 自研）

这是 R1 最强的地方，也是和普通 LLM 最大的区别。

- **① 算法：GRPO（Group Relative Policy Optimization）**
  - 不是看绝对分数，而是在一组回答中做相对比较。
  - 更稳定、更适合有明确对错的推理任务。
- **② 奖励机制：过程奖励（PRM）+ 结果奖励（RM）**
  - **过程奖励（PRM，Process Reward Model）**：对每一步思考打分（如“这一步推导是否正确”）。
    - 数学题：检查每一步计算是否正确。
    - 代码：检查每一行逻辑是否合理。
  - **结果奖励（RM）**：最终答案是否正确（可自动验证：数学算对、代码跑通）。
  - **额外奖励**：
    - 一致性奖励：避免前后矛盾、中英夹杂。
    - 简洁性奖励：步骤不冗余。
- **③ 训练目标**：不仅要答案对，还要**每一步推理都对**。

### 4. 数据差异（最直观）

#### 普通 LLM（V3）数据

- **内容**：通用对话、知识问答、文案、翻译。
- **格式**：问题 → 答案。
- **不包含**：思考过程。

#### 推理大模型（R1）数据

- **核心**：数学题、竞赛题、逻辑题、代码题、证明题。
- **格式**：问题 → 详细思考步骤 → 答案。
- **必须**：可自动验证对错（有标准答案）。

## 四、DeepSeek R1 独有的训练创新（普通 LLM 没有）

- **R1-Zero 冷启动**
  - 跳过传统 SFT，直接用纯 RL 训练出一个种子模型，生成推理数据。
  - 解决“一开始没有高质量推理数据”的问题。
- **GRPO 替代 PPO**
  - 更适合客观、可验证的推理任务，比 PPO 更稳定、效果更好。
- **过程奖励模型（PRM）**
  - 普通 LLM 只看结果，R1 每一步都打分，强制模型学会正确推导。
- **多轮 SFT + RL 迭代**
  - SFT → RL → SFT → RL，反复打磨推理能力。

## 五、一句话总结（初学者必记）

- **普通 LLM（V3）**：学“怎么说话”，看结果，重自然。
- **推理大模型（R1）**：学“怎么思考”，看过程，重正确。
- **DeepSeek 的比喻**：V3 是“会聊天的大脑”，R1 是“会解题的大脑”。

## PPO 和 GRPO

PPO 是传统 RLHF 的“老大哥”，GRPO 是 DeepSeek 为推理任务优化的“新贵”；**GRPO 不是 DeepSeek 独家**，现在很多团队都在用 / 改。

下面用初学者能懂的方式讲清楚：

### 一、先搞懂两个算法是什么（通俗版）

#### 1. PPO（Proximal Policy Optimization，近端策略优化）

- **一句话**：让模型在“不跑偏太远”的前提下，朝着奖励高的方向更新。
- **（1）核心原理（初学者版）**
  - 模型（Actor）生成回答。
  - 奖励模型（RM）打分：这个回答好不好。
  - 价值模型（Critic）估计“当前状态值”，算出优势函数（这个回答比平均水平好多少）。
  - 用策略梯度更新模型，但加了“裁剪”：不让模型一次改太多，防止训练崩掉。
  - 反复迭代：生成 → 打分 → 算优势 → 更新。
- **（2）在 LLM 里的作用（以 DeepSeek V3 为例）**
  - 用于 RLHF：让模型更听话、更自然、更安全。
  - 只看最终回答的好坏，不关心中间步骤。
  - 适合：对话、知识问答、通用生成。
- **（3）缺点（为什么 DeepSeek 要做 GRPO）**
  - 要同时训 Actor + Critic + RM，显存占用大、训练复杂。
  - 长文本 / 推理任务中，价值函数估计不准。
  - 对过程正确性（如数学步骤）奖励不精准。

#### 2. GRPO（Group Relative Policy Optimization，组相对策略优化）

- **一句话**：同一问题生成多个回答，在组内比好坏，只奖励“相对更优”的；去掉 Critic，省显存、更稳。
- **（1）核心创新（DeepSeek R1 的关键）**
  - 去掉价值模型（Critic）。
  - 不用估计“状态值”，直接用组内平均奖励当基线。
  - 显存占用减少 40%+，训练更简单。
  - 组内相对比较：
    - 对同一个问题，模型生成 N 个回答（比如 5 个）。
    - 奖励模型给每个回答打分。
    - 只看：这个回答在本组里排第几、比平均好多少。
    - 目标：让模型更倾向于生成组内高分回答。
  - **过程 + 结果双奖励（R1 独有）**
    - 结果奖励（RM）：最终答案对不对。
    - 过程奖励（PRM）：每一步推理对不对（数学 / 代码）。
    - 强制模型不仅答案对，步骤也要对。
  - 裁剪 + KL 约束：
    - 像 PPO 一样，防止模型跑偏太远。
    - 但更简单、更稳定。
- **（2）在 DeepSeek R1 里的作用**
  - 专门用于推理强化学习。
  - 目标：数学、逻辑、代码、多步推理能力拉满。
  - 比 PPO 更适合有明确对错、可自动验证的任务。

### 二、PPO vs GRPO 核心区别（一眼看懂）

| 对比项 | PPO（传统 RLHF） | GRPO（DeepSeek 推理专用） |
| --- | --- | --- |
| 核心思想 | 绝对奖励 + 价值函数估计 | 组内相对奖励 + 无价值函数 |
| 模型组件 | Actor + Critic + RM | Actor + RM（无 Critic） |
| 显存占用 | 高（多一个 Critic） | 低（省 40%+） |
| 训练复杂度 | 高（多模块协同） | 低（单模块更新） |
| 奖励机制 | 结果导向（最终回答） | 过程 + 结果双导向（步骤 + 答案） |
| 稳定性 | 一般（长文本易崩） | 高（推理任务更稳） |
| 适用场景 | 通用对话、知识问答、安全对齐 | 数学、逻辑、代码、多步推理 |
| 代表模型 | GPT-3.5、DeepSeek V3、Llama 2 | DeepSeek R1、DeepSeek Math、Qwen 推理版 |

### 三、GRPO 只有 DeepSeek 用吗？（重点）

不是！GRPO 现在是业界主流推理强化学习算法之一，很多团队都在用 / 改进。

#### 1. 谁在用 GRPO？

- DeepSeek：R1、Math 系列（原创者）。
- 字节跳动：Qwen 推理增强版（类 GRPO）。
- 阿里通义：用 GRPO/GSPO 优化推理。
- 清华 / 北大：联合 DeepSeek 提出，后续开源改进。
- 其他开源团队：如 Llama 3、Mistral 推理版，很多都在尝试 GRPO。

#### 2. 为什么大家都用 GRPO？

- 简单高效：去掉 Critic，训练门槛低。
- 推理友好：天然支持过程奖励，数学 / 代码效果爆炸。
- 显存友好：大模型训练更省资源。
- 稳定可靠：比 PPO 更不容易训崩。

#### 3. 有没有类似 GRPO 的算法？

- DPO：直接偏好优化（更早，二元对比）。
- GSPO：阿里通义的改进版。
- DAPO：字节 + 清华的解耦版。
- **本质都是**：去掉 Critic、做相对比较、适合推理。

### 四、一句话总结（初学者必记）

- **PPO**：传统 RLHF 标配，看结果、训复杂、适合通用对话。
- **GRPO**：DeepSeek 原创，看过程 + 结果、训简单、省显存、适合推理。
- **GRPO 不是独家**：现在是推理模型的主流强化学习算法。


### 五、在 PPO / GRPO 里，rollout 干什么用？
1. PPO 里的 rollout
生成一批回答
计算奖励
记录 log prob（概率）
计算优势函数
→ 为了更新模型
2. GRPO 里的 rollout
同一个问题生成 4～8 条回答（组成一组）
给每组内部分数
让模型学习组内最好的那条
GRPO 的 rollout 特点：同问题多生成 → 组内对比 → 更适合推理
