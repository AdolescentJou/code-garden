# 0x12 启动流程——从敲下回车到第一个字符出现-副本

> *系列：Claude Code 源码深度研究 · 专题 12 版本：v2.1.88 · 文件：*`*src/entrypoints/*`* · *`*src/main.tsx*`* · *`*src/setup.ts*`

### 一、从一次启动说起

你在终端输入 `claude`，按下回车。不到一秒，提示符出现了，Claude Code 已经准备好接受你的第一条消息。

表面上看，启动就是加载程序、初始化配置、显示界面——不就这样吗？

但真实的实现远比这复杂。从进程启动到首屏渲染，中间经历了超过 30 个检查点：终端能力检测、配置迁移、信任对话框、MCP 服务器预连接、Skills 预加载、Hooks 快照……每一步都有明确的目的，每一步的顺序都经过精心设计。如果你在加载期间就开始打字，那些字符不会丢失——Claude Code 在初始化开始时就已经开始捕获输入了。

这篇文章要带你深入 `src/main.tsx`，看清楚每一次启动背后的完整链路。

> 交叉引用：启动流程中的 Hooks 快照与 Hooks 系统密切相关（→ 参见**专题 10**：Hooks 系统），启动后的 Skills 预加载与 Skills 系统相关（→ 参见**专题 11**：Skills 系统），信任对话框与权限系统的安全边界设计一脉相承（→ 参见**专题 06**：权限系统）。

### 二、整体架构：三层入口

```TypeScript
// 代码块
用户执行 claude
        |
        v
entrypoints/cli.tsx（Bootstrap 入口）
  ├── 快速路径（--version、特殊子命令）→ 直接处理，零模块加载
  └── 普通路径 → 动态 import main.tsx
              |
              v
        main.tsx（主入口，4684行）
          ├── run()：Commander.js 命令解析
          └── 默认命令 action handler
                      |
                      v
                setup.ts（会话初始化）
                  ├── 工作目录设置
                  ├── Hooks 快照
                  ├── Worktree 创建
                  └── 后台预取启动

```

三层分工明确：`cli.tsx` 负责快速路径分发，`main.tsx` 负责 CLI 解析和全局初始化，`setup.ts` 负责每个会话的具体初始化。

### 三、Bootstrap 入口：零成本快速路径

`cli.tsx` 是真正的入口点，它的设计原则是**所有 import 都是动态的**，以最小化模块加载开销。

```TypeScript
// 代码块
// src/entrypoints/cli.tsx
async function main(): Promise<void> {
  const args = process.argv.slice(2);

  // 快速路径：--version 零模块加载
  if (args.length === 1 && (args[0] === '--version' || args[0] === '-v')) {
    console.log(`${MACRO.VERSION} (Claude Code)`);  // 版本号在构建时内联
    return;
  }

  // 其他路径：加载启动性能分析器
  const { profileCheckpoint } = await import('../utils/startupProfiler.js');
  profileCheckpoint('cli_entry');

  // ... 各种快速路径检测 ...

  // 普通路径：加载完整 CLI
  const { startCapturingEarlyInput } = await import('../utils/earlyInput.js');
  startCapturingEarlyInput();  // 开始捕获用户输入（在模块加载期间）
  const { main: cliMain } = await import('../main.js');
  await cliMain();
}

```

#### 3.1 快速路径列表

`cli.tsx` 检测到以下情况时，会绕过完整 CLI 直接处理：

- `--version`/`-v`：零模块加载，直接输出版本号
- `--dump-system-prompt`：输出系统提示词后退出（仅内部构建）
- `--claude-in-chrome-mcp`：启动 Chrome 集成 MCP 服务器
- `--daemon-worker=<kind>`：启动守护进程工作线程（轻量，无配置加载）
- `remote-control`/`rc`/`bridge`：启动远程控制模式（含认证检查）
- `daemon`：启动长期运行的守护进程
- `ps`/`logs`/`attach`/`kill`/`--bg`：后台会话管理
- `new`/`list`/`reply`：模板任务命令
- `environment-runner`：无头 BYOC 运行器
- `self-hosted-runner`：自托管运行器
- `--worktree --tmux`：在加载完整 CLI 前先 exec 进 tmux

#### 3.2 earlyInput：不丢失用户输入

```TypeScript
// 代码块
startCapturingEarlyInput();  // 开始捕获
// ... 135ms 的模块加载 ...
const { main: cliMain } = await import('../main.js');
await cliMain();
// 在 REPL 渲染后：
seedEarlyInput(capturedInput);  // 把捕获的输入注入到 REPL

```

用户可能在 CLI 加载期间就开始打字。`earlyInput` 模块在模块加载期间捕获 stdin 输入，等 REPL 渲染完成后再注入，避免输入丢失。

### 四、main.tsx：全局初始化的并行艺术

`main.tsx` 是 Claude Code 最复杂的文件（4684 行）。它的顶部有一段特殊的注释：

```TypeScript
// 代码块
// 这些副作用必须在所有其他 import 之前运行：
// 1. profileCheckpoint 在重量级模块求值开始前标记入口
// 2. startMdmRawRead 启动 MDM 子进程（plutil/reg query），与后续 ~135ms 的 import 并行
// 3. startKeychainPrefetch 并行启动两个 macOS keychain 读取（OAuth + 旧版 API key）
//    否则 isRemoteManagedSettingsEligible() 会通过同步 spawn 顺序读取（每次启动 ~65ms）
import { profileCheckpoint } from './utils/startupProfiler.js';
profileCheckpoint('main_tsx_entry');
import { startMdmRawRead } from './utils/settings/mdm/rawRead.js';
startMdmRawRead();  // 立即启动 MDM 读取
import { startKeychainPrefetch } from './utils/secureStorage/keychainPrefetch.js';
startKeychainPrefetch();  // 立即启动 keychain 预取

```

这三行代码在模块求值阶段（import 语句执行时）就启动了后台进程，与后续 135ms 的模块加载并行执行。这是 Claude Code 最重要的启动优化之一。

#### 4.1 启动性能分析器

```TypeScript
// 代码块
// src/utils/startupProfiler.ts
export function profileCheckpoint(name: string): void {
  const now = performance.now();
  checkpoints.push({ name, time: now });
}

export function profileReport(): string {
  // 输出每个检查点的时间和与上一个检查点的差值
  // 用于诊断启动慢的原因
}

```

整个启动流程有超过 30 个检查点，从 `cli_entry` 到 `main_after_run`，每个检查点都记录了精确的时间戳。这让 Anthropic 工程师可以精确定位哪个步骤变慢了。

#### 4.2 Commander.js 命令解析

```TypeScript
// 代码块
const program = new CommanderCommand()
  .configureHelp(createSortedHelpConfig())
  .enablePositionalOptions();

// preAction hook：在执行任何命令前运行
program.hook('preAction', async thisCommand => {
  // 等待 MDM 和 keychain 预取完成（几乎是免费的，因为它们已经并行运行了）
  await Promise.all([ensureMdmSettingsLoaded(), ensureKeychainPrefetchCompleted()]);
  await init();  // 核心初始化
  initSinks();   // 附加日志和分析 sink
  runMigrations();  // 运行配置迁移
  void loadRemoteManagedSettings();  // 非阻塞：加载企业远程设置
  void loadPolicyLimits();           // 非阻塞：加载策略限制
});

```

`preAction` hook 的设计很精妙：它只在实际执行命令时运行，而不是在显示帮助时运行。这避免了 `claude --help` 触发完整初始化。

### 五、init()：核心初始化（memoize 保证只运行一次）

```TypeScript
// 代码块
// src/entrypoints/init.ts
export const init = memoize(async (): Promise<void> => {
  enableConfigs()                    // 启用配置系统（验证 settings.json）
  applySafeConfigEnvironmentVariables()  // 应用安全的环境变量（信任对话框前）
  applyExtraCACertsFromConfig()      // 应用自定义 CA 证书（TLS 连接前）
  setupGracefulShutdown()            // 注册退出清理处理器
  void populateOAuthAccountInfoIfNeeded()  // 填充 OAuth 账户信息
  void initJetBrainsDetection()      // 检测 JetBrains IDE（异步）
  void detectCurrentRepository()    // 检测 GitHub 仓库（异步）
  initializeRemoteManagedSettingsLoadingPromise()  // 初始化远程设置加载 Promise
  initializePolicyLimitsLoadingPromise()           // 初始化策略限制加载 Promise
  recordFirstStartTime()             // 记录首次启动时间
  configureGlobalMTLS()              // 配置 mTLS
  configureGlobalAgents()            // 配置 HTTP 代理
  preconnectAnthropicApi()           // 预连接 Anthropic API（TCP+TLS 握手，~100-200ms）
  setShellIfWindows()                // Windows：设置 git-bash
  registerCleanup(shutdownLspServerManager)  // 注册 LSP 清理
})

```

`memoize` 确保 `init()` 只运行一次，即使被多次调用（例如，子命令和默认命令都调用了 `preAction`）。

#### 5.1 安全的环境变量分两阶段应用

```TypeScript
// 代码块
// 第一阶段（init 时）：只应用安全的环境变量
applySafeConfigEnvironmentVariables()

// 第二阶段（信任对话框接受后）：应用完整环境变量
applyConfigEnvironmentVariables()

```

为什么要分两阶段？因为 `settings.json` 中的 `env` 字段可以设置任意环境变量，包括 `PATH`、`LD_PRELOAD` 等危险变量。在用户确认信任当前目录之前，只应用白名单中的安全变量（如 `ANTHROPIC_API_KEY`、`HTTP_PROXY`）。

#### 5.2 preconnectAnthropicApi：隐藏 TCP 握手延迟

```TypeScript
// 代码块
// 在 init() 中立即启动，与后续的命令解析并行
preconnectAnthropicApi()
// 用户还在输入提示词时，TCP+TLS 握手（~100-200ms）已经完成
// 第一次 API 调用时直接复用已建立的连接

```

这是一个经典的预连接优化：在用户还在思考要输入什么的时候，就已经建立好了到 Anthropic API 的 TCP 连接。

### 六、信任对话框：安全的第一道门

```TypeScript
// 代码块
// 在 main.tsx 的默认命令 action handler 中
const hasTrust = checkHasTrustDialogAccepted();
if (!hasTrust && isInteractive) {
  // 显示信任对话框，等待用户确认
  await showSetupScreens(cwd);
}
// 信任确认后：
initializeTelemetryAfterTrust();  // 初始化遥测（等待远程设置加载）
applyConfigEnvironmentVariables();  // 应用完整环境变量
void getSystemContext();  // 现在可以安全地运行 git 命令了

```

信任对话框不只是 UI 上的确认——它是一个安全边界。在用户确认之前：

- 不运行 git 命令（git hooks 可以执行任意代码）
- 不应用 `settings.json` 中的危险环境变量
- 不初始化遥测（遥测配置可能在 settings.json 中）

### 七、setup()：会话级初始化

`setup()` 在每次会话开始时调用，负责会话级别的初始化：

```TypeScript
// 代码块
export async function setup(
  cwd: string,
  permissionMode: PermissionMode,
  // ...
): Promise<void> {
  // 1. 启动 UDS 消息服务器（Unix Domain Socket，用于 Agent 间通信）
  await m.startUdsMessaging(socketPath)

  // 2. 捕获 Teammate 模式快照（Swarm 功能）
  captureTeammateModeSnapshot()

  // 3. 恢复终端备份（如果上次 iTerm2/Terminal.app 设置被中断）
  await checkAndRestoreITerm2Backup()
  await checkAndRestoreTerminalBackup()

  // 4. 设置工作目录（必须在所有依赖 cwd 的代码之前）
  setCwd(cwd)

  // 5. 捕获 Hooks 配置快照（防止 hooks 被隐式修改）
  captureHooksConfigSnapshot()
  initializeFileChangedWatcher(cwd)

  // 6. 处理 Worktree 创建（如果 --worktree 标志）
  if (worktreeEnabled) {
    const worktreeSession = await createWorktreeForSession(...)
    process.chdir(worktreeSession.worktreePath)
    setCwd(worktreeSession.worktreePath)
  }

  // 7. 启动后台任务
  initSessionMemory()  // 会话记忆（同步注册，懒加载）
  void lockCurrentVersion()  // 锁定当前版本（防止被其他进程删除）

  // 8. 预取（不阻塞渲染）
  void getCommands(getProjectRoot())  // 预加载命令列表
  void loadPluginHooks()  // 预加载插件 hooks

  // 9. 附加分析 sink，发送 tengu_started 事件
  initSinks()
  logEvent('tengu_started', {})

  // 10. 检查上次会话的退出数据
  logEvent('tengu_exit', { last_session_cost, last_session_duration, ... })
}

```

#### 7.1 Hooks 配置快照：防止隐式修改

```TypeScript
// 代码块
captureHooksConfigSnapshot()
// 之后：
updateHooksConfigSnapshot()  // 在 worktree 切换后重新捕获

```

Hooks 配置快照在会话开始时捕获一次，之后的 hooks 执行都基于这个快照，而不是实时读取配置文件。这防止了一种攻击：恶意代码在会话中途修改 `settings.json` 来注入新的 hooks。

#### 7.2 tengu_started：最早的可靠信号

```TypeScript
// 代码块
initSinks()  // 先附加 sink
logEvent('tengu_started', {})  // 立即发送

```

`tengu_started` 事件是会话成功率的分母。它在 `initSinks()` 之后立即发送，确保即使后续代码崩溃（比如 `checkForReleaseNotes` 曾经崩溃过），这个事件也已经被记录。

### 九、配置迁移系统

```TypeScript
// 代码块
const CURRENT_MIGRATION_VERSION = 11;

function runMigrations(): void {
  if (getGlobalConfig().migrationVersion !== CURRENT_MIGRATION_VERSION) {
    migrateAutoUpdatesToSettings()
    migrateBypassPermissionsAcceptedToSettings()
    migrateEnableAllProjectMcpServersToSettings()
    resetProToOpusDefault()
    migrateSonnet1mToSonnet45()
    migrateLegacyOpusToCurrent()
    migrateSonnet45ToSonnet46()
    migrateOpusToOpus1m()
    migrateReplBridgeEnabledToRemoteControlAtStartup()
    // ...
    saveGlobalConfig(prev => ({ ...prev, migrationVersion: CURRENT_MIGRATION_VERSION }))
  }
}

```

每次发布新版本时，如果需要修改配置格式或默认值，就添加一个新的迁移函数并递增 `CURRENT_MIGRATION_VERSION`。迁移是幂等的——如果 `migrationVersion` 已经是最新，就跳过所有迁移。

模型迁移（`migrateSonnet1mToSonnet45` 等）是一个有趣的设计：当 Anthropic 发布新模型时，旧模型名称会被自动迁移到新名称，用户不需要手动更新配置。

### 十、启动时间线：从 0 到 REPL

以下是一次典型的 `claude` 启动的时间线（基于源码中的 profileCheckpoint 推算）：

```TypeScript
// 代码块
0ms      cli.tsx 开始执行
0ms      startMdmRawRead()（后台）
0ms      startKeychainPrefetch()（后台）

135ms    Commander 初始化
140ms    preAction hook 开始

140ms    ensureKeychainPrefetchCompleted()（几乎免费，已并行完成）
140ms    init() 开始
145ms    enableConfigs()（读取 settings.json）
145ms    applySafeConfigEnvironmentVariables()
145ms    preconnectAnthropicApi()（后台，TCP+TLS 握手）
150ms    init() 完成

155ms    setup() 开始

160ms    setCwd()
```

### 十一、--bare 模式：极简启动

`--bare` 标志（对应 `CLAUDE_CODE_SIMPLE=1`）跳过了大量启动工作：

- 不启动 UDS 消息服务器
- 不捕获 Teammate 快照
- 不加载插件 hooks
- 不运行 commit attribution hooks
- 不启动 team memory watcher
- 不预取文件数、用户信息、系统上下文
- 不初始化技能变更检测器
- 不读取 keychain（只用 `ANTHROPIC_API_KEY` 或 `apiKeyHelper`）

这让 `--bare` 模式的启动时间大幅缩短，适合脚本化调用（`claude -p "..." --bare`）。

### 十二、总结：启动流程的设计哲学

Claude Code 的启动流程体现了三个核心设计原则：

**快速启动**：所有可以并行的工作都并行（MDM 读取、keychain 预取、API 预连接）；所有可以延迟的工作都延迟（用户信息、文件统计、分析门控）；所有不必要的工作都跳过（快速路径、--bare 模式）。

**安全优先**：信任对话框是一个真正的安全边界，不只是 UI；环境变量分两阶段应用；hooks 配置在会话开始时快照，防止中途篡改；`--dangerously-skip-permissions` 在非沙箱环境下被拒绝。

**可观测性**：30+ 个 profileCheckpoint 让启动性能可以被精确测量；`tengu_started` 事件是会话成功率的可靠分母；每个初始化步骤都有 `logForDiagnosticsNoPII` 日志。

这三个原则共同构成了 Claude Code 启动流程的工程基础。

#### 12.4 为什么要在模块加载阶段就启动后台进程？

`main.tsx` 顶部那三行代码——`profileCheckpoint`、`startMdmRawRead`、`startKeychainPrefetch`——在 import 语句执行时就运行，而不是等到某个函数被调用。这是一个反直觉的设计，值得深入理解。

原因在于 JavaScript 模块的加载机制：当 Node.js/Bun 执行 `import { main } from './main.js'` 时，会同步地求值 `main.js` 的所有顶层代码，包括所有 import 语句。这个过程大约需要 135ms（加载 React、Commander、Yoga 等重量级模块）。

如果 MDM 读取和 keychain 预取在这 135ms 之后才启动，它们就会串行地增加启动时间。但如果在模块加载开始时就启动（作为顶层副作用），它们就能与 135ms 的模块加载并行执行。等模块加载完成，这些 I/O 操作也几乎完成了——`ensureMdmSettingsLoaded()` 和 `ensureKeychainPrefetchCompleted()` 的等待时间接近于零。

这是一个"把等待时间藏进不可避免的延迟里"的经典优化技巧，在 Web 性能优化中被称为"关键路径并行化"。

### 十三、给 mini-claude-code 的启示

mini-claude-code 的启动流程目前是线性的，可以借鉴 Claude Code 的并行化思路：

```Python
// 代码块
# mini-claude-code 的启动优化
# 对应 Claude Code 的 startKeychainPrefetch + preconnectAnthropicApi

import asyncio
from pathlib import Path

async def startup_parallel():
    """
    并行执行所有启动任务，而不是顺序执行。
    对应 Claude Code 的 main.tsx 顶层副作用 + preAction hook。
    """
    # 并行启动所有不相互依赖的初始化任务
    config_task = asyncio.create_task(load_config())
    preconnect_task = asyncio.create_task(preconnect_api())  # TCP 握手
    skills_task = asyncio.create_task(load_skills("."))       # 扫描 skills

    # 等待配置加载（其他任务在后台继续）
    config = await config_task

    # 应用配置后，等待其他任务（此时大概率已完成）
    await asyncio.gather(preconnect_task, skills_task)

    return config

async def preconnect_api():
    """
    预建立到 API 的 TCP 连接。
    对应 Claude Code 的 preconnectAnthropicApi()。
    在用户输入第一个 prompt 时，连接已经就绪。
    """
    import aiohttp
    try:
        async with aiohttp.ClientSession() as session:
            # 只建立连接，不发送请求
            async with session.head("https://api.anthropic.com",
                                    timeout=aiohttp.ClientTimeout(total=5)):
                pass
    except Exception:
        pass  # 预连接失败不影响后续使用

```

**最值得从 Claude Code 借鉴的两个设计**：

第一，`**earlyInput 模式——不丢失用户在加载期间的输入**`。如果 mini-claude-code 的初始化需要超过 100ms，应该在初始化开始时就开始捕获 stdin，等初始化完成后再处理。这避免了用户"打字没反应"的体验问题。

第二，`**startDeferredPrefetches 模式——渲染后再做后台工作**`。把非关键的初始化（统计文件数、刷新模型能力等）推迟到首屏渲染完成后，用 `asyncio.create_task` 在后台执行。用户看到提示符时，这些工作在后台悄悄进行，不阻塞交互。
