# 稠密向量与稀疏向量生成流程

## 一、统一示例文本

为了方便对比，我们全程用同一个简单的文本作为输入：

> **输入文本**：如何用 Python 实现 RAG 的混合检索

## 二、稠密向量（Dense Vector）生成流程（以 BGE-M3 为例）

稠密向量的核心是「把整段文本的语义压缩成固定长度的浮点数数组」，流程可拆分为 6 个基础步骤，每一步都有明确的操作和目的：

### 步骤 1：文本预处理

- **操作**：对输入文本做标准化处理，比如统一大小写（这里都是中文无需）、去除无效空格、分句 / 分词（模型内部完成）。
- **示例处理后**：`如何用Python实现RAG的混合检索`（无明显变化，中文主要是按字 / 子词切分）。

### 步骤 2：Token 化（转模型可识别的数字）

- **操作**：模型内置的词典会把文本拆成最小单元（Token），并映射成对应的 ID。
- **示例拆分（中文 Token）**：`[如何, 用, Python, 实现, RAG, 的, 混合, 检索]`
- **示例 Token ID（模拟）**：`[1024, 567, 8901, 345, 9876, 23, 6789, 4567]`

> 注：实际 ID 是模型训练时确定的，不同模型词典不同。

### 步骤 3：模型编码（Transformer Encoder 计算）

- **操作**：Token ID 输入 Transformer 编码器，通过多层自注意力机制，计算每个 Token 的上下文语义向量（每个 Token 对应一个高维向量）。
- **核心逻辑**：自注意力会让 "RAG""混合检索""Python" 这些关键 Token 互相关联，捕捉 "用 Python 做 RAG 混合检索" 的整体语义。
- **示例中间结果（模拟）**：每个 Token 输出 768 维向量，比如 "RAG" 的向量可能是 `[0.12, -0.34, 0.56, ..., 0.89]`（共 768 个浮点数）。

### 步骤 4：向量聚合（整句语义浓缩）

- **操作**：把所有 Token 的向量合并成一个句子级向量，最常用的是「CLS 池化」（取第一个特殊 Token `[CLS]` 的向量）或「平均池化」（所有 Token 向量求平均）。
- **示例结果**：将 8 个 Token 的 768 维向量平均，得到一个 **768 维的稠密向量**。

### 步骤 5：向量归一化（可选，提升检索效果）

- **操作**：将向量的模长归一化为 1（即所有维度的平方和开根号等于 1），确保向量只代表方向，不代表长度。
- **示例（简化为 3 维）**：原始向量 `[0.2, 0.4, 0.8]` → 归一化后 `[0.18, 0.36, 0.73]`（实际是 768 维）。

### 步骤 6：输出最终稠密向量

最终结果（模拟，仅展示前 5 维）：

```
[0.087, -0.123, 0.456, 0.219, -0.308, ..., 0.198]
```

> 共 768 个浮点数，无零值，这就是 **"稠密"** 的核心。

## 三、现代稀疏向量（Sparse Vector）生成流程（以 SPLADE 为例）

现代稀疏向量的核心是「模型预测文本中每个关键词的重要性权重，只保留高权重词，其余为 0」，流程同样拆分为 6 个基础步骤：

### 步骤 1：文本预处理（同稠密向量）

- 处理后：`如何用Python实现RAG的混合检索`。

### 步骤 2：Token 化（同稠密向量，但词典更大）

- 拆分 Token：`[如何, 用, Python, 实现, RAG, 的, 混合, 检索]`
- Token ID（模拟）：`[1024, 567, 8901, 345, 9876, 23, 6789, 4567]`

### 步骤 3：模型编码 + 权重预测（SPLADE 核心）

- **操作**：输入 Transformer 编码器后，模型会做两件事：
  1. 识别文本中的核心词汇（过滤掉 "的""用""如何" 等无意义虚词）；
  2. 为每个核心词汇预测一个「重要性权重」（浮点数，权重越高越关键）。
- **核心逻辑**：SPLADE 模型训练时，被要求 "放大关键词的权重，缩小虚词的权重"，兼顾关键词匹配和弱语义。

**示例权重预测结果：**

| Token | 权重 | 说明 |
| --- | --- | --- |
| Python | 3.2 | 核心工具，权重最高 |
| RAG | 2.8 | 核心概念，权重次高 |
| 混合检索 | 2.5 | 核心任务，权重较高 |
| 实现 | 1.0 | 普通动词，权重低 |
| 如何 / 用 / 的 | 0.0 | 虚词，权重归零 |

### 步骤 4：构建稀疏向量空间

- **操作**：以模型的完整词典为维度（比如词典有 10 万个词，就是 10 万维），每个维度对应一个词，维度值 = 该词的权重（无权重则为 0）。
- **示例维度映射（模拟）**：
  - 词典中 "Python" 对应维度 ID：`8901` → 维度值 = 3.2
  - 词典中 "RAG" 对应维度 ID：`9876` → 维度值 = 2.8
  - 词典中 "混合检索" 对应维度 ID：`6789` → 维度值 = 2.5
  - 其余 99997 个维度值全部 = 0

### 步骤 5：稀疏化优化（可选）

- **操作**：过滤掉权重极低的词（比如 < 0.5），只保留高权重词，进一步压缩向量大小。
- **示例优化后**：只保留 `Python(3.2)`、`RAG(2.8)`、`混合检索(2.5)`、`实现(1.0)`，其余维度全为 0。

### 步骤 6：输出最终稀疏向量

最终结果（稀疏表示，仅记录非零维度）：

```
{(8901, 3.2), (9876, 2.8), (6789, 2.5), (345, 1.0)}
```

> 实际存储时，稀疏向量只存 "维度 ID - 权重" 键值对，10 万维中仅 4 个维度非零，这就是 **"稀疏"** 的核心。

## 四、两种向量生成结果对比（同一示例）

| 类型 | 维度数量 | 非零维度数 | 核心值示例 | 代表的信息 |
| --- | --- | --- | --- | --- |
| 稠密向量 | 768 | 768 | `[0.087, -0.123, 0.456, ...]` | 整句语义（"用 Python 做 RAG 混合检索"） |
| 现代稀疏向量 | 100000 | 4 | `{(8901,3.2), (9876,2.8), ...}` | 关键词 + 权重（Python / RAG / 混合检索） |

## 五、总结

- **稠密向量生成核心**：通过 Transformer 编码器捕捉整句语义，最终输出「固定长度、全维度非零」的浮点数数组，核心是 **"语义整体表达"**。
- **现代稀疏向量生成核心**：模型先识别关键词并预测权重，再基于大词典构建「大部分维度为 0、仅核心词有权重」的向量，核心是 **"关键词 + 重要性"**。
- **两者最直观的差异**：稠密向量是 "一长串连续的数字"，稀疏向量是 "少数关键词的权重列表"，这也决定了前者适合语义匹配，后者适合关键词精准匹配。

## 附：TF-IDF 稀疏向量生成

### 一、什么是稀疏向量 vs 稠密向量

假设词表有 10000 个词：

**稀疏向量（Sparse Vector）—— TF-IDF 生成的：**

```
一条文本只包含几十个词，其他位置全是 0
[0, 0, 0.3, 0, 0, 0, 0, 0.7, 0, 0, 0, 0.5, 0, 0, ..., 0]
 ↑ 10000 维，但只有 ~20 个位置非零，其余 9980 个都是 0
 稀疏率：99.8% 都是 0
```

**稠密向量（Dense Vector）—— BERT/大模型生成的：**

```
每个位置都有值，没有 0
[0.12, -0.34, 0.56, 0.78, -0.23, 0.45, ..., 0.67]
 ↑ 768 维，每个位置都有含义，几乎没有 0
```

### 二、TF-IDF 为什么天然是稀疏的

原因很简单：**一条文本只用到了词表中极少数的词**。

```
词表（10000 个词）：
  位置0: "信用卡"
  位置1: "办理"
  位置2: "转账"
  位置3: "手机银行"
  位置4: "理财"
  ...
  位置9999: "西红柿"

用户问："信用卡怎么办理？"
  → 分词后只有 "信用卡" 和 "办理" 两个有效词
  → 10000 维的向量中，只有位置0 和 位置1 有值，其余全是 0

  [0.6, 0.8, 0, 0, 0, 0, 0, ..., 0, 0, 0]
   ↑     ↑   ↑______________________________↑
  信用卡 办理        9998个0
```

> 这就是 **"稀疏"** 的含义：绝大多数维度的值为 0。

### 三、和你可能见过的 "稀疏向量" 概念对比

向量数据库（如 Milvus、Qdrant、Elasticsearch）中提到的稀疏向量检索，原理确实一脉相承：

```
┌─────────────────────────────────────────────────────────────┐
│                  稀疏向量的演进路线                            │
│                                                             │
│  Bag of Words     →    TF-IDF      →    BM25/SPLADE        │
│  (词袋模型)            (加了权重)         (现代搜索引擎用的)    │
│                                                             │
│  核心思想都一样：                                              │
│  每个维度 = 一个词，值 = 这个词的重要程度                        │
│  大部分维度为 0（因为一条文本只包含少量词）                       │
└─────────────────────────────────────────────────────────────┘
```

| 方法 | 向量长度 | 非零值占比 | 值的含义 |
| --- | --- | --- | --- |
| 词袋 (BoW) | 词表大小（几万维） | < 1% | 词频（出现几次） |
| TF-IDF | 词表大小（几万维） | < 1% | 词频 × 稀有度 |
| BM25 | 词表大小（几万维） | < 1% | TF-IDF 的改进版（ElasticSearch 默认用这个） |
| SPLADE | 词表大小（3 万维） | ~1% | 用 BERT 预测的稀疏权重（语义 + 稀疏的结合） |
| BERT 稠密向量 | 768 维 | ~100% | 每个维度都有值，编码语义 |

### 四、稀疏 vs 稠密向量的本质区别

**稀疏向量（TF-IDF）：**

```
"信用卡办理" → [0, 0, 0.6, 0, 0.8, 0, 0, 0, ..., 0]
                      ↑         ↑
                   "信用卡"    "办理"   ← 每个维度你知道代表什么词

特点：可解释！看到非零位置就知道是哪个词在起作用
局限：不理解语义（"办卡" 和 "申请信用卡" 是不同维度，相似度=0）
```

**稠密向量（BERT/大模型）：**

```
"信用卡办理" → [0.12, -0.34, 0.56, 0.78, -0.23, ...]
                 ↑      ↑      ↑      ↑
              你不知道每个维度代表什么，但它编码了语义

特点：理解语义！"办卡" 和 "申请信用卡" 的向量会很接近
局限：不可解释，需要 GPU 计算
```

**用一个比喻来理解：**

| | 比喻 | 特点 |
| --- | --- | --- |
| 稀疏向量 | 关键词索引 → 像图书馆的目录卡片 | 只记录出现了什么词，精确匹配 |
| 稠密向量 | 读懂了文章的摘要 → 像一个人读完文章后写的内容总结 | 理解了意思，"办卡" 和 "申请信用卡" 是一回事 |

### 五、回到代码

当前用的 TF-IDF 就是经典的稀疏向量方案：

```python
# TF-IDF 向量化：fit_transform 同时学习词表并转换文本
self.tfidf_matrix = self.vectorizer.fit_transform(self.corpus)
```

sklearn 内部用稀疏矩阵（`scipy.sparse.csr_matrix`）存储，只存非零值的位置和数值，非常节省内存：

```
实际存储（稀疏格式，只存非零值）：
  文本0: {位置2: 0.6, 位置5: 0.8}         ← 只需存 2 个数
  而不是: [0, 0, 0.6, 0, 0, 0.8, 0, ..., 0]  ← 存 10000 个数

内存对比（10万条文本 × 5万维词表）：
  稠密存储：10万 × 5万 × 8字节 = 40 GB    ❌
  稀疏存储：10万 × 平均30个非零值 × 12字节 = 36 MB  ✅
```
