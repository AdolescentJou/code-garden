# 混合检索：稠密向量 + 稀疏向量的检索流程详解

## 核心需求确认

理解 RAG 中：

1. 稠密向量的单独检索流程
2. 现代稀疏向量的单独检索流程
3. 混合检索的完整流程

且需要从实操层面拆解，结合例子理解。

## 一、单独检索稠密向量（语义检索）

**核心逻辑**：计算查询向量与库中向量的「语义相似度」（余弦相似度为主），按相似度排序召回。流程分 5 步：

### 步骤 1：加载查询稠密向量

从内存 / 向量数据库中取出用户查询生成的稠密向量（如 768 维浮点数数组）。

### 步骤 2：计算余弦相似度（核心）

余弦相似度公式：

$$
\text{similarity} = \frac{A \cdot B}{\|A\| \times \|B\|}
$$

即向量点积除以模长乘积，值越接近 1，语义越相似。

**示例计算**（仅用前 3 维）：

- **查询向量 vs 文档 1**：

$$
\frac{(0.085 \times 0.087) + (-0.125 \times -0.123) + (0.458 \times 0.456)}{1 \times 1} \approx 0.98
$$

（归一化后模长为 1，分母可省略）

- **查询向量 vs 文档 2**：≈ 0.85
- **查询向量 vs 文档 3**：≈ 0.70

### 步骤 3：按相似度排序

排序结果：**文档 1（0.98）** > 文档 2（0.85）> 文档 3（0.70）

### 步骤 4：设定召回阈值 / 数量

比如召回 **Top2**（前 2 个最相似的文档），得到召回结果：**文档 1、文档 2**。

### 步骤 5：返回检索结果

输出召回的文档 ID + 相似度，供后续 RAG 使用。

### 关键补充

- **常用工具**：FAISS、Milvus、Pinecone（专为稠密向量优化，支持高效余弦相似度计算）
- **核心特点**：靠语义匹配，哪怕查询换说法（如 "用 Python 做 RAG 的混合检索"），也能精准召回文档 1

## 二、单独检索现代稀疏向量（关键词权重检索）

**核心逻辑**：计算查询向量与库中向量的「加权词匹配度」（BM25 / 内积为主），按匹配度排序召回。流程分 5 步：

### 步骤 1：加载查询稀疏向量

取出用户查询生成的稀疏向量（仅保留非零的 "维度 ID - 权重" 键值对）。

### 步骤 2：计算加权匹配度（核心）

现代稀疏向量常用「内积（点积）」计算匹配度：仅对两者**共有的维度**，计算权重乘积之和，值越高，关键词匹配度越高。

**示例计算：**

- **查询向量 vs 文档 1**：
  - 共享维度 8901：`3.1 × 3.2 = 9.92`
  - 共享维度 9876：`2.9 × 2.8 = 8.12`
  - 共享维度 6789：`2.4 × 2.5 = 6.0`
  - **总分 = 9.92 + 8.12 + 6.0 = 24.04**

- **查询向量 vs 文档 2**：仅共享维度 9876 → `2.9 × 3.0 = 8.7`

- **查询向量 vs 文档 3**：仅共享维度 6789 → `2.4 × 2.6 = 6.24`

### 步骤 3：按匹配度排序

排序结果：**文档 1（24.04）** > 文档 2（8.7）> 文档 3（6.24）

### 步骤 4：设定召回阈值 / 数量

同样召回 Top2：**文档 1、文档 2**。

### 步骤 5：返回检索结果

输出召回的文档 ID + 匹配度。

### 关键补充

- **常用工具**：Elasticsearch（支持稀疏向量的倒排索引）、SPLADE 配套的检索工具
- **核心特点**：靠关键词权重匹配，若查询少了 "Python"（维度 8901），文档 1 的匹配度会大幅下降（从 24.04 → 14.12）

## 三、混合检索（稠密 + 稀疏）

**核心逻辑**：先分别检索两种向量得到召回结果，再通过「分数归一化 + 融合排序」得到最终结果。流程分 7 步（工业界主流方案）：

### 步骤 1：单独检索稠密向量（召回 TopN）

召回 Top3，结果 + 分数：

| 文档 | 稠密分数 |
| --- | --- |
| 文档 1 | 0.98 |
| 文档 2 | 0.85 |
| 文档 3 | 0.70 |

### 步骤 2：单独检索稀疏向量（召回 TopN）

召回 Top3，结果 + 分数：

| 文档 | 稀疏分数 |
| --- | --- |
| 文档 1 | 24.04 |
| 文档 2 | 8.7 |
| 文档 3 | 6.24 |

### 步骤 3：分数归一化（关键！统一量纲）

两种向量的分数范围不同（稠密：0~1，稀疏：0~∞），需归一化到同一范围（如 0~1），常用 **Min-Max 归一化**：

$$
\text{归一化分数} = \frac{\text{原始分数} - \text{最小值}}{\text{最大值} - \text{最小值}}
$$

**稠密分数归一化：**

| 文档 | 原始分数 | 归一化分数 |
| --- | --- | --- |
| 文档 1 | 0.98 | (0.98 - 0.70) / (0.98 - 0.70) = **1.0** |
| 文档 2 | 0.85 | (0.85 - 0.70) / (0.98 - 0.70) ≈ **0.54** |
| 文档 3 | 0.70 | (0.70 - 0.70) / (0.98 - 0.70) = **0.0** |

**稀疏分数归一化：**

| 文档 | 原始分数 | 归一化分数 |
| --- | --- | --- |
| 文档 1 | 24.04 | (24.04 - 6.24) / (24.04 - 6.24) = **1.0** |
| 文档 2 | 8.7 | (8.7 - 6.24) / (24.04 - 6.24) ≈ **0.14** |
| 文档 3 | 6.24 | (6.24 - 6.24) / (24.04 - 6.24) = **0.0** |

### 步骤 4：设置融合权重（可调）

给两种向量的归一化分数分配权重（如稠密占 0.6，稀疏占 0.4），平衡语义和关键词匹配：

$$
\text{最终分数} = \alpha \times \text{稠密归一化分数} + \beta \times \text{稀疏归一化分数}
$$

其中 \(\alpha = 0.6\)，\(\beta = 0.4\)。

### 步骤 5：计算最终分数

| 文档 | 稠密归一化 | 稀疏归一化 | 最终分数 |
| --- | --- | --- | --- |
| 文档 1 | 1.0 | 1.0 | 1.0 × 0.6 + 1.0 × 0.4 = **1.0** |
| 文档 2 | 0.54 | 0.14 | 0.54 × 0.6 + 0.14 × 0.4 ≈ **0.38** |
| 文档 3 | 0.0 | 0.0 | 0.0 × 0.6 + 0.0 × 0.4 = **0.0** |

### 步骤 6：按最终分数排序

排序结果：**文档 1 (1.0)** > 文档 2 (0.38) > 文档 3 (0.0)

召回 Top2：**文档 1、文档 2**。

### 步骤 7：可选 —— 重排序（Rerank）

若追求更高精度，可将召回的 TopN 文档输入轻量级重排序模型（如 **BGE-Reranker**），模型基于完整文本再次计算相似度，得到最终排序（示例中文档 1 仍为第一）。

---

## 混合检索的优势示例

假设用户查询是「Python 做 RAG 的混合检索方法」（换了说法）：

- **稠密检索**：仍能高相似度匹配文档 1（语义理解）
- **稀疏检索**：因 "方法" 是新词，文档 1 匹配度略有下降
- **混合检索**：结合两者，既保留语义匹配的优势，又避免因关键词变化导致召回失效

---

## 四、三种检索流程对比表

| 环节 | 稠密向量单独检索 | 稀疏向量单独检索 | 混合检索 |
| --- | --- | --- | --- |
| **核心计算方式** | 余弦相似度 | 加权内积 / BM25 | 归一化分数 + 权重融合（+Rerank） |
| **召回依据** | 语义相似性 | 关键词权重匹配 | 语义 + 关键词双重匹配 |
| **常用工具** | FAISS / Milvus | Elasticsearch | FAISS + Elasticsearch |
| **优势** | 抗文本改写、理解意图 | 精准匹配关键词 / 术语 | 兼顾语义和关键词，召回更准 |

---

## 总结

- **稠密向量检索**：核心是余弦相似度计算，靠语义匹配召回，适合抓用户查询的 **"意图"**
- **稀疏向量检索**：核心是加权关键词匹配，靠字面权重召回，适合抓查询中的 **"术语 / 关键词"**
- **混合检索**：先分别检索，再归一化分数、分配权重融合，可选 Rerank 优化，是工业界 RAG 的主流方案，兼顾语义和关键词的优势

> 这三个流程的核心差异在于 **「匹配的依据」** 和 **「分数计算方式」**，混合检索的关键是 **归一化（统一量纲）** 和 **权重调优（平衡两种向量的贡献）**。
