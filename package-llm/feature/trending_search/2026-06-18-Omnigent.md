### 一、项目简介

Omnigent 是一个开源的 AI Agent 框架和 **meta-harness（元编排层）**，核心定位是：**给所有 AI Agent 一个统一的编排层**。

它不和你抢"谁是最好的 Agent"这个问题，而是解决一个更实际的问题——当你的团队同时使用 Claude Code、Codex、Cursor、Pi 以及自研 Agent 时，如何让它们在同一个会话里协作、如何无缝切换引擎而不重写代码、如何统一治理安全策略。

**一句话总结**：Omnigent 是 AI Agent 世界的"Kubernetes"——它不运行模型，它编排、治理和调度所有运行模型的 Agent。

### 二、核心功能详解

#### 1. 🤖 多 Agent 统一编排（Meta-Harness）

这是 Omnigent 最大的差异化能力。它支持以下 Agent 运行时作为 "harness"：

| Harness | 说明 |
| --- | --- |
| `claude` / `claude-sdk` | Anthropic Claude Code |
| `codex` / `codex-native` | OpenAI Codex |
| `cursor` | Cursor CLI（需 cursor-agent + API Key） |
| `pi` | Pi Agent |
| `openai-agents` | OpenAI Agents SDK |
| `antigravity` | Antigravity 框架 |
| 自定义 YAML | 你自己写的 Agent |

**关键特性**：同一个 Agent 定义（YAML），可以随意切换底层 harness，不需要改任何代码：

```Shell
// 代码块
omnigent run examples/polly/ --harness pi
omnigent run examples/polly/ --harness openai-agents
omnigent run examples/polly/ --harness cursor
```

#### 2. 📱 跨设备会话同步

会话跟随你走：在终端启动 → 在浏览器继续 → 在手机上接续。消息、子 Agent、终端、文件全部同步。

- 本地模式：局域网内手机直接访问 `http://192.168.x.x:6767`
- 远程模式：部署服务器后从任何地方访问
- 原生桌面 App：macOS 版已发布，支持系统通知

#### 3. 🤝 实时团队协作

三种协作模式：

- **Share**：分享会话链接，队友实时观看 Agent 工作并聊天
- **Co-drive**：队友远程 attach 到你的会话，在自己的机器上操作
- **Fork**：克隆会话，从分叉点独立继续

```Shell
// 代码块
omnigent attach  # Co-drive 附加到运行中的会话
omnigent run --fork  # Fork 一个会话
```

#### 4. 🔌 模型自由切换

支持四种凭证类型：

| 类型 | 说明 |
| --- | --- |
| 🔑 API Key | Anthropic、OpenAI 等官方 Key |
| 🎟️ Subscription | Claude Pro/Max、ChatGPT 订阅 |
| 🌐 Gateway | OpenRouter、LiteLLM、Ollama、vLLM、Azure 等 |
| 🧱 Databricks | Databricks Workspace Profile |

会话中可以用 `/model` 命令随时切换，不同 Agent 可以有不同的默认模型。

#### 5. ☁️ 云沙箱运行

Agent 不需要绑定在你的笔记本上。支持按需创建云端沙箱：

- **Modal** — Serverless GPU 沙箱
- **Daytona** — 开发环境沙箱
- **Islo** — 轻量隔离沙箱

部署方式：Docker Compose 一键启动、Render 一键部署，也支持 Fly.io、Railway、Hugging Face Spaces。

#### 6. 🛡️ Agent 治理策略（Policies）

这是企业级场景的关键能力。策略系统分三级：

```
// 代码块
Server-wide（管理员）→ Per-agent（开发者）→ Per-session（用户）
```

越内层越严格，Session 级规则优先检查。内置策略：

| 策略 | 功能 |
| --- | --- |
| `approve_shell` | 执行 Shell 命令前需人工确认 |
| `cap_calls` | 限制单会话工具调用次数 |
| `budget` | 消费上限 + 阈值警告 |

```YAML
// 代码块
policies:
  approve_shell:
    type: function
    handler: omnigent.policies.builtins.safety.ask_on_os_tools
  cap_calls:
    type: function
    handler: omnigent.policies.builtins.safety.max_tool_calls_per_session
    factory_params:
      limit: 50
  budget:
    type: function
    handler: omnigent.policies.builtins.cost.cost_budget
    factory_params:
      max_cost_usd: 5.00
      ask_thresholds_usd: [3.00]
```

#### 7. 📝 自定义 Agent（YAML 定义）

Agent 就是一个简短的 YAML 文件：

```YAML
// 代码块
name: my_agent
prompt: You are a helpful data analyst.

executor:
  harness: claude-sdk  # 或: codex, openai-agents, pi, cursor 等

tools:
  # 本地 Python 函数（签名自动生成 schema）
  word_count:
    type: function
    callable: mypackage.mymodule.word_count

  # 子 Agent（supervisor 可委托任务）
  researcher:
    type: agent
    prompt: Search for relevant information and summarize it.
    tools:
      word_count: inherit
```

运行：

```Shell
// 代码块
omnigent run path/to/my_agent.yaml
```

甚至可以让 Agent 帮你写 Agent——在任意 Omnigent 会话中描述你想要的 Agent，它会自动生成 YAML 文件。

### 四、内置示例 Agent

#### 🐙 Polly — 多 Agent 编码协调器

Polly 自己不写代码，她是技术负责人：

1. 分析任务，制定计划
2. 将子任务委托给编码 Agent（Claude Code / Codex / Pi），在**并行 git worktree** 中工作
3. 每个 diff 由**不同厂商的 Agent** 交叉 review
4. 你来决定是否 merge

#### 🟠🔵 Debby — 双模型头脑风暴

每个问题同时发给 Claude 和 GPT，并排展示两个回答。输入 `/debate`，两个"大脑"互相批判几轮后收敛。

### 五、落地实践场景

#### 1. 团队 AI 编码协作

多个开发者同时与 Agent 协作，Share/Co-drive/Fork 三种模式适配不同协作场景。特别适合远程团队 Pair Programming。

#### 2. 企业 Agent 治理

通过三层策略体系（Server → Agent → Session），实现：

- Shell 命令执行审批
- 工具调用次数限制
- 消费预算管控
- 符合企业安全合规要求

#### 3. 多模型 A/B 测试

同一任务在不同 harness 上运行，对比 Claude vs GPT vs 开源模型的输出质量。Debby Agent 就是这种模式的原型。

#### 4. 云端 CI/CD Agent

将 Agent 运行在 Modal/Daytona 沙箱中，不依赖本地环境。适合 CI 场景、定时任务、无人值守的 Agent 工作流。

#### 5. 自定义领域 Agent 快速开发

用 YAML 定义 Agent，几十行就能创建一个带子 Agent、带工具的专业 Agent。适合快速原型验证和领域定制。

#### 6. 移动办公场景

手机上随时查看 Agent 进度、发送指令、查看文件。适合需要随时关注 Agent 任务状态的管理者。

### 六、个人评价和建议

#### ✅ 优势

1. **定位精准**：不造轮子，做编排层。当团队已经在用多个 Agent 时，Omnigent 的价值立竿见影。
2. **治理能力强**：三层策略体系是目前开源 Agent 框架中最完善的安全治理方案，企业场景刚需。
3. **跨设备体验好**：终端 → 浏览器 → 手机的无缝切换，加上原生桌面 App，体验闭环。
4. **YAML 定义 Agent**：低门槛、可版本控制、可由 Agent 自举生成，设计优雅。
5. **云沙箱集成**：Modal/Daytona/Islo 三种方案覆盖不同场景，部署灵活。

#### ⚠️ 不足

1. **项目较新**：3.6K Stars，处于 Alpha 阶段，生产环境使用需谨慎。
2. **依赖链较重**：Python 3.12+、Node.js 22+、tmux、bubblewrap……安装前置条件多。
3. **中文支持未知**：README 全英文，文档体系尚在建设中，中文社区需要自建。
4. **性能开销**：meta-harness 层引入额外延迟，对实时性要求高的场景可能有影响。

#### 💡 建议

1. **如果你是团队技术负责人**：值得在非核心项目上试用，特别是治理策略部分，可以为自建 Agent 平台提供参考。
2. **如果你在做 Agent 平台开发**：Omnigent 的 meta-harness 架构和策略系统设计非常值得学习，尤其是 "YAML 定义 + 多 harness 切换" 的抽象方式。
3. **如果你是个人开发者**：目前可能过重，除非你确实需要同时用多个 Agent 运行时。但 Polly 和 Debby 的设计思路可以借鉴。
4. **关注方向**：随着 Agent 生态碎片化加剧，"统一编排 + 治理" 将是刚需赛道，Omnigent 在这个方向上走得很前。
