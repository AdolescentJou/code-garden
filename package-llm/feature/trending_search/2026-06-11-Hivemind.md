### 一、项目简介

Hivemind 是 Activeloop 推出的**跨 Agent 共享记忆与技能传播引擎**，核心理念是：

> "One brain for all your agents"

它解决了当前 AI Coding Agent 生态中最根本的痛点——**每个 Agent 每次都从零开始**。团队中一个工程师的 Agent 解决了复杂的数据迁移问题，第二天另一个工程师的 Agent 仍然不知道这套解法。Hivemind 把这个"领悟"变成团队所有 Agent 都能调用的共享知识。

**核心价值**：Agent A 今天踩过的坑，明天团队所有 Agent 都能绕开。

### 二、核心功能详解

#### 1. 📥 全量 Session 捕获（Capture）

每一个 Agent 会话的**提示词、工具调用、响应**都被完整结构化地存储到 Deeplake 向量数据库中，构成"交互轨迹"（trace）。

```
// 代码块
捕获内容：
- 用户每条 prompt
- 工具名称 + 完整输入
- 工具响应输出
- Agent 最终回复
- 子 Agent 活动
```

#### 2. 🧠 自动技能挖掘（Skillify）

这是 Hivemind 最独特的功能。背景工作进程在每次 Session 结束时自动启动：

1. 拉取最近 10 个 Session 的内容
2. 剥离工具调用噪声，只保留 prompt + 回复文本
3. 调用 Claude Haiku 做"模式判断"：
  - `KEEP <name> <body>` → 生成新 SKILL.md
  - `MERGE <existing-name>` → 更新已有技能
  - `SKIP <reason>` → 一次性操作，跳过
4. 将 SKILL.md 写入 `<project>/.claude/skills/<name>/` 并同步到团队共享存储

**团队协作**：技能支持 push/pull，用 `hivemind skillify pull` 一键拉取队友挖掘出的技能。每次 Session 启动时**自动 pull 全团队最新技能**，零感知传播。

#### 3. 🔍 混合检索（Hybrid Search）

- **语义检索**：基于本地 `nomic-embed-text-v1.5` 嵌入模型（768 维）
- **词法检索**：BM25 作为无嵌入模式的降级方案
- **代码图谱检索**：从真实 Agent 轨迹中构建文件/符号/导入关系图，"在哪处理 auth？"会精确落到团队 Agent 真正修改过的文件

自然语言查询示例：

```
// 代码块
"Emanuele 最近在做什么？"
"搜索我们解决过的认证 Bug"
"我们在 API 设计上做了什么决定？"
```

#### 4. 📝 Session Wiki 自动生成（Summaries）

每次 Session 结束后，后台 Worker 调用 Agent 自身的 CLI（`claude -p`/`codex exec` 等）自动生成 AI 撰写的 Wiki 摘要，存入 `~/.deeplake/memory/summaries/`。长 Session（50 条消息或 2 小时）会触发中途检查点。**无需额外 API Key**，复用 Agent 自身的模型能力。

#### 5. 📋 跨 Agent 团队规则（Rules）

在组织层面注入强制规则，每次 SessionStart 时自动注入到所有 Agent 上下文：

```Shell
// 代码块
hivemind rules add "生产数据库禁止 DROP TABLE"
hivemind rules list
hivemind rules edit <rule-id> "更新后的规则"
hivemind rules done <rule-id>
```

#### 6. 🗺️ 实时代码图谱（Codebase Graph）

从捕获的轨迹中自动构建代码库的实时知识图谱：文件、符号、导入关系、以及 Agent 实际遍历的调用边。检索时走图谱而非纯文本，结果更精准。

#### 7. 🎯 目标与 KPI 管理（Goals + KPIs）

基于虚拟文件系统（VFS）的目标跟踪，路径即结构：

```
// 代码块
~/.deeplake/memory/goal/<owner>/<status>/<uuid>.md
~/.deeplake/memory/kpi/<goal_id>/<kpi-slug>.md
```

### 四、使用方式

#### 快速安装（一键覆盖所有检测到的 Agent）

```Shell
// 代码块
npm install -g @deeplake/hivemind && hivemind install
```

#### 按 Agent 单独安装

```Shell
// 代码块
hivemind install --only claude    # 仅 Claude Code
hivemind claw install             # 仅 OpenClaw
hivemind codex install            # 仅 Codex
hivemind cursor install           # 仅 Cursor
```

#### CI/无头环境安装

```Shell
// 代码块
HIVEMIND_TOKEN=<your-token> hivemind install
```

#### 检查安装状态

```Shell
// 代码块
hivemind status
```

#### 技能管理

```Shell
// 代码块
# 查看当前技能状态
hivemind skillify

# 切换范围（个人/团队）
hivemind skillify scope team

# 拉取队友挖掘的技能
hivemind skillify pull
hivemind skillify pull --user alice@example.com

# 推广某个项目级技能到全局
hivemind skillify promote <skill-name>

# 干运行预览
hivemind skillify pull --dry-run
```

#### 禁用捕获（隐私模式）

```Shell
// 代码块
HIVEMIND_CAPTURE=false claude   # 仅本次 Session
```

#### 本地开发

```Shell
// 代码块
git clone https://github.com/activeloopai/hivemind.git
cd hivemind
npm install
npm run build    # tsc + esbuild，多平台 bundle
npm test         # vitest

# 本地测试（Claude Code）
claude --plugin-dir claude-code
```

#### 关键环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `HIVEMIND_TOKEN` | - | API token |
| `HIVEMIND_CAPTURE` | `true` | 设为 `false` 禁用捕获 |
| `HIVEMIND_EMBEDDINGS` | `true` | 设为 `false` 降级为纯词法检索 |
| `HIVEMIND_SKILLIFY_EVERY_N_TURNS` | `20` | 每 N 轮触发一次技能挖掘 |
| `HIVEMIND_DEBUG` | - | 设为 `1` 开启详细日志 |

### 五、架构设计

```
// 代码块
Capture → Codify → Propagate → Compound

[Agent 会话] 
    ↓ (hooks/插件)
[Deeplake 向量存储]
    ↓ (后台 Worker)
[SKILL.md 技能文件]
    ↓ (SessionStart auto-pull)
[团队所有 Agent 上下文]
```

**存储后端**：Deeplake（结构化 tensor 格式，可直接导出为 PyTorch 数据集用于微调）
**BYOC 支持**：GCS / Azure Blob / S3 / S3 兼容私有部署，数据不出企业边界
**安全性**：TLS 传输 + AES-256 落地加密，SQL 值转义防注入，凭证文件 0600 权限

### 六、落地实践场景

#### 场景 1：中大型工程团队 Agent 知识沉淀

**问题**：10 人团队，每人都在用 Claude Code，但各自踩坑各自解决，没有积累。
**方案**：团队统一部署 Hivemind，scope 设为 team，每周自动 pull 队友技能。
**效果**：Senior 工程师解决的架构问题自动变成 Junior 工程师 Agent 的可调用技能。

#### 场景 2：复杂代码库的上下文召回

**问题**：大型 Monorepo，Agent 每次都要重新探索依赖关系、摸清架构。
**方案**：开启代码图谱 + 语义搜索，Agent 召回历史轨迹中已探索过的路径。
**效果**：Token 消耗减少 40%+，避免重复"探索"同一代码区域。

#### 场景 3：生产操作规范强制执行

**问题**：Agent 偶尔会生成有风险的生产操作（如 DROP TABLE）。
**方案**：用 `hivemind rules add` 注入不可绕过的团队规则，每次 Session 自动注入。
**效果**：规则在组织层面强制，不依赖个人 prompt 工程习惯。

#### 场景 4：Agent 轨迹用于模型微调

**问题**：团队积累大量高质量 Agent 轨迹，想用于 fine-tune 内部模型。
**方案**：Deeplake tensor 格式天然 PyTorch 兼容，直接导出为训练数据集。
**效果**：从"使用 AI"到"训练专属 AI"，知识产权留在企业内部。

#### 场景 5：多 Agent 框架 + 隔离管控

**问题**：同时使用 Cursor + Claude Code + OpenClaw，需要统一记忆但互不干扰。
**方案**：Hivemind 对每个 workspace 隔离，同一 org 内共享，不同 org 严格隔离。
**效果**：一套基础设施管理跨 IDE 的 Agent 记忆和技能，避免碎片化。

### 七、个人评价与建议

#### ✅ 亮点

1. **技能挖掘机制极具创新性**：用 Agent 本身来理解 Agent 行为，自动从历史会话提炼可复用知识，是 meta-learning 的工程化落地。
2. **多平台支持覆盖面广**：Claude Code、OpenClaw、Codex、Cursor、Hermes 全覆盖，没有选择困难。
3. **基准测试数据透明**：公开 LoCoMo 测试结果，而不只是定性描述，有说服力。
4. **BYOC 架构**：企业级数据合规友好，数据主权在用户侧。

#### ⚠️ 注意事项

1. **隐私问题**：默认捕获所有 prompt 和工具调用，**team 成员默认可读彼此数据**，这是设计而非缺陷，但务必在启用前和团队明确沟通。
2. **语义搜索依赖额外安装**：`nomic-embed` 模型约 600MB，不启用则降级为 BM25，召回质量有差距。
3. **技能质量依赖 Claude Haiku 判断**：挖掘结果可能有噪声，建议开启 skill review 等待团队手动确认后再 push。
4. **当前 901 stars 相对不高**：项目仍在快速迭代（v0.7.88），今日 Trending 64 stars，适合早期采用者。

#### 🎯 给杰哥的建议

Hivemind 对 **重度使用多 AI Coding Agent 的团队** 价值最大。如果你在 OpenClaw 环境下使用，它已经有 Native 扩展支持，安装成本极低（`hivemind claw install`）。建议：

1. 先个人试用（scope=me），评估技能挖掘质量
2. 确认隐私策略后再推广到团队
3. 如果代码库是私有 Monorepo，强烈建议开启 BYOC 模式（S3/GCS）

**整体评分：★★★★☆**（理念超前，工程扎实，但生态尚早期）
