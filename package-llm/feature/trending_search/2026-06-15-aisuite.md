### 一、项目简介

aisuite 是吴恩达（Andrew Ng）开源的轻量级 Python 库，旨在解决 AI Agent 开发中最基础也最烦人的问题：**不同 LLM Provider 的 API 接口不统一**。

项目分两层架构：

- **底层**：Chat Completions API — 统一 OpenAI、Anthropic、Google、AWS、Mistral、HuggingFace、Ollama、OpenRouter 等 Provider 的调用接口，切换模型只需改一个字符串
- **上层**：Agents API + Toolkits + MCP — 在统一接口之上构建完整的 Agent 开发能力，包括工具调用、多轮循环、工具策略、状态持久化等

此外，项目还内置了 **OpenCoworker** — 一个基于 aisuite 构建的桌面 AI 助手应用（macOS / Windows），可作为 Agent Harness 的参考实现。

```
// 代码块
┌───────────────────────────────────────────────┐
│ OpenCoworker        │ agent harness for doing everyday tasks  │
├───────────────────────────────────────────────┤
│ Agents API · Toolkits · MCP │ build agents across multiple LLMs  │
├───────────────────────────────────────────────┤
│ Chat Completions API │ one API across multiple LLM providers     │
├────────┬───────────┬────────┬────────┬────────┤
│ OpenAI │ Anthropic │ Google │ Ollama │ Others │
└────────┴───────────┴────────┴────────┴────────┘
```

#### 核心定位

aisuite 不是又一个大模型框架，而是一个**基础设施层**。它不做模型训练、不做 UI、不做 RAG — 只专注于解决"多 Provider 调用"这一件事，并在此基础上提供最小可用的 Agent 工具链。

### 二、核心功能详解

#### 2.1 统一 Chat Completions API

这是 aisuite 的根基。所有 Provider 的 Chat 调用被统一为 OpenAI 风格的接口：

```Python
// 代码块
import aisuite as ai

client = ai.Client()

models = ["openai:gpt-4o", "anthropic:claude-3-5-sonnet-20240620"]

messages = [
    {"role": "system", "content": "Respond in Pirate English."},
    {"role": "user", "content": "Tell me a joke."},
]

for model in models:
    response = client.chat.completions.create(
        model=model,
        messages=messages,
        temperature=0.75
    )
    print(response.choices[0].message.content)
```

**模型命名规则**：`<provider>:<model-name>`，如 `openai:gpt-4o`、`anthropic:claude-sonnet-4-6`、`ollama:llama3.1:8b`。aisuite 自动路由到正确的 Provider SDK。

**支持的 Provider**（持续扩展中）：

| Provider | 标识符 | 备注 |
| --- | --- | --- |
| OpenAI | `openai` | 原生支持 |
| Anthropic | `anthropic` | 原生支持 |
| Google | `google` | Gemini 系列 |
| AWS Bedrock | `aws` | 托管模型 |
| Azure | `azure` | Azure OpenAI |
| Mistral | `mistral` | 原生支持 |
| HuggingFace | `huggingface` | 开源模型 |
| Groq | `groq` | 高速推理 |
| Ollama | `ollama` | 本地模型 |
| OpenRouter | `openrouter` | 聚合路由 |
| Cohere | `cohere` | 企业搜索 |

#### 2.2 工具调用（Tool Calling）— max_turns 模式

aisuite 把工具调用简化为一行配置。传普通 Python 函数，aisuite 自动生成 JSON Schema、执行调用、把结果返回给模型：

```Python
// 代码块
def will_it_rain(location: str, time_of_day: str):
    """Check if it will rain in a location at a given time today.

    Args:
        location (str): Name of the city
        time_of_day (str): Time of the day in HH:MM format.
    """
    return "YES"

client = ai.Client()
response = client.chat.completions.create(
    model="openai:gpt-4o",
    messages=[{
        "role": "user",
        "content": "I live in San Francisco. Can you check for weather "
                   "and plan an outdoor picnic for me at 2pm?"
    }],
    tools=[will_it_rain],
    max_turns=2  # 最多 2 轮工具调用循环
)
print(response.choices[0].message.content)
```

关键设计：

- 设置 `max_turns` 后，aisuite 自动执行"模型→工具调用→返回结果→模型"的循环
- `response.choices[0].intermediate_messages` 携带完整的工具交互历史
- 不设 `max_turns` 则走手动模式，aisuite 只返回模型的工具调用请求，开发者自己跑循环

#### 2.3 Agents API — 结构化 Agent 开发

对于更复杂的场景，aisuite 提供了 Agent + Runner 模式：

```Python
// 代码块
import aisuite as ai
from aisuite import Agent, Runner

agent = Agent(
    name="repo-helper",
    model="anthropic:claude-sonnet-4-6",
    instructions="You are a careful repo assistant. Use your tools to answer from the code.",
    tools=[*ai.toolkits.files(root="."), *ai.toolkits.git(root=".")],
)

result = Runner.run(agent, "What changed in the last commit? Summarize in 3 bullets.")
print(result.final_output)
```

**Agent API 生产级能力**：

| 能力 | 说明 |
| --- | --- |
| **Tool Policies** | `RequireApprovalPolicy`、allow/deny 列表，或自定义 callable 控制哪些工具调用可执行 |
| **State Stores** | 持久化 & 恢复 Agent 运行状态（内存 / 文件 / Postgres），跨进程继续对话 |
| **Artifacts & Tracing** | 捕获 Agent 产出物和每一步的执行轨迹 |
| **Toolkits** | 预构建的沙箱化工具族（files / git / shell），开箱即用 |

#### 2.4 MCP 原生支持

aisuite 原生支持 Model Context Protocol，任何 MCP Server 的工具可以直接作为 Agent 工具使用：

```Python
// 代码块
client = ai.Client()
response = client.chat.completions.create(
    model="openai:gpt-4o",
    messages=[{"role": "user", "content": "List the files in the current directory"}],
    tools=[{
        "type": "mcp",
        "name": "filesystem",
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/directory"]
    }],
    max_turns=3
)
print(response.choices[0].message.content)
```

安装：`pip install 'aisuite[mcp]'`

对于更复杂的 MCP 场景，还提供显式 `MCPClient`，支持可复用连接、安全过滤和工具前缀。

#### 2.5 OpenCoworker — 桌面 AI 助手

基于 aisuite 构建的桌面应用，是 Agent Harness 的参考实现：

- **能力**：聊天、深度研究、执行任务（读文件/发消息/创建交付物）、定时自动化
- **隐私**：数据本地存储，支持自带 API Key 或 Ollama 本地模型
- **平台**：macOS 13+ (Apple Silicon)、Windows 10/11 (x64)
- 源码在仓库的 `platform/` 目录下

#### 2.6 Provider 扩展机制

新增 Provider 只需实现轻量级 Adapter，遵循命名约定即可自动发现：

```Python
// 代码块
# providers/openai_provider.py
class OpenaiProvider(BaseProvider):
    ...
```

- 模块文件：`<provider>_provider.py`
- 类名：`<Provider>Provider`（首字母大写）

### 三、使用方式

#### 3.1 安装

```Shell
// 代码块
# 基础安装（不含任何 Provider SDK）
pip install aisuite

# 安装特定 Provider SDK
pip install 'aisuite[anthropic]'

# 安装所有 Provider SDK
pip install 'aisuite[all]'

# MCP 支持
pip install 'aisuite[mcp]'
```

#### 3.2 API Key 配置

环境变量方式（最简单）：

```Shell
// 代码块
export OPENAI_API_KEY="your-openai-api-key"
export ANTHROPIC_API_KEY="your-anthropic-api-key"
export GOOGLE_API_KEY="your-google-api-key"
```

也可以通过代码中的配置对象传递，支持多 Provider 混合 Key。

#### 3.3 快速对比测试

aisuite 最典型的使用场景之一 — 快速对比不同模型的输出：

```Python
// 代码块
import aisuite as ai

client = ai.Client()

prompt = "Explain quantum computing in 3 sentences."
models = [
    "openai:gpt-4o",
    "anthropic:claude-sonnet-4-6",
    "google:gemini-2.5-pro",
    "ollama:llama3.1:8b"
]

for model in models:
    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
        temperature=0.7
    )
    print(f"\n[{model}]:")
    print(response.choices[0].message.content)
```

#### 3.4 构建 Agent 的完整流程

```Python
// 代码块
import aisuite as ai
from aisuite import Agent, Runner

# 1. 定义 Agent
agent = Agent(
    name="data-analyst",
    model="openai:gpt-4o",
    instructions="""You are a data analyst. 
    - Always read data files before making claims
    - Show your reasoning step by step
    - Provide actionable insights""",
    tools=[
        *ai.toolkits.files(root="./data"),
        *ai.toolkits.shell(allowed_commands=["python3", "wc", "head", "tail"]),
    ],
)

# 2. 运行
result = Runner.run(
    agent, 
    "Analyze the sales data in ./data/sales.csv and give me top 3 insights"
)

# 3. 获取结果
print(result.final_output)

# 4. 如需继续对话
result2 = Runner.run(agent, "Now compare this with last quarter", state=result.state)
```

### 四、落地实践场景

#### 场景 1：多模型 A/B 测试与效果评估

**痛点**：上线 AI 产品前需要评估不同模型在同一任务上的表现，但每个 Provider 的 SDK 调用方式不同，切换成本高。

**方案**：用 aisuite 统一接口，只需切换 `model` 字符串即可跑同一套 prompt 在多个模型上的对比。结合评估框架（如 Promptfoo、Ragas），可快速产出模型选型报告。

#### 场景 2：AI Agent 快速原型验证

**痛点**：想快速验证一个 Agent 概念，但不想从零搭基础设施（工具调用循环、Provider 适配、状态管理）。

**方案**：aisuite 的 Agent + Runner + Toolkits 提供了最小可用的 Agent 开发闭环。加 MCP 支持后，几乎任何外部工具都能接入。适合做 POC 和 MVP。

#### 场景 3：本地优先的隐私 AI 助手

**痛点**：企业或个人需要 AI 能力但数据不能出域。

**方案**：aisuite + Ollama，所有推理在本地完成。OpenCoworker 桌面应用直接可用，数据存储在本地 SQLite。

#### 场景 4：多 Provider 降级容灾

**痛点**：生产环境中单一 Provider 的 API 可能宕机或限流。

**方案**：aisuite 的统一接口让 Provider 降级只需改一个字符串。可在应用层实现自动降级逻辑：

```Python
// 代码块
import aisuite as ai

client = ai.Client()

def call_with_fallback(prompt, primary="openai:gpt-4o", fallback="anthropic:claude-sonnet-4-6"):
    try:
        return client.chat.completions.create(
            model=primary,
            messages=[{"role": "user", "content": prompt}]
        )
    except Exception:
        return client.chat.completions.create(
            model=fallback,
            messages=[{"role": "user", "content": prompt}]
        )
```

#### 场景 5：MCP 工具集成

**痛点**：已有大量 MCP Server（文件系统、数据库、API 网关等），但接入 Agent 需要写大量胶水代码。

**方案**：aisuite 原生 MCP 支持，一个 JSON 配置即可将 MCP Server 的工具暴露给模型，无需手写 Schema 映射。

### 五、个人评价和建议

#### 优势

1. **问题定义精准**：多 Provider 调用不统一是 AI 工程的日常痛点，aisuite 瞄准这一点做深做透
2. **极简设计**：不是又一个大而全的 Agent 框架，而是可组合的基础设施层。Chat API 可独立使用，Agent API 按需叠加
3. **吴恩达背书**：项目维护质量有保障，社区活跃，14.4k+ Stars
4. **MCP 原生支持**：紧跟 2026 年 Agent 生态的标准协议方向
5. **OpenCoworker 参考实现**：不是纯库，有端到端的 Agent 应用可参考
6. **Provider 扩展简单**：命名约定 + BaseProvider 即可新增 Provider

#### 不足

1. **RAG/向量检索缺失**：aisuite 不处理知识库和检索增强，需要搭配 LangChain / LlamaIndex 等使用
2. **多 Agent 编排较弱**：没有内置多 Agent 协作（如 CrewAI 那样），需要自己在上层编排
3. **流式响应支持有限**：对 SSE / Streaming 的支持还在完善中
4. **TypeScript 版本功能滞后**：aisuite-js 覆盖的功能不如 Python 版完整
5. **Provider 特有功能适配不完整**：如 OpenAI 的 Structured Outputs、Anthropic 的 Extended Thinking 等特有能力，统一接口中可能无法使用

#### 与同类项目对比

| 项目 | 定位 | 优势 | 劣势 |
| --- | --- | --- | --- |
| **aisuite** | 多 Provider 统一接口 + 轻量 Agent | 极简、Provider 切换一行代码 | 功能少，无 RAG/多 Agent |
| **Litellm** | 多 Provider 代理网关 | 功能更全（成本追踪、限流、缓存） | 更重，需要部署代理服务 |
| **LangChain** | 全栈 LLM 开发框架 | 生态最全 | 复杂度高，学习曲线陡 |
| **CrewAI** | 多 Agent 协作框架 | 多 Agent 编排开箱即用 | 单 Provider 依赖强 |

#### 建议

- **入门 AI Agent 开发**：aisuite 是最佳起点。先掌握 Chat API + Tool Calling，再叠加 Agent API
- **生产级 Agent**：aisuite 做 Provider 层，上层搭配专业框架（如 LangGraph 做工作流编排）
- **企业内部**：建议用 aisuite 做统一 LLM 网关，实现 Provider 降级和成本控制
- **值得关注**：aisuite 的 MCP 集成和 State Store 持久化正在快速发展，这是向生产级 Agent 框架演进的关键能力
