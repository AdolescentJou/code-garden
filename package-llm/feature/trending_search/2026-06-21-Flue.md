### 一、项目简介

Flue 是 Astro 团队（withastro）推出的开源 **Agent Harness Framework**，即"AI Agent 线束框架"。它不是又一个 Agent SDK，而是一套完整的 TypeScript 编程式线束（harness），让开发者可以为任意 LLM 模型构建真正自主的 Agent——拥有会话、工具、技能、指令、文件系统访问和沙箱环境的完整运行时。

#### 核心定位

Flue 的核心理念来自对 Agent 演进的观察：

- **第一代**：原始 LLM API 调用，只能做简单聊天和脚本任务
- **第二代**：以 Claude Code、Codex 为代表，真正自主的 Agent——给它任务，而不是步骤，信任它用提供的上下文和工具自主完成
- **Flue 的目标**：将这种"自主 Agent"架构开放给所有开发者

Flue 提供的不是一个工具库，而是一个**运行时线束**——Agent 的"全副武装"，包含会话管理、工具调用、技能加载、沙箱执行、持久化等完整基础设施。

### 二、核心功能详解

#### 1. Agents（自主 Agent）

Flue Agent 不是简单的 chatbot，而是可以跨对话和事件保持上下文、自主向目标推进的实体：

```TypeScript
// 代码块
// agents/triage.ts
import { defineAgent, type AgentRouteHandler } from '@flue/runtime';
import { local } from '@flue/runtime/node';
import triage from '../skills/triage/SKILL.md' with { type: 'skill' };
import verify from '../skills/verify/SKILL.md' with { type: 'skill' };
import * as githubTools from '../tools/github.ts';

const instructions = `
Triage a bug report end-to-end: reproduce the bug,
diagnose the root cause, verify whether the behavior is
intentional, and attempt a fix.
`;

export const route: AgentRouteHandler = async (_c, next) => next();

export default defineAgent(() => ({
  model: 'anthropic/claude-sonnet-4-6',
  tools: [...githubTools],
  skills: [triage, verify],
  sandbox: local(),
  instructions,
}));
```

**关键设计**：

- `defineAgent()` 声明式定义，组合模型、工具、技能、沙箱
- `route` 导出控制 HTTP 访问权限（安全网关）
- Agent 通过 CLI 本地运行，或部署到 Cloudflare Workers 等

#### 2. Workflows（结构化工作流）

Workflow 是代码驱动的结构化自动化——从明确输入到完成结果的完整流程：

```TypeScript
// 代码块
// workflows/triage.ts
import { defineWorkflow } from '@flue/runtime';
import triageAgent from '../agents/triage.ts';

export default defineWorkflow({
  agent: triageAgent,
  input: { type: 'object', properties: { issueUrl: { type: 'string' } } },
  output: { type: 'object', properties: { summary: { type: 'string' } } },
  async run(ctx) {
    const result = await ctx.agent.prompt(`Triage: ${ctx.input.issueUrl}`);
    return { summary: result };
  },
});
```

- Workflow 需要 Agent 定义，代码引导 Agent 推理
- 输入/输出有 schema 校验
- 支持 `invoke(workflow, { input })` 编程式调用

#### 3. Sandboxes（沙箱执行环境）

Flue 给 Agent 提供了安全的执行环境：

```TypeScript
// 代码块
import { local } from '@flue/runtime/node';
import { virtual } from '@flue/runtime';

// 本地沙箱（开发用）
sandbox: local()

// 虚拟沙箱（隔离文件系统）
sandbox: virtual()

// Cloudflare 沙箱（生产部署）
sandbox: cloudflareSandbox()
```

- Agent 可以在沙箱中使用工具、修改文件、自主完成实际工作
- 沙箱与 Harness 绑定，不同 Agent 实例之间隔离
- `FlueFs.writeFile()` 保证自动创建父目录

#### 4. Skills（可复用技能包）

Skills 是打包好的可复用专业知识和工作流，Agent 可以在任务需要时加载：

```TypeScript
// 代码块
import triage from '../skills/triage/SKILL.md' with { type: 'skill' };

export default defineAgent(() => ({
  skills: [triage, verify],
  // ...
}));
```

- 技能可以从本地文件、npm 包或 workspace 包导入
- Vite 解析支持，包管理器 symlink 兼容
- `flue add` 命令可安装官方技能

#### 5. Subagents（子 Agent 委派）

定义专业角色，让主 Agent 将任务委派给合适的专家：

- 支持 Task 和 Action 两种委派模式
- 混合委派深度限制，防止无限递归
- 子 Agent 共享父级 policy、sandbox、filesystem、environment

#### 6. Durable Execution（持久化执行）

Agent 可以从故障和重启中恢复：

- Workflow run 有持久化状态
- Recovery 恢复中断的 turn，先完成已有工作再检查预算
- 修复部分 tool batch，不重播已完成工具
- Durable Streams 协议替代 WebSocket/SSE，支持断点续传

#### 7. Channels（事件通道）

接收来自外部系统的验证事件：

- **官方支持**：Slack、Teams、Discord、GitHub、Google Chat、Telegram、WhatsApp、Twilio、Messenger、Intercom、Zendesk、Salesforce、Stripe、Notion、Resend、Shopify、Linear
- 每个 Channel 有独立的 `@flue/<channel>` 包
- `flue add blueprints` 可生成可编辑的集成代码

#### 8. Observability（可观测性）

- OpenTelemetry 原生支持（`@flue/opentelemetry`）
- Braintrust、Sentry 集成
- 自定义 Observer 接口

#### 9. 持久化适配器

import { defineTool } from '@flue/runtime';
import * as v from 'valibot';

export const searchIssues = defineTool({
  name: 'search_issues',
  description: 'Search GitHub issues',
  parameters: v.object({
    query: v.string(),
    repo: v.optional(v.string()),
  }),
  async execute({ query, repo }) {
    const url = repo
      ? `https://api.github.com/repos/${repo}/issues?q=${query}`
      : `https://api.github.com/search/issues?q=${query}`;

});

### 四、落地实践场景

#### 1. 自动化 Bug Triage

最经典场景——给 Agent 一个 Bug Report，让它端到端地复现、诊断根因、判断是否是预期行为、尝试修复。Flue 的沙箱让 Agent 可以安全地在隔离环境中运行测试、修改代码。

#### 2. CI/CD 中的 AI Agent

通过 GitHub Actions / GitLab CI/CD 部署，Agent 可以在 PR 审查、代码分析、安全审计等环节中作为自动化助手运行。Workflow 的持久化执行确保即使 CI Runner 重启也能恢复进度。

#### 3. 企业沟通集成

16+ 官方 Channel 集成，让 Agent 可以监听 Slack/Discord/Teams 等平台的事件并自动响应。例如：

- Slack 中 @Agent 自动分析问题
- GitHub Issue 创建时自动分类和分配
- Stripe Webhook 触发财务报表生成

#### 4. 多 Agent 协作

通过 Subagents 定义不同专业角色的 Agent，主 Agent 负责任务分解和委派：

- 安全审计 Agent → 代码审查 Agent → 修复 Agent
- 调研 Agent → 写作 Agent → 校对 Agent

#### 5. 客服 / 工单自动化

结合 Zendesk、Intercom、Salesforce 等 Channel，Agent 可以自动处理客户工单，在沙箱中查询系统、生成回复、执行操作。

#### 6. 内部工具编排

MCP Server 支持让 Agent 连接到已认证的工具和服务生态，Flue 的 Harness 架构让多个工具的编排变得类型安全。

### 五、个人评价和建议

#### 亮点

1. **架构成熟**：不是玩具项目。从 CHANGELOG 可以看出迭代节奏快、breaking change 管理（semver 版本迁移指南）专业，已经在认真做向后兼容
2. **Astro 团队出品**：withastro 是 Web 框架 Astro 背后的团队，在 DX（开发者体验）和模块化设计上有深厚积累
3. **沙箱优先**：这是区别于其他 Agent 框架的核心——沙箱不是附加功能，而是 Agent 运行的基本环境，从架构层面保证了安全性
4. **Channel 生态丰富**：16+ 官方 Channel 包，从 Slack 到 WhatsApp，从 Stripe 到 Salesforce，企业集成能力极强
5. **持久化 + Durable Streams**：这不是 demo 级别的持久化，而是生产级的 Durable Streams 协议、多种数据库适配器、断点续传
6. **类型安全**：Valibot schema 校验、TypeScript 全栈、工具参数类型推断

#### 注意事项

1. **还在 beta**：当前版本 1.0.0-beta.x，API 仍在快速迭代，breaking change 频繁
2. **依赖链较重**：底层依赖 `@earendil-works/pi-ai` 和 `@earendil-works/pi-agent-core`，需要 Node.js >= 22.19.0
3. **学习曲线**：概念较多（Agent/Workflow/Skill/Tool/Channel/Blueprint/Sandbox/Harness/Session/Operation/Turn），初次接触需要时间理解层级关系
4. **文档尚不完善**：虽然 `flue docs` 提供了离线文档，但线上文档站目前无法访问
