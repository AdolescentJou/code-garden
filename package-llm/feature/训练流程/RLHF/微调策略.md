# RLHF 微调策略对比：PPO / DPO / GRPO / GSPO

---

## 一、PPO（Proximal Policy Optimization，近端策略优化）

> **一句话定位**：RLHF 经典基石，Actor-Critic 双模型，靠裁剪保证稳定，通用性最强但显存 / 计算开销最大。

### 核心原理

基于 **策略梯度 + Actor-Critic** 框架：

- **Actor**：待优化的语言模型（生成答案）
- **Critic**：价值网络（估计状态价值，辅助优势函数计算）
- **Reward Model (RM)**：对生成结果打分（人类偏好 / 规则）
- 用 **裁剪（Clip）** 限制策略更新幅度，防止一步更新过大导致训练崩溃。

📌 **流程**：采样 → RM 打分 → GAE 计算优势 → 裁剪更新策略

### 优缺点

| | 说明 |
|---|---|
| ✅ 优点 | 稳定性极高、对超参数不敏感、通用性强（早期 ChatGPT、代码 / 对话 / 控制任务） |
| ❌ 缺点 | 显存占用高（需同时跑 Actor + Critic + RM）、计算密集、大模型训练效率低 |

### 适用场景

通用 RLHF、对话对齐、早期大模型对齐、对稳定性要求极高的任务。

---

## 二、DPO（Direct Preference Optimization，直接偏好优化）

> **一句话定位**：无强化学习、无 Critic、无 GAE，直接用"偏好对"优化，极简、显存友好、训练快。

### 核心原理

抛弃传统 RL 循环，直接在 **偏好数据（y_winner, y_loser）** 上优化：

- **目标**：让模型对"更好答案"的概率，显著高于"更差答案"
- 损失基于对数概率差 + KL 散度正则（防止偏离基座模型）
- 本质是 **监督式偏好学习**，不是严格意义上的强化学习

### 优缺点

| | 说明 |
|---|---|
| ✅ 优点 | 极简、显存极低（仅需基座 + 策略模型）、训练快、超参数少、易复现 |
| ❌ 缺点 | 依赖高质量成对偏好数据、难以处理复杂多目标 / 客观奖励（如代码执行、数学对错）、长序列 / 推理任务效果一般 |

### 适用场景

对话对齐、摘要、翻译、数据充足的偏好任务、快速原型验证。

---

## 三、GRPO（Group Relative Policy Optimization，组相对策略优化）

> **一句话定位**：DeepSeek 提出，去掉 Critic、组内相对排名、显存减半、数学 / 代码 / 推理强。

### 核心原理

对同一输入，批量生成 N 个答案（组内样本），用 **相对排名** 而非绝对奖励优化。

**关键创新**：

- 无 Critic、无 GAE，组内归一化奖励作为优势信号
- 支持 **客观奖励**（如代码执行、数学对错）+ 主观奖励融合
- 损失基于组内对数概率差 + 组相对裁剪

📌 **流程**：组采样 → 客观 / 主观打分 → 组内归一化 → KL 正则 → 更新策略

### 优缺点

| | 说明 |
|---|---|
| ✅ 优点 | 显存大幅降低（≈ PPO 的 50%）、训练更稳、支持多奖励、数学 / 代码 / 推理能力强、DeepSeek-R1 / Qwen 等主流模型标配 |
| ❌ 缺点 | 对组内样本多样性敏感、token 级优化在长序列易不稳定、MoE 模型中易受专家激活波动影响 |

### 适用场景

数学推理、代码生成、多目标优化、需要客观奖励的任务、大模型高效对齐。

---

## 四、GSPO（Group Sequence Policy Optimization，组序列策略优化）

> **一句话定位**：GRPO 的序列级升级，解决 GRPO token 级不稳定，长序列 / Agent / 长思考更稳更强。

### 核心原理

在 GRPO 基础上，把 **token 级优化提升到整个序列级**：

- 计算整段序列的联合概率，而非逐 token 计算
- 序列级重要性采样 + 序列级裁剪，对单个 token 波动不敏感
- 更适配 MoE、长上下文、多步推理

📌 **流程**：组采样 → 序列级奖励 → 序列级优势估计 → 序列级裁剪 → 更新

### 优缺点

| | 说明 |
|---|---|
| ✅ 优点 | 长序列稳定性大幅提升、MoE 友好、长链思考 / Agent 任务更强、性能随计算持续扩展 |
| ❌ 缺点 | 实现更复杂、计算略高于 GRPO、短任务优势不明显 |

### 适用场景

长文本生成、长链推理、Agent 任务、复杂代码、MoE 模型、需要极高稳定性的对齐。

## 五、四者核心对比表（一眼看懂）

| 维度 | PPO | DPO | GRPO | GSPO |
|------|-----|-----|------|------|
| **训练范式** | Actor-Critic（双模型） | 监督式偏好学习（无 RL） | 组内相对优化（无 Critic） | 组序列优化（GRPO 序列级） |
| **核心组件** | Actor + Critic + RM | 基座模型 + 策略模型 | Actor + RM（无 Critic） | Actor + RM（序列级优化） |
| **优化粒度** | Token 级 | 序列级（成对） | Token 级（组内） | 序列级（整段） |
| **显存占用** | 🔴 最高 | 🟢 最低 | 🟡 中（≈ PPO 50%） | 🟠 中高（略高于 GRPO） |
| **训练速度** | 🔴 最慢 | 🟢 最快 | 🟡 中快 | 🟠 中 |
| **稳定性** | 极高 | 高 | 高（优于 PPO） | 🟢 最高（长序列 / MoE 友好） |
| **奖励类型** | 主观 / 客观均可 | 主观偏好为主 | 主观 + 客观融合 | 主观 + 客观融合 |
| **代表模型** | GPT-3.5、早期 RLHF | 各类对话模型 | DeepSeek-R1、Qwen 系列 | Qwen 3、长序列 / Agent 模型 |
| **最佳场景** | 通用对齐、稳定性优先 | 对话 / 摘要、快速迭代 | 数学 / 代码、多目标、高效对齐 | 长思考、Agent、MoE、复杂推理 |

## 六、演进关系与选择建议

### 演进脉络

```
PPO ──→ DPO ──→ GRPO ──→ GSPO
(经典RL)  (极简,去RL)  (去Critic,组相对,客观奖励)  (序列级,长序列/MoE稳定)
```

### 怎么选？

| 场景 | 推荐策略 |
|------|----------|
| 🚀 快速验证、对话任务 | **DPO** |
| 🧮 数学 / 代码、多目标、显存有限 | **GRPO** |
| 📜 长序列、Agent、MoE、稳定性极致 | **GSPO** |
| 🛡️ 通用、传统 RLHF、稳定性第一 | **PPO** |
