# 🍡 在 Mac M2（16GB）上从零完成 SFT + DPO 微调训练，打造中文个人助手

> 本教程面向想要用自己的数据微调一个**中文个人助手**的初学者。不需要 GPU，不需要 Linux 服务器，一台 Mac M2 16GB 就够了。

---

## 📖 概述：你会学到什么

通过本教程，你将：

- 🔧 在一台 Mac M2 16GB 上搭建完整的微调训练环境
- 📝 理解并准备 SFT（有监督微调）和 DPO（直接偏好优化）两种训练所需的数据格式
- 🚀 用 **QLoRA 4bit + LoRA** 技术对 **Qwen2.5-1.5B-Instruct** 做 SFT 训练
- 📊 对比训练前后的效果，学会评估模型表现
- 🎯 用 DPO 进一步提升模型的对齐质量（回答更贴近你的偏好）
- 🏁 将最终模型转为 GGUF 格式，用 Ollama 部署，真正在本地跑起来

整个流程不需要显卡、不需要服务器，Mac M2 16GB 全程够用。

## 🧠 核心概念速通

### SFT（Supervised Fine-Tuning，有监督微调）

SFT 就是给模型"喂"大量带答案的问答对，让它学习特定领域的回答方式。打个比方：模型已经学了"语文、数学、英语"的基础知识（预训练），SFT 就是给它开小灶，教它"怎么做一个中文个人助手"。

### DPO（Direct Preference Optimization，直接偏好优化）

DPO 是在 SFT 之后的一步。它不是告诉模型"正确答案是什么"，而是告诉它"哪个回答更好、哪个更差"。比如两个回答都是对的，一个啰嗦，一个简洁，DPO 会让模型学会偏好简洁的那个。这比 SFT 更接近人类的对齐偏好。

### LoRA（Low-Rank Adaptation，低秩适配）

微调大模型的一个核心问题：全量训练太贵（需要改全部参数，动辄上百GB显存）。LoRA 的聪明之处在于，它不直接改模型的权重，而是在旁边加一个**很小的"旁路"**（低秩矩阵），只训练这个旁路。模型主体几乎不动，但能力大幅提升。就像给一个员工加了一个小笔记本，不改变他本身，但极大地提升了他的工作效率。

### QLoRA（Quantized LoRA，量化低秩适配）

QLoRA 在 LoRA 的基础上再优化一步：把模型权重**压缩到 4bit**（16bit → 4bit，省 75% 显存），这样 1.5B 的模型在 16GB 内存的 Mac 上也能跑起来了。代价是训练速度稍慢，但在 Mac M2 这种设备上，这是唯一可行的方案。

## 🛠️ 环境搭建

### 1. 安装 Miniconda

Mac M2 是 Apple Silicon（ARM64），需要装 ARM 版本的 Miniconda。

```bash
# 检查你的芯片架构
uname -m
# 如果是 aarch64，就是 M1/M2/M3/M4 系列
```

下载并安装 Miniconda（Apple Silicon）：

```bash
# 下载 ARM64 版本的 Miniconda
curl -LO https://repo.anaconda.com/miniconda/Miniconda3-latest-MacOSX-arm64.sh

# 安装
bash Miniconda3-latest-MacOSX-arm64.sh

# 安装完成后，重新加载 shell
source ~/.zshrc  # 如果你用的是 zsh
# 或者 source ~/.bashrc  # 如果你用的是 bash
```

验证安装：

```bash
conda --version
# 输出类似：conda 24.x.x
```

### 2. 创建 Conda 环境

```bash
# 创建名为 llamafactory 的环境，Python 3.10（兼容性较好）
conda create -n llamafactory python=3.10 -y

# 激活环境
conda activate llamafactory
```

### 3. 安装 PyTorch（MPS 后端）

MPS（Metal Performance Shaders）是 Apple 的 GPU 加速框架，相当于 Mac 上的"CUDA"。

```bash
pip install torch torchvision torchaudio
```

验证 PyTorch 能否使用 MPS：

```python
python -c "
import torch
print('PyTorch版本:', torch.__version__)
print('MPS可用:', torch.backends.mps.is_available())
print('MPS设备:', torch.device('mps') if torch.backends.mps.is_available() else '不可用')
"
```

如果 `MPS可用` 输出 `True`，说明你的 Mac 可以通过 Metal 加速训练。

### 4. 安装 LLaMA-Factory

LLaMA-Factory 是目前最好用的微调框架之一，支持 SFT、DPO、多模型、多适配器格式。安装时指定版本 0.8.3：

```bash
pip install "llama-factory==0.8.3"
```

验证安装：

```bash
llamafactory-cli version
```

### 5. 下载基座模型

Qwen2.5-1.5B-Instruct 通过 QLoRA 4bit 加载后约占用 1-2GB 显存，Mac M2 16GB 完全够用。

```bash
# 安装 hf_transfer 加速下载（可选但强烈推荐）

```

模型下载完成后，确认路径存在：

```bash
ls ~/models/Qwen2.5-1.5B-Instruct/
# 应该能看到 config.json, tokenizer.json, model.safetensors 等文件
```

### 6. 安装 Ollama（部署用）

Ollama 是用来在本地跑微调后模型的推理工具，类似"本地版 ChatGPT"。

```bash
# 下载 Ollama
curl -fsSL https://ollama.com/install.sh | sh
```

验证：

```bash
ollama --version
```

- `instruction`：用户的问题/指令

- `output`：模型应该给出的回答

### DPO 数据格式说明

DPO 数据是"三件套"：
- `instruction`：用户的问题/指令
- `chosen`：**更好的回答**（你偏好的）
- `rejected`：**更差的回答**（你不喜欢的）

模型学习"chosen 比 rejected 更好"。

### 数据质量技巧

| 技巧 | 说明 |
|------|------|
| **多样性** | 覆盖不同领域（代码、翻译、问答、分析等），不要让数据太单一 |
| **长度均衡** | 长回答和短回答都要有，避免模型只学会"长回答"或"短回答" |
| **chosen > rejected** | DPO 数据中，chosen 回答应该明显优于 rejected，差距不能太小也不能太大 |
| **中文为主** | 既然目标是中文助手，数据以中文为主，少量英文也可以增加多语言能力 |
| **数据量建议** | SFT 至少 100 条，DPO 至少 50 条。本教程用 5 条做演示，实际使用时建议更多 |
| **避免模板化** | 不要每条回答都"当然可以！"、"好的！"开头，让回答自然一些 |

## 🚀 SFT 训练

### 创建 LLaMA-Factory 配置文件

```yaml
# ~/llamafactory/configs/sft_config.yaml
model_name_or_path: ~/models/Qwen2.5-1.5B-Instruct

# 训练模式：SFT
stage: sft

do_train: true
finetuning_type: lora

lora_target: all

# 量化：4bit
quantization_bit: 4

# 训练参数
per_device_train_batch_size: 1
gradient_accumulation_steps: 8
learning_rate: 2e-4
num_train_epochs: 3
warmup_ratio: 0.1
lr_scheduler_type: cosine

logging_steps: 10
save_steps: 50
save_total_limit: 2

# 数据集配置
dataset: sft_data
dataset_dir: ~/llamafactory/data

template: qwen
output_dir: ~/llamafactory/sft_output

# Mac MPS 设备
device: mps
```

### 启动 SFT 训练

```bash
cd ~/llamafactory
llamafactory-cli train configs/sft_config.yaml
```

### 训练参数解释

| 参数 | 值 | 说明 |
|------|------|------|
| `per_device_train_batch_size` | 1 | Mac 内存有限，batch 设 1 |
| `gradient_accumulation_steps` | 8 | 梯度累积，等价于 batch_size=8 的效果 |
| `learning_rate` | 2e-4 | 微调常用学习率，别太大也别太小 |
| `num_train_epochs` | 3 | 3 个 epoch 足够，太多会过拟合 |
| `warmup_ratio` | 0.1 | 前 10% 步数线性预热学习率 |
| `lr_scheduler_type` | cosine | 余弦退火，学习率从高到低平滑衰减 |
| `logging_steps` | 10 | 每 10 步打印一次训练日志 |
| `save_steps` | 50 | 每 50 步保存一次检查点 |

### 训练监控

训练过程中会输出类似这样的日志：

```
Step  50/150  |  Loss: 0.8234  |  Learning Rate: 1.80e-4
Step 100/150  |  Loss: 0.5123  |  Learning Rate: 1.20e-4
Step 150/150  |  Loss: 0.3876  |  Learning Rate: 5.00e-5
```

**关键观察点：**

- **Loss 下降**：从 0.8 降到 0.38，说明模型在"学习"
- **Loss 不降**：可能是数据太少、学习率太大或太小，需要调整
- **Loss 为 NaN**：学习率太大，需要调小（如 1e-4）

### 合并 LoRA 权重

训练完成后，LoRA 权重保存在 `~/llamafactory/sft_output` 目录。需要把它合并回基座模型：

```bash
llamafactory-cli export \
  --model_name_or_path ~/models/Qwen2.5-1.5B-Instruct \
  --adapter_name_or_path ~/llamafactory/sft_output \
  --template qwen \
  --finetuning_type lora \
  --export_dir ~/llamafactory/sft_merged
```

合并后，`~/llamafactory/sft_merged` 就是一个**完整的模型**，可以直接用于推理。

用以下测试用例对比三个版本：

| 测试用例 | 说明 |
|----------|------|
| "你好，请介绍一下你自己" | 看回答是否自然、有个性 |
| "请帮我写一个 Python 函数" | 看代码质量和解释深度 |
| "请帮我总结这段话" | 看摘要是否准确、简洁 |

### 使用方法

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

# 加载基座模型
model = AutoModelForCausalLM.from_pretrained(
    "~/models/Qwen2.5-1.5B-Instruct",
    trust_remote_code=True,
    device_map="auto"
)
tokenizer = AutoTokenizer.from_pretrained(
    "~/models/Qwen2.5-1.5B-Instruct",
    trust_remote_code=True
)

# 加载 SFT 模型
sft_model = AutoModelForCausalLM.from_pretrained(
    "~/llamafactory/sft_merged",
    trust_remote_code=True,
    device_map="auto"
)
sft_tokenizer = AutoTokenizer.from_pretrained(
    "~/llamafactory/sft_merged",
    trust_remote_code=True
)

# 生成回答
prompt = "你好，请介绍一下你自己"

# 基座模型回答
inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
gen_config = {
    "max_new_tokens": 200,
    "temperature": 0.7,
    "do_sample": True
}

base_output = tokenizer.decode(
    model.generate(**inputs, **gen_config)[0],
    skip_special_tokens=True
)
print("基座模型:", base_output)

# SFT 模型回答
inputs = sft_tokenizer(prompt, return_tensors="pt").to(sft_model.device)
sft_output = sft_tokenizer.decode(
    sft_model.generate(**inputs, **gen_config)[0],
    skip_special_tokens=True
)
print("SFT 模型:", sft_output)
```

## 🎯 DPO 训练

### DPO 配置

```yaml
# ~/llamafactory/configs/dpo_config.yaml
model_name_or_path: ~/llamafactory/sft_merged  # 注意：从 SFT 模型开始

stage: dpo

do_train: true
finetuning_type: lora

lora_target: all

quantization_bit: 4

per_device_train_batch_size: 1
gradient_accumulation_steps: 8
learning_rate: 5e-5
num_train_epochs: 3
warmup_ratio: 0.1
lr_scheduler_type: cosine

logging_steps: 10
save_steps: 50
save_total_limit: 2

dataset: dpo_data
dataset_dir: ~/llamafactory/data

template: qwen
output_dir: ~/llamafactory/dpo_output
device: mps
```

### 关键区别：从 SFT 模型开始

DPO 的 `model_name_or_path` 应该指向 **SFT 合并后的模型**（`~/llamafactory/sft_merged`），而不是基座模型。这样做的原因是：

1. SFT 已经教会了模型"怎么回答"（格式、内容）
2. DPO 在此基础上教它"哪个回答更好"（偏好对齐）
3. 如果从基座直接 DPO，模型可能根本不知道"怎么回答"，DPO 的对齐效果会很差

### 启动 DPO 训练

```bash
llamafactory-cli train configs/dpo_config.yaml
```

### DPO 训练监控

DPO 的日志和 SFT 类似，额外关注 `reward_margin`（奖励差值）：

```
Step  50/150  |  Loss: 0.4521  |  Reward Margin: 0.32
Step 100/150  |  Loss: 0.3123  |  Reward Margin: 0.58
Step 150/150  |  Loss: 0.2456  |  Reward Margin: 0.72
```

**关键观察点：**

- **Loss 下降**：模型在学会区分好坏回答
- **Reward Margin 上升**：模型对"好回答"的偏好越来越强
- **Reward Margin 下降**：可能需要降低学习率或增加数据

### 合并 DPO 权重

```bash
llamafactory-cli export \
  --model_name_or_path ~/llamafactory/sft_merged \
  --adapter_name_or_path ~/llamafactory/dpo_output \
  --template qwen &39;
  --finetuning_type lora \
  --export_dir ~/llamafactory/final_model
```

最终模型在 `~/llamafactory/final_model`。

## 🔧 常见问题排查

### 1. 内存不足（OOM）

```
RuntimeError: MPS backend out of memory (MPS allocated: ...)
```

**解决方案：**
- 降低 `gradient_accumulation_steps`（8 → 4）
- 减少 `per_device_train_batch_size`（已经是 1，无法再降）
- 减少数据量
- 换更小的模型（如 Qwen2.5-0.5B-Instruct）

### 2. Loss 不下降

```
Step  50/150  |  Loss: 1.5234  |  Learning Rate: 2.00e-4
Step 100/150  |  Loss: 1.4987  |  Learning Rate: 2.00e-4
Step 150/150  |  Loss: 1.5012  |  Learning Rate: 2.00e4
```

**原因：**
- 数据太少（建议至少 100 条 SFT 数据）
- 学习率太大，模型"跳过了"最优解
- 学习率太小，模型"走不动"

**解决方案：**
- 增加数据量
- 调整学习率（2e-4 → 1e-4 或 5e-5）
- 增加 epoch 数

### 3. Loss 为 NaN

```
Step 30/150 | Loss: nan
```

**原因：** 学习率太大，梯度爆炸

**解决方案：** 降低学习率（2e-4 → 1e-4）

### 4. MPS 不可用

```
ValueError: MPS is not available
```

**原因：** Python 环境不是 ARM 原生版本

**解决方案：**
- 用 `conda` 创建环境（不要用系统 Python）
- 确认 `conda activate llamafactory`
- 确认 `torch.backends.mps.is_available()` 返回 True

### 5. 下载模型慢

**解决方案：**
- 设置 HuggingFace 镜像：`export HF_ENDPOINT=https://hf-mirror.com`
- 使用 `hf_transfer` 加速：`pip install hf_transfer`

### 6. 训练很慢

Mac M2 的 MPS 加速比 GPU 慢不少，这是正常的。

**优化建议：**
- 确保用 MPS（`device: mps`）
- 减少数据量
- 用更小的模型
- 耐心等待（1.5B 模型 SFT 训练 3 个 epoch 大概需要 30-60 分钟）

### 7. Ollama 模型无法加载

```
Error: model not found
```

**解决方案：**
- 确认 `ollama create` 命令执行成功
- 确认 `Modelfile` 中的路径正确
- 用 `ollama list` 查看已安装模型
