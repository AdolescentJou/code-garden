0. 能力概览

OpenClaw（原名 Clawdbot）是一款面向未来的自主 AI 智能体（Autonomous AI Agent）框架，旨在将大语言模型（LLM）的推理能力转化为对物理与数字世界的实际执行力。其核心能力在于通过 Agent Loop（自主循环） 机制，让 AI 能够独立观察环境、拆解复杂任务并调用 Tools（原子工具） 与 Skills（复合技能） 执行操作。依托于模块化的 Workspace（工作空间） 管理记忆、Gateway（核心网关） 调度多模型路由 以及 Channels（通信渠道） 接入 Telegram/飞书等主流平台，OpenClaw 能够 24/7 全天候作为“数字员工”在 Platforms（多平台环境） 中稳定运行，处理从自动化网页操作到复杂系统运维的全流程任务。



1. Workspace

定义：在 OpenClaw 的架构中，Workspace（工作空间） 被定义为智能体的“家”——它是 Agent 运行时的默认工作目录，也是其感知自我、理解用户和存储记忆的物理载体。如果把 OpenClaw 比作一名数字员工，那么配置文件是它的入职合同，而 Workspace 就是它的办公桌和笔记本。Workspace 是 Agent 的物理边界与逻辑核心，它让 AI 的“记忆”可编辑、“性格”可克隆、“权限”可管控。它由Markdown文件驱动。Workspace 通过特定的 .md 文件定义 Agent 的灵魂和行为，无需代码即可完成深度定制。

AGENTS.md：操作手册。规定 Agent 的任务优先级和干活准则。

SOUL.md：人设滤镜。定义性格、语气（如：毒舌、严谨、温柔）。

USER.md：用户画像。让 Agent 记住你的职业、偏好和禁忌。

memory/：每日日志。按日期自动记录交互，实现跨时空的记忆连续。

核心能力：

安全边界-默认沙盒机制

隔离性：Workspace（工作区）与全局配置（密钥、凭证）物理分离。

权限控制：通过配置可开启“硬沙盒”，将 Agent 的读写权限死锁在当前文件夹内，防止其误删系统文件。

技能本地化-定制化“外挂”

skills/ 目录：你可以为特定 Agent 编写专属脚本。

覆盖逻辑：Workspace 内的技能优先级高于全局技能。这意味着同一个“代码助手”，在不同项目（Workspace）里可以拥有完全不同的私有工具。

支持同步与迁移：官网推荐初始化为 Git 仓库，进行版本管理，可通过 git push/pull，轻松在不同机器间同步 Agent 的“记忆”和“性格”。

2. Model

定义： 被设计为高度灵活、可自动降级且支持多供应商并行的系统。它不只是简单的 API 调用，而是一套完整的模型路由与治理框架。

核心功能：

多层级路由与降级。OpenClaw 的模型选择遵循严密的优先级逻辑，确保智能体在复杂环境下“永不掉线”。

三级模型路由：

Primary Model（主模型）：默认的首选大脑（如 anthropic/claude-3-5-sonnet）。

Fallbacks（降级列表）：当主模型遇到错误、欠费或触发速率限制时，系统按顺序自动切换到后续模型。

Provider Auth Failover（供应商内轮询）：如果同一供应商（如 OpenAI）配置了多个账号，系统会在切换模型前先尝试轮询不同的账户。

供应商全图谱。OpenClaw 采取“模型中立”策略，官方已深度适配了数十家主流及垂直领域的模型供应商。主流闭源： Anthropic (Claude 3.5/Opus)、OpenAI (GPT-4o/Codex)、Google (Gemini)。国产大模型： Moonshot AI (Kimi)、MiniMax、GLM (智谱)、Qianfan (百度千帆)、Mistral。本地与开源： Ollama 和 vLLM（用于本地运行 Llama 3 等模型）、Hugging Face。聚合网关： LiteLLM (统一网关)、OpenRouter (可一键接入数百种模型)、Vercel AI Gateway。隐私优先推荐： 官方推荐使用 Venice AI，支持隐私保护的推理。

实时交互能力。用户无需重启服务即可在对话中动态切换模型、查看模型状态，进行实时管理模型。

实例演示：

智能切换： 优先调用 Claude 3.5 Sonnet 处理复杂的逻辑架构设计；如果 API 报错或触发速率限制，自动切换到 GPT-4o 完成后续文本润色。

本地化推理： 为了数据隐私，将内部文档总结任务路由至通过 Ollama 运行的本地 Llama 3。

3. Tools 与Skills

在 OpenClaw 的生态系统中，Tools（工具） 和 Skills（技能） 构成了智能体的“行动层”。虽然两者常被提及，但在官方定义中，它们有着明确的职能分工：Tools 是原子的执行力（手脚），而 Skills 是复合的专业知识（职业技能）。

Tools：底层的“原子”能力。Tools 是 OpenClaw 赋予 Agent 的最基础、不可分割的操作权限。它们直接与操作系统、浏览器或用户进行交互。

核心特征：原子性，每一个 Tool 通常只负责一件极简的事（如“读文件”或“点击网页”）。权限驱动，Tool 的开启与否直接决定了 Agent 的风险等级。

四大核心工具集：

File Tools：read（读）、write（写）、edit（局部编辑）、ls（列出文件）。

System Tools：bash 或 shell（执行命令）。这是最强大的工具，允许 Agent 安装软件、编译代码或部署服务。

Web Tools：基于 Playwright，提供 Maps、click、screenshot、type 等模拟人类浏览器的行为。

Interaction Tools：AskUser。当 Agent 遇到不确定或危险操作时，主动请求人类确认。

Web Tools：OpenClaw 的 Web 工具箱底层深度集成了 Playwright（由微软开发的浏览器自动化库），它能处理复杂的 JavaScript 渲染、单页应用（SPA）以及动态加载的内容，而不是简单的静态 HTML 抓取。它拥有自主导航、模拟人类交互、视觉理解与截图、结构化内容提取、会话与身份保持等能力。

Skills：高层的“复合”套件。Skills 是对 Tools 的高级封装和逻辑组合。一个 Skill 往往包含了一组指令、特定的提示词（Prompt）以及对多个 Tool 的调用逻辑。

核心特征：

场景化：Skill 是为了解决特定任务而生的（如“管理 GitHub 仓库”或“整理 Obsidian 笔记”）。

模块化：可以像插拔 U 盘一样随时为 Agent 增加或删除某项技能。

易扩展性：用户通过编写一个 Markdown 文件（通常是 SKILL.md）就能定义一个新技能。

代表性 Skills (来自 ClawHub 社区)：

GitHub Skill：调用 bash 工具执行 git 命令，结合 LLM 逻辑处理冲突和 PR 描述。

Financial Skill：调用 fetch 工具获取实时股价，并使用 Python 代码进行趋势分析。

Social Skill：集成 Slack/Discord API，让 Agent 具备跨平台通讯的能力。

ClawHub 与自定义技能。OpenClaw 真正的强大之处在于其开源的技能生态：

ClawHub：官方提供的“技能商店”，拥有超过 5000+ 个预设技能，涵盖了从管理 Apple Reminders 到控制 Kubernetes 集群的所有领域。

自定义技能 (Customizable)：
如果你有一个私有 API 或特殊的自动化需求，你只需要在 Workspace 的 skills/ 目录下创建一个文件夹，放入你的脚本和说明文档。Agent 会通过 Semantic Discovery（语义发现） 自动理解这个新技能。

示例：你写了一个 deploy.py 脚本并在文档中注明“此脚本用于发布前端代码”。Agent 在处理相关指令时，会自动调用 bash 工具来运行你的这个 deploy.py。

4. OpenClaw 核心网关 (Gateway)

定义：作为 OpenClaw 架构的核心枢纽与唯一通信入口，Gateway 承担着 “交通指挥官” 的关键角色。它通过本地运行的 API 服务器（默认端口 18789），高效连接用户端 (Channels)、大模型 (Models) 与后端执行环境 (Agents/Workspace)，并将复杂的 Agent 操作封装为标准化的 HTTP 和 WebSocket 接口。所有外部请求（包括 Telegram Bot、Web Dashboard 及自定义脚本）均需经由 Gateway 处理，其独特能力在于将异步的 Agent 思考过程转化为可订阅的实时数据流，实现类似 ChatGPT 网页版的逐字输出效果。gateway官网介绍

核心能力

安全防护。Gateway强制要求所有请求携带 Bearer Token，有效防止公网暴露导致的未授权访问。OAuth 托管服务统一管理第三方服务（如 Google Calendar、GitHub）的授权凭证，确保工具调用的合法性。

智能路由系统。根据 agentId 参数将请求定向至对应 Workspace 及会话。并智能协调后台进程资源，优化高并发场景下的处理效率。

可视化管理系统。可通过 Web 界面直观展示运行中的 Agent 状态、Token 消耗及工具执行情况。内置 Playground 功能，支持网页端直接测试 Agent 响应。

持久化服务。自动加载磁盘存储的会话历史并注入模型。在网络中断时保持后台运行，重连后自动推送中断期间的执行进度。

跨平台适配。将 Slack、Discord 等异构平台的数据格式统一转换为 OpenClaw 标准 Message 对象。

典型应用场景

远程运维：通过 HTTPS 端口实现移动端 App 对家庭 Agent 的跨网络指令下发（如“备份服务器”命令）。

访问控制：支持基于 IP 段或特定 Token 的精细化权限管理策略。

5. Daemon (守护进程)

定义： 让 Agent 具备“主动性”和“稳定性”的后台管理器，它保障了 Agent Loop 的持久性，使得“自动化监控”、“定时报告”和“长流程任务”成为可能。agent-loop官网介绍

24/7 的“维生系统”。在 OpenClaw 中，Daemon 不是一个单一的组件，而是指通过后台静默运行的 Gateway 进程。它解决了 AI 运行的两个痛点：

脱离终端： 即使你关闭了终端程序或浏览器，智能体依然在后台处理任务。

主动性： 智能体不再是被动等待指令，而是可以基于时间或事件“主动”开始思考。

Daemon 与 Agent Loop 的结合。智能体在执行任务时会进入一个“思考-行动-观察”的死循环。Daemon 为这个循环提供了持续的生命力。会话保持 ： Daemon 负责维护会话状态。即使网络中断，当 Channel 重新连接时，Daemon 能确保 Agent Loop 从中断的点继续，而不是重启；资源锁管理： 在循环执行长耗时任务（如：抓取 100 个网页）时，Daemon 确保工作空间（Workspace）不会被并发任务冲突破坏。

心跳机制。这是 Daemon 最具代表性的功能。 Daemon 会定期“唤醒” Agent，它会向 Agent 发送一个内部信号，触发 Agent 阅读 Workspace 中的 HEARTBEAT.md。例如Agent 会自检：“我昨天答应老板的报告发了吗？”或“监控的那个网页有更新吗？”

自动恢复与自愈。进程守护： 如果 Gateway 因为内存溢出或网络波动崩溃，Daemon 会尝试自动拉起；状态对齐： 重启后，它会扫描未完成的 Command Queue（命令队列），确保重要的异步任务（如自动化部署）不会因为程序崩溃而夭折。

任务调度。Daemon 赋予了 Agent 时间感，支持标准的 Cron 表达式（如 0 9 * * *）。例如每天早上 9 点，Daemon 准时启动 Agent Loop，让 Agent 去看新闻、总结邮件，并在 Channel 里给你发简报。

实例演示：

早起简报： 设置 Cron 任务 0 8 * * *。Daemon 会在每天早 8 点唤醒 Agent 抓取昨晚的科技新闻并汇总。

监控报警： 持续在后台运行，一旦监控到公司官网 404，立即通过 Channel 向你发出警报。



6. Channels (通信渠道)

定义：OpenClaw的交互渠道，Channels模块让 OpenClaw 摆脱了“浏览器插件”或“本地终端”的局限。 它让 Agent 变成了一个随时随地可以被召唤的数字员工。无论你是在排队、开车（通过语音控制 iMessage/WhatsApp），还是在群聊里开会，都可以直接通过自然语言调动 Agent 在 Workspace 里的所有技能。

能力定位-全渠道接入。Channels 负责将外部通讯平台的协议（如 Telegram 的 Bot API、Slack 的 Webhook）转化为 OpenClaw 内部的标准消息格式。多端联动：同一个 Agent 可以同时挂载到 Telegram、Slack、Discord 等多个渠道。统一入口：无论你在哪里发指令，Agent 接收到的上下文是一致的。

丰富平台矩阵。OpenClaw 提供了丰富的预置渠道支持：主流社交/极客平台：Telegram (Bot API)、Discord (Bot)、Slack (App)。国内生产力工具：飞书 (Lark)、钉钉 (DingTalk) —— 通常通过 Webhook 或 Gateway 适配器接入。高阶/个人渠道：WhatsApp (通过 Twilio 或 Matrix)、iMessage (Apple 专用)、甚至简单的 HTTP Webhook。

身份与权限认证。Channels 不仅仅是传输消息，它还负责“安保”工作：白名单机制：你可以通过配置 allowed_users，限制只有特定的 Telegram ID 或飞书用户才能给 Agent 下指令，防止 AI 被外部滥用。身份映射：Channel 会自动识别发送者，并将其与 Workspace 中的 USER.md 关联，让 Agent 知道“正在跟我说话的是老板还是访客”。

智能路由。这是 Channels 最强大的地方。你可以通过 Gateway 配置路由规则：指定分配：例如来自“运维群”的消息自动路由给“运维 Agent”，来自“私人私聊”的消息路由给“生活秘书 Agent”。负载均衡：在多实例部署时，确保消息能准确投递到活跃的 Agent 进程。

实时交互与流式传输。支持像 ChatGPT 网页版那样的“逐字蹦出”效果（需平台 API 支持，如 Telegram/Slack），提升用户交互体验。主动推送 ：Agent 不仅能被动回答，还能通过 Daemon 触发，主动在 Channel 里给你发消息（如：监控到股价波动，自动在飞书群里报警）。

实例演示：

群组助手： 将 Agent 拉入 Telegram 开发群，全组成员可以通过 @bot fix bug 触发代码修复流程。

语音交互： 接入支持语音转文字的 Channel，让你在开车时通过语音命令 Agent “帮我查一下下午的会议室”。

7. Platforms

定义： 决定了 Agent 如何在不同的操作系统环境（OS）中“安家”。它为智能体提供了运行所需的底层执行环境和硬件资源访问接口。

Platforms 模块充当了 OpenClaw 与物理主机（或容器）之间的翻译层。它确保了同样的指令（如“查看磁盘空间”或“运行 Python 脚本”）能够在不同操作系统上准确执行。

跨平台支持：官方深度支持 macOS（原生集成度最高）、Linux（服务器端部署首选）和 Windows (通过 WSL2 或原生环境)。

环境感知：Agent 会自动识别当前运行的平台，并调整其工具调用逻辑（例如在 macOS 上使用 pbcopy，在 Linux 上使用 xclip）。

三大执行模式（Runtime Modes）

根据安全与便捷需求，提供不同级别的环境隔离：

Host Mode (宿主机)：直接运行。性能最强，可调用本地软件和外设，但安全性较低。

Docker Mode (容器)：完全隔离。在独立容器中运行，是处理高风险代码或爬虫的首选。

Cloud / Remote (远程)：通过 SSH 在云端执行。适合处理编译、大数据等重型任务。

核心能力特性

桌面集成：支持剪贴板读写、多媒体控制（音量/亮度）及原生应用（如 VS Code）唤起。

资源与环境管理：实时监控 CPU/内存占用，安全托管并注入环境变量用于身份验证。

权限沙盒：精细化定义挂载点（Mounts）和运行用户身份（User Identity），实现权限最小化。

实例演示

异常拦截： 监测到由于欠费导致 OpenAI API 调用失败，Agent 会在 Channel 里主动告诉你：“老板，余额不足了，我先转为使用免费模型。”

性能预警： 当 Workspace 占用磁盘超过 90% 时，自动触发清理旧日志的 Skill。

附录：一个完整的自动化工作流- 每日新闻订阅

指令： 订阅每日新闻



1. 输入适配阶段

用户发起： 你在 Telegram 或 Discord 发送消息：“帮我订阅每日新闻”。

Channel Adapter (入口)： 系统接收原始消息，将其标准化（Normalize）。例如，将不同平台的格式统一为 OpenClaw 可理解的 JSON 格式，并提取出“订阅”、“每日新闻”等核心意图。

2. 路由与调度阶段

Gateway Server： 作为“协调员”，它识别出你的用户 ID，并将此消息路由到对应的会话（Session）。

Lane Queue： 如果你同时发了好几条指令，这里会负责排队和流控，确保任务有序进入执行层。

3. 智能体准备阶段

在这一步，系统会为 LLM 准备“大脑”所需的背景资料：

Model Resolver： 确定使用哪个模型（如 GPT-4 或 Claude 3）。

Session History Loader： 加载你之前的对话，确认你之前是否提到过偏好的新闻频道。

System Prompt Builder： 构建系统提示词，告诉 LLM：“你是一个助手，现在用户要订阅新闻，请调用相应的工具”。

Context Window Guard： 检查上下文长度，确保所有信息都能塞进模型的处理范围。

4. 推理与决策阶段 (Agentic Loop)

这是最核心的逻辑循环，流程如下：

LLM 响应： 模型分析意图，意识到需要执行操作。

Tool Call (工具调用)： 模型决定调用 Tool A (订阅管理工具)。

Execute (执行)： 系统在后台将你的 ID 和“每日新闻”写入数据库或定时任务列表。

循环确认： 如果订阅成功，模型可能会再次思考（Loop），确认是否需要调用 Tool B (搜索工具) 来展示今天的新闻示例，或者直接生成确认信息。

5. 结果输出阶段

Final Text： LLM 生成最终回复：“没问题！我已经为你开启了每日新闻订阅，每天早上 8 点我会准时推送到这里。”

Stream Chunks： 为了让你觉得响应飞快，文本会以**流式（Stream）**的方式一字一句地传出。

Channel Adapter (出口)： 将文本包装回 Telegram/Discord 的特定格式。

反馈用户： 你在手机上收到了订阅成功的确认消息。
