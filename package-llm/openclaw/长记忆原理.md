核心结论

OpenClaw 采用 "Markdown 文件即真理源 + 混合检索" 的记忆架构，核心设计哲学是 "模型只记得写入磁盘的内容"。系统通过双层存储（每日日志 + 长期记忆文件）、混合检索（70% 向量语义 + 30% BM25 关键词）、以及压缩前自动记忆刷写三大机制，实现了跨会话的持久化记忆。优雅降级是核心设计原则——从零 API Key 的纯关键词模式到完整的向量+BM25 混合搜索，系统在任何环境下都能工作。

这一架构已被多源（官方文档、GitHub 源码、知乎、V2EX、linux.do、Twitter/X、小红书）一致确认，并通过源码审计验证。（置信度 97%）

3. 检索机制：混合搜索算法

OpenClaw 提供两个 Agent 可调用的工具（src/agents/tools/memory-tool.ts）：

memory_search：语义召回，对索引的 Markdown 片段进行搜索

memory_get：定向读取特定文件/行范围（安全检查防止目录穿越）

混合检索公式（src/memory/hybrid.ts）

const score = params.vectorWeight * entry.vectorScore + params.textWeight * entry.textScore;
// 默认: 0.7 * vectorScore + 0.3 * textScore


BM25 分数转换（源码发现）

SQLite FTS5 的 bm25() 返回值越小越相关，需要转换到 0-1 区间：

// src/memory/hybrid.ts
export function bm25RankToScore(rank: number): number {
  const normalized = Number.isFinite(rank) ? Math.max(0, rank) : 999;
  return 1 / (1 + normalized);
}


FTS 查询构造（源码发现）

// 将查询拆分为 token，每个用引号包裹，AND 连接
// "build the feature" → "build" AND "the" AND "feature"
const quoted = tokens.map((t) => `"${t.replaceAll('"', "")}"`);
return quoted.join(" AND ");


注意：所有 token 必须全部匹配，可能过于严格。系统有放松机制：如果混合搜索只有关键词命中且低于 minScore（默认 0.35），阈值会放松到 min(minScore, textWeight) 以避免丢弃精确词法匹配。

向量搜索

使用 embedding 模型将文本块转为向量

默认本地模型：embeddinggemma-300m-qat-Q8_0.gguf（~600MB，通过 node-llama-cpp）

也支持 OpenAI text-embedding-3-small、Gemini gemini-embedding-001、Voyage、Mistral

Provider 自动选择链（src/memory/embeddings.ts createEmbeddingProvider）：

auto 模式下：Local（仅当模型文件已存在于磁盘时，不会自动下载）→ OpenAI → Gemini → Voyage → Mistral

Ollama 被刻意排除在 auto 之外（避免假设用户有本地 Ollama）

所有 Provider 都无可用 API Key → 降级为纯 FTS 模式（provider: null）

向量存储在 per-agent SQLite：~/.openclaw/memory/<agentId>.sqlite

向量搜索 SQL（src/memory/manager-search.ts）：

SELECT c.id, c.path, c.start_line, c.end_line, c.text, c.source,
       vec_distance_cosine(v.embedding, ?) AS dist
  FROM chunks_vec v
  JOIN chunks c ON c.id = v.id
 WHERE c.model = ?
 ORDER BY dist ASC
 LIMIT ?
-- score = 1 - dist（余弦距离转余弦相似度）


无 sqlite-vec 扩展时的降级：加载全部 chunks 到 JS 内存，暴力计算 cosineSimilarity()（src/memory/internal.ts）。

高级检索选项

MMR（最大边际相关性）（src/memory/mmr.ts）：默认关闭，λ 默认 0.7

源码发现：MMR 使用 Jaccard 相似度（token 集合交集比），不是向量余弦相似度

设计动机：避免存储/比较 pairwise 向量，计算更轻量

公式：MMR = lambda * normalizedRelevance - (1 - lambda) * maxSimilarityToSelected

时间衰减（src/memory/temporal-decay.ts）：默认关闭，半衰期 30 天

公式：score = score * Math.exp(-lambda * ageInDays)，其中 lambda = Math.LN2 / halfLifeDays

常青文件豁免：MEMORY.md 和 memory/ 下的非日期文件返回 null 时间戳，完全跳过衰减

仅 memory/YYYY-MM-DD.md 和会话转录文件受衰减影响

4. 文本分块策略（src/memory/internal.ts chunkMarkdown()）

采用纯字符计数滑动窗口，保留行边界：

目标块大小：maxChars = tokens * 4 = 1600 字符（默认 400 tokens）

重叠保留：overlapChars = overlap * 4 = 320 字符（默认 80 tokens）

去重：SHA-256 哈希，chunk ID = SHA-256(source:path:startLine:endLine:hash:model)

源码发现——分块不感知 Markdown 结构：

算法逐行累积，当 currentChars + lineSize > maxChars 时切割

Markdown 标题没有特殊处理——标题可能落在前一个块的尾部，其内容在下一个块的开头

超大单行通过 maxChars 长度硬切

超过 Provider 最大输入 token 的块，通过 UTF-8 字节二分查找进一步拆分（src/memory/embedding-chunk-limits.ts）

会话文件特殊处理（src/memory/session-files.ts）：

JSONL 转录逐行解析，提取 user/assistant 消息

格式化为 "User: ..." / "Assistant: ..." 纯文本

敏感信息脱敏：redactSensitiveText(text, { mode: "tools" }) 在索引前执行

lineMap 数组映射内容行号回原始 JSONL 行号

5. 压缩前记忆刷写（Memory Flush）

当会话接近上下文窗口极限时，OpenClaw 触发一个 "静默 agentic turn"，提示模型将持久化信息写入磁盘：

compaction: {
  reserveTokensFloor: 20000,
  memoryFlush: {
    enabled: true,
    softThresholdTokens: 4000,
    systemPrompt: "Session nearing compaction. Store durable memories now."
  }
}


触发条件：currentTokens >= contextWindow - reserveTokensFloor - softThresholdTokens

对于 200K 窗口：约在 176,000 tokens 时触发

每次压缩周期仅执行一次，防止刷屏

无需保存时返回 NO_REPLY

只读沙箱模式下跳过

3. 全量索引写入临时 DB
4. 原子 rename 交换: old → backup, temp → target
5. 删除 backup
6. 重新打开 DB

  mtime INTEGER NOT NULL,
  size INTEGER NOT NULL
);

-- 文本块 + embedding
CREATE TABLE chunks (
  id TEXT PRIMARY KEY,     -- SHA-256(source:path:startLine:endLine:hash:model)
  path TEXT NOT NULL,
  source TEXT NOT NULL DEFAULT 'memory',
  start_line INTEGER NOT NULL,
  end_line INTEGER NOT NULL,
  hash TEXT NOT NULL,      -- 文本块内容 SHA-256
  model TEXT NOT NULL,     -- embedding 模型名
  text TEXT NOT NULL,      -- 原始文本
  embedding TEXT NOT NULL, -- JSON 序列化 number[]
  updated_at INTEGER NOT NULL
);

-- BM25 全文索引
CREATE VIRTUAL TABLE chunks_fts USING fts5(
  text,
  id UNINDEXED, path UNINDEXED, source UNINDEXED,
  model UNINDEXED, start_line UNINDEXED, end_line UNINDEXED
);

-- 向量索引（维度动态设定）
CREATE VIRTUAL TABLE chunks_vec USING vec0(
  id TEXT PRIMARY KEY,
  embedding FLOAT[N]  -- N 由首次 embedding 维度决定
);

-- Embedding 缓存
CREATE TABLE embedding_cache (
  provider TEXT NOT NULL,
  model TEXT NOT NULL,
  provider_key TEXT NOT NULL,
  hash TEXT NOT NULL,
  embedding TEXT NOT NULL,
  dims INTEGER,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (provider, model, provider_key, hash)
);

矛盾与争议

记忆系统默认是否好用：GitHub Discussion #25633 指出 "OpenClaw Memory Is Broken By Default"，认为核心功能默认关闭（Memory Flush、MMR、时间衰减等均需手动开启），社区对此有不同看法

可能原因：官方倾向保守默认值以避免性能开销，社区用户期望开箱即用

本地 vs 云端 Embedding：社区对是否应该默认使用本地模型（速度慢但隐私好）vs 云端模型（速度快但需 API Key）存在讨论

OpenClaw 的做法：默认本地优先，云端作为 fallback

源码澄清：auto 模式不会主动下载本地模型，仅在已存在时使用
